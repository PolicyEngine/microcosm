# Financial completion before geography

The US financial host now has two explicit entry points. The existing
`run_atomic_survey_financial` keeps its assigned-geography prefix and required
configuration. `run_pre_geography_survey_financial` uses the genuine survey
CREATE, allocation, whole-household clone EXPAND and clone ownership claim.
Its result retains the actual preparation, allocation and clone. It has no
placeholder geography population or configuration.

The new variant lets support-changing financial and PUF work precede a future
completed-spine geography suffix. It does not implement that suffix, native52
tail placement, selective clone2 receiving contracts or qualified GQ support.
Those remain separate work. Observation-time state and PUMA are source facts;
the new path can use qualified source state as a predictor without assigning a
synthetic block.

Both paths use the same financial, property, tax and child-completion algorithms.
The actual issuer seals one of two exact result types and prefix modes. The
atomic checker still accepts only the atomic result. The common checker used by
PUF consumers accepts precisely the two issued types and repeats the same live
source, implementation, artifact, population and final-state checks. Public
result constructors and copied Frames grant no authority. New source and graph
identities require fresh compatible stores; old-store reuse is not asserted.

For the new path, independent reconstruction verifies the complete allocation,
clone lineage, DESIGN anchors, weight halves, mass ledger and distinct
pre-claim/post-claim ownership. Its graph binds real preparation, allocation and
frame-context evidence. Optional status, development-input and child-completion
nodes retain that evidence; no geography gate or invented successful validation
receipt is supplied. The existing atomic receipt shape is preserved. The new
receipt explicitly says atomic geography is absent and release eligibility is
false.

The old sampling-origin financial-successor bridge remains atomic-only. A
pre-geography result is not an admitted calibration population through that API.
Likewise this extension does not certify immigration, enrichment, engine input
completeness or a release merely because their parent types are descriptive.

The first tests cover genuine invented-source cloning, source-qualified
predictor/property declarations, observed demographic state, altered-population
refusals and the unissued/invalid-option boundary. They execute no successful
financial model, PUF transfer or geography assignment. Cold/required fitted
financial and PUF composition require separate evidence before adoption. No
actual microdata or launch acceptance follows from source review or these tests.
Poverty remains comparison-only and prior wages remain excluded.
