# Child completion verification operations

The child property-income verifier independently reconstructs its keyed
empirical result and compares actual materialized populations and artifacts.
Required graph cache hits do not remove that owner check.

A private synchronous verification operation can now retain that independently
verified reconstruction for repeated checks of the exact same child boundary.
The first verification completes before retention. Each subsequent borrow still
performs both genuine source/parent requalifications, implementation checks,
physical input seals and typed artifact/output comparisons. Changed inputs or
retained expected results refuse; they are not normalized into a new baseline.

Closing disables reuse before running the full verifier once per participating
child against actual retained evidence. It then checks every retained result
and evidence container again, after all closing callbacks. Failure revokes the
participants, nested scopes cannot restart a closing or failed operation, and
no memo survives scope exit. Direct child and financial checks remain complete
outside these scopes.

The PUF and enrichment checked operations, public SPM bridge and development
checkpoint writer open or join the scope. They retain their own detached output
and owner checks after close. The writer also checks delivered checkpoint bytes
after closing callbacks and removes its handoff document if final verification
fails. This does not cache successful checked views, source-file reads, graph
compilation, registry validation, financial reconstruction, or source epochs.

The change targets repeated child semantic reconstruction only. Full population
seals, ancestor checks and source hashing may dominate runtime; no speedup or
completed combined proof is claimed by this source change. Invented tests cover
actual first/closing call counts, required replay, nested/separate lifetimes,
changed inputs/expected results, and mutation during warm or closing checks.
Those tests require separate execution evidence. This is not actual-source,
consumer, calibration or release acceptance.
