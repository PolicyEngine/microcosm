# Descriptive person status in the common US graph

`run_atomic_survey_financial(..., person_status=True)` adds four operations
after the complete survey/PUF-support clone families and atomic geography, before
financial enrichment. The default remains `False`. The existing nine-node
spine/geography prefix and its returned populations remain separate and unchanged.
The optional graphs have 23, 39 or 42 nodes, compared with the respective
19-node financial, 35-node property and 38-node property/tax paths.

| Node | Input and output |
| --- | --- |
| `survey_person_status.source_projection` | Borrows the actual retained preparation and source qualifier. Creates a private branch of original support and a typed artifact containing exact original identities and literal items. |
| `survey_person_status.literals` | Exposes the complete union of ACS/ASEC raw items and distinct allocation/edit flags on original support. |
| `survey_person_status.recode` | Calls the existing descriptive recoder and checks its result against the retained qualifier. Declares every parse/code field, difficulty/student observation, knownness, universe and period field. |
| `survey_person_status.bind` | Joins the descriptive observations and context onto both initial clone families by exact original-person, native-person, survey-arm and clone-index identity. |

The receiving Frame carries ten descriptive observations and their explicit
context, rather than repeating all raw strings per clone. Raw/edit/parse fields
remain on original support. The projection artifact is therefore required for
the audit lineage: its typed producer edge, digest and the clone-origin linkage
must be retained by a subsequent export. A receipt alone cannot authorize the
source. Row values, private paths and native identifiers are absent from public
node parameters and receipts. The private JSON artifact represents integers as
decimal strings under `integer_literal`, never lossy JavaScript numbers.

All column declarations are fixed, including when the selection contains only
one survey arm. Missing opposite-survey fields remain null. Code columns use
nullable `Int64` and observations use nullable Boolean storage, with knownness
separate from the value. No `is_blind`, `is_disabled`, annual full-time student,
prior-wage, sex or household-role writer is added. The
[source definitions and reference periods](us-survey-person-status.md) remain
unchanged.

The shared host adds a typed status-binding dependency to its existing financial
donor node. A narrow adapter checks that dependency, then supplies the exact
original declaration and artifact slice to the existing donor kernel. This
ordering is visible in the graph. The original source qualifiers continue to
receive the untouched geography population.

Verification covers the complete output. The status boundary reconstructs every
status value, dtype, null mask, writer and position from qualified source literals.
The existing financial/property verifiers independently verify the remaining
population, including unrelated values, structural links, weights, design
weights and mass ledger. The host retains complete output seals and rechecks
them after its last source requalification. It refuses both a status-only change
with an unchanged financial complement and an unrelated financial-cell change.

The fragment validates the actual qualified object on admission. Before and
after each executed kernel callback it checks live code, defaults, closures,
declared artifacts, input/output seals and the original preparation/student
owner relationships. The final host borrow requalifies the original source
members before the last pure checks. Cold execution and required replay use the
same declarations and full materialization comparisons.

## Validation boundary

The private projection has an explicit 2 GiB serialized-byte ceiling. Each raw
survey token retains the source qualifier's 64-character bound; the existing
ASEC student-controls issuer also retains its 600,000-row ceiling. There is no
claim that these limits admit the complete ACS/ASEC universe; the inherited
survey graph's preparation/allocation artifacts each retain their 64 MiB limits.
Projection JSON is
materialized in memory before its byte-limit check, and its working memory can
exceed the final serialized size substantially. The small invented fixture will
check a conservative 16 KiB-per-original serialized bound; that is an authored
test expectation, not a measured native-data size. Before a maximum-local or
full-national claim, measure the actual bytes per original and peak memory on
successive small samples and consider a separately reviewed columnar/chunked
private artifact. Repeating that artifact in every clone is not an option here.

Authored tests include pure schema/binding controls, an actual 13-node
spine/geography-plus-status fixture, optional 23-node common-host replay, and
39/42-node property/tax preservation using invented authenticated sources.
These tests are unexecuted in this source-only change pending review and a
separately pinned bounded run. The later PUF and survey-enrichment hosts are not
modified here; their combined end-to-end preservation remains a separate
integration acceptance. Input-coverage counts describe the input registry, not
the number of Frame columns.

The root previously reported acceptance of 77 person-status source tests
(75 pure/source controls and two actual owner cases), and 100 canonical-sex
tests (88 plus 12). Those are root-reported source-boundary results, not this
author's independent acceptance, validation of this new graph, a native-file
build or release certification. The frozen native V4 graph is unaffected.
