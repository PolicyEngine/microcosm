# Native geography and tenure bindings

The canonical state fragment converts the existing `assigned_state_fips` into household `state_fips`. It requires exact equality with `survey_observed_state`, which the native source projection qualifies from ACS `ST` and current ASEC `GESTFIPS`. Both inputs must be canonical two-digit strings in the shared state FIPS constants. There is no default-state fallback or float conversion.

`graph_current_survey_state.state_binding_node` depends on the typed `geography.gate` artifact and the two household inputs. The existing graph assigns blocks after complete initial cloning and derives geographic layers through the shared atomic support. This fragment neither assigns blocks nor parses block identifiers to construct a second mapping. Each clone keeps its existing assignment. The gate orders the graph; its serialized bytes alone grant no source authority.

The output is `int64` when new. If the receiving population carries `state_fips`, the declaration uses the graph's explicit full-cell rewrite and replaces it from the qualified derived input. Matching, incorrect, or missing incumbent values are not used as evidence. An existing `int64` or nullable `Int64` dtype is retained, as required by the graph rewrite contract; unsupported incumbent storage refuses. Every other column, axis, membership, weight and mass record is unchanged. The kernel does not import the country engine.

This is an independent fragment. The enrichment host must explicitly register it, retain its genuine source and population ancestry, and reconstruct/requalify it on cold and required replay before it qualifies a complete native run. This slice does not change that host's default graph or claim release readiness.

## Tenure questions that remain

The consumer source declares household `tenure_type` as `RENTED`, `OWNED_OUTRIGHT`, `OWNED_WITH_MORTGAGE`, or `NONE`. SPM-unit `spm_unit_tenure_type` separately declares `OWNER_WITH_MORTGAGE`, `OWNER_WITHOUT_MORTGAGE`, and `RENTER`; its documentation identifies Census `SPM_TENMORTSTATUS` codes 1, 2 and 3 respectively. These are different entity grains and code systems.

Current qualified housing capture (`current_survey_housing.ASEC_HOUSEHOLD_COLUMNS` and `ACS_HOUSEHOLD_COLUMNS`) retains original ASEC `H_TENURE` and ACS `TEN`. ASEC `H_TENURE=1` identifies ownership but does not establish whether a mortgage exists. The legacy `housing_inputs._HOUSEHOLD_TENURE_MAP` maps it to `OWNED_WITH_MORTGAGE`. That historical convention cannot become a claimed mortgage observation. `H_TENURE=2` is cash rent and `3` is no-cash-rent occupancy; the legacy household mapper uses `RENTED` and `NONE`, respectively. NIU or missing values must remain separately unresolved, not silently mapped to `NONE`.

ACS `TEN=1` identifies ownership with mortgage/loan, `2` ownership free and clear, `3` cash rental, and `4` no-cash-rent occupancy. The maintained `acs_inputs._HOUSEHOLD_TENURE` maps `TEN=4` to household `NONE`, while its separate `_SPM_TENURE` maps that code to SPM `RENTER` through `_map_tenure`'s membership join. `acs_release_predictors.ACS_TEN_TO_SPM_TENMORTSTATUS` also maps `TEN=4` into the SPM non-owner consumed bin 3. The official Census ASEC 2025 dictionary (PDF page 103, printed 6C-66) describes SPM_TenMortStatus=2 as “Owner without Mortgage or rent-free.” Thus the maintained ACS TEN=4→SPM code 3 mapping requires source reconciliation, and ASEC code 2 alone cannot establish household ownership. The consumer enum label is narrower than the source definition. Group-quarters and unknown/inconsistent records need explicit applicability and missingness handling. No tenure output or scientific convention is added by the state fragment.

A separate source-completion proposal can capture `SPM_TENMORTSTATUS` from the same authenticated original ASEC person member, retain literals and source year, and require within-SPM consistency against the existing genuine SPM membership. `current_survey_spm_source` currently captures membership and role fields, not that tenure field. A later binding must retain the actual SPM source owner and applicability. It must not derive household-owner mortgage detail from unrelated or multiple SPM units, reinterpret all owners as mortgaged, or qualify an inherited canonical tenure column merely because it exists.

Consumer declarations were read without imports from the pinned local `2.2.1+spmuniverse.20260919` consumer used by the native159 source audit: `variables/input/geography.py`, `variables/household/expense/housing/tenure_type.py`, and `variables/household/income/spm_unit/spm_unit_tenure_type.py`. No country-engine execution or consumer update is part of this work.

## Enrichment host option

`run_us_survey_enrichment(..., canonical_state_input=True)` opts into the canonical state binding after the existing terminal enrichment fragment. The default stays false. A visible keep-all FILTER creates `survey_geography.canonical_state_version` before `survey_geography.bind_state_fips`; it preserves every support row and weight and adds one structural ledger record. The separate version is necessary when earlier projections read an inherited `state_fips`: rewriting that column on the same population would redirect those earlier reads to the later writer and create a dependency cycle.

When child support is selected, state takes the child-support version as its base and its typed final attachment as the ordering dependency. The state binding is then the returned terminal population; both keep-all transitions remain in the ledger. Selecting all people must preserve every entity axis, including otherwise orphan groups; the reconstruction refuses if selection would prune any.

The host retains the genuine parent population and authenticates its source/geography through the existing cold and required-replay entry/final fences. The version kernel checks the exact projected person IDs, memberships and clone coordinates. The binding kernel checks the exact retained household IDs and qualified derived/observed states, then calls the deterministic state operator. The host independently reconstructs both complete population transitions and compares persisted artifacts, Frames, weights and ledgers on every execution and replay. These checks do not turn a detached receipt into source authority.

An existing canonical `state_fips` must use `int64` or nullable `Int64` storage; unsupported inherited storage remains an explicit schema prerequisite. The option never silently casts that incumbent. ASEC household mortgage status remains unresolved by H_TENURE alone; this option makes no tenure inference.
