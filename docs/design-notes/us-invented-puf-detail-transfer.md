# Invented PUF detail transfer on combined survey clones

This slice proves a graph path using invented source records and households. It does not admit a genuine fit, turn raw PUF draws into tax inputs, or establish national or congressional-district model adequacy. The source-owned `not_admitted_pending_basis_review` metadata and raw period observations remain unchanged.

The graph first constructs the combined ACS and ASEC household population and makes one whole-household detail clone of every household. A separate donor path decodes the real source envelopes, runs the existing price-growth kernels, reads the exact local price-export envelope, and trains the existing targetwise QRF. The recipient matrix uses every detail tax unit, including zero-weight units. The final node attaches one raw signed Schedule C profit/loss draw to that tax unit by its exact ordered identifier. Native output cells remain null.

| Decision | Invented machinery semantics | Genuine boundary still open |
| --- | --- | --- |
| Target | Raw `E00900`, with negative, zero and positive values retained | Raw Schedule C reporting is not a repaired income total or a complete tax input |
| Wage proxy | Donor `E00200`; ACS `employment_income_before_lsr`; ASEC declared current-price wage field | Gross survey wages and tax-reported wages differ; genuine ASEC cohort/current-money and ACS under-15 universe evidence must be bound |
| Filing category | MARS categories 1–4 as four indicators; JOINT and SURVIVING_SPOUSE map to 2 | These are an explicit developmental match choice, not a demonstrated adequate conditional model |
| Tax-unit aggregation | Head plus actual spouse for JOINT; head only for survivor; dependents excluded | No missing-to-zero rule follows merely from age; missing eligible wages refuse |
| Prices | Actual CPI development-price transform, 2015-file basis to 2024 prices | This is not 2024 nominal-income growth or fit admission; raw FLPDYR remains raw |
| Fit | One target, two trees, seed 578, exact zero tolerance 0 | No adequacy, calibration, held-out, policy or launch inference |
| Weights | Delivered S006 integer hundredths are donor DESIGN resampling weights | They never replace survey household weights |
| Clone boundary | Paired source cells, membership and same-valued effective weights must remain exact | This first adapter expects untouched clones before calibration; it does not accept subsequently redistributed role weights |

The price-array reader checks the exact external header and payload identity, column inventory, types, rows, per-column hashes and full byte consumption. The graph also checks the companion source/price binding and actual producer edge; the envelope alone is not a price-admission object. This fixture producer records its own code identity rather than impersonating a completed genuine price run.

The attachment binds the full declared host content, exact matrix bytes and producer, the complete application-state target and feature order, the actual raw draw producer, and raw values' ordered tax-unit IDs. A separate materialized verifier checks every carried column and effective weight, including columns a kernel projection could omit. It compares the original-design anchor roster and values and the entire graph ledger at the first post-filter population against the final population. The main invented graph begins at an IMPORTANCE-weighted composition, so its original-design roster is empty and preservation of that roster is vacuous. A separate materialized Population fixture checks nonempty and zero-valued anchor mutations.

Changing host wages must reuse donor fitting while invalidating recipient matrix/application/placement. Changing donor S006 must invalidate fitting while preserving host weights. Required-cache replay runs in a fresh process with fatal kernels; fixture definition construction and decoding needed to compute source bindings occur before replay, so zero graph calls is not a claim of zero source parsing overall.
