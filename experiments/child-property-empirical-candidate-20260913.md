# Child property-income empirical candidate

This source-only candidate implements an explicit transfer from original ASEC persons aged15–17 to explicitly unmeasured children aged0–14. It is opt-in methodology under review, not a released default or a measured child-income distribution. No native fit or test execution has occurred in this commit.

`microcosm.fit.joint_empirical` fits a pooled weighted joint law for two nonnegative targets. It classifies each donor into neither, first-only, second-only or both-positive, then draws one paired observation within the chosen pattern. It uses Microcosm's typed/explicit weight resolvers. It does not run QRF or independently sample marginal amounts.

For observed weighted pattern probabilities p, receipt factor r produces q_g=r*p_g for positive patterns and q_00=1-r*sum(p_positive). It refuses r<0, nonfinite values or r*sum(p_positive)>1; no probability is clipped. Two strictly positive amount factors scale the paired donor coordinates. Source-positive amounts lost to underflow or overflow refuse. Reference factors are one. r=0 is a separately labeled all-zero stress, still requiring the same fitted support-qualified donor population.

Cumulative positive weights are normalized by their own finite positive endpoint. This declared normalization makes the final CDF endpoint one; non-increasing positive intervals refuse. Uniform coordinates use half-open intervals. The numerical operator accepts supplied uniforms; the separately owned graph adapter uses the maintained typed `keyed_uniform`, with exact original source coordinates rather than row positions, clone IDs or graph keys. Model JSON preserves integer coordinate types with decimal-string tags, including IDs above2**53. Descriptive model bytes cannot issue source authority.

Reference transport retains the fitted zero-pattern mass directly rather than reconstructing it by subtracting rounded positive probabilities from one. This preserves representable leading intervals such as a zero donor with weight `2**-54` beside a positive donor with weight one. Every present positive-mass pattern, including the zero-income pattern when not named as required, must meet the declared pattern minima. Binary64 is the numerical input contract: floating dtypes wider than 64 bits refuse before target, explicit weight or uniform conversion. Where NumPy's `longdouble` aliases binary64, it remains supported; tests do not claim to exercise an unavailable extended-exponent representation. Already constructed Frame weights retain the Frame's own binary64 input contract.

Support policy is mandatory and has no native default. It records positive-mass row/household counts, person and household effective sizes, separate overall/positive/pattern minima, and required patterns. Zero-weight observations stay visible in raw diagnostics but are never sampled or counted as positive support. Absent nonrequired patterns retain empirical zero and an explicit absence diagnostic; observed rare patterns cannot bypass the declared minima. Invented tests use named test policies. Native adequacy thresholds and sensitivity criteria require separate review.

The US source qualifier calls the existing actual preparation and complete ASEC catalogue owners. Existing interest/dividend qualifiers already authenticate all current-year member rows before projecting selected `.person` tables; their full `.asec_literals` supply the donor pool. Exact full roster joins retain original household weights using `Fraction(HSUP_WGT,100)`, with no sample or clone multiplier. Ordinary interest is `TRDINT_VAL`, not combined `INT_VAL`; dividends are `DIV_VAL`. Missing retirement/rental information does not disqualify a known pair. Allocation/edit/topcode descriptors, including the existing I_DIVYN codebook ambiguity, remain descriptive provenance.

The recipient path admits only jointly unknown, explicitly unmeasured under15 O/D observations. Source errors take precedence. It refuses contradictory or positive out-of-universe ASEC values, numeric out-of-universe ACS INTP, invalid ACS adjustments hidden by blank-status precedence, and unsupported known/partially-known incumbents. Source amounts and knownness are never rewritten by this module. Future model zeros must be labeled imputed, not observed nonreceipt.

The qualifier extends maintained source identity and live function/default/closure fences around initial and final actual owner borrows. Its returned tables remain descriptive: downstream owners must retain and requalify original source owners, verify model/scenario artifacts and independently reconstruct the complete receiving population. A copied receipt or DataFrame cannot grant that authority. The new source tables are bounded to600,000 full source rows; the64MiB encoding ceiling applies to encoded metadata/individual coordinate data here, not a demonstrated resident-memory bound. The existing parent and future runtime guards retain their independent limits.

The interpretation seal includes the routing domain, receipt, account and allocation constants used by the literal projectors. The unpublished-allocation set is represented by its type and sorted immutable values, so changing its contents cannot silently change provenance. Authored actual-owner controls preserve an allocation flag on the excluded teenager, compare raw original catalogue weights with projected weights, refuse malformed or contradictory excluded-donor literals pinned before issuance, and mutate detached projections during final catalogue/preparation callbacks. These controls remain unrun pending guarded acceptance.

This commit changes no receiving graph, canonical columns, source-knownness, tax rules, PUF allocator, calibration, dataset, paper/site deployment or release gate. The graph integration lane owns separate private model-support CREATE branches with exact schema Slices; it will leave the receiving survey spine, clone expansion and geography unchanged. Whole-Frame reconstruction, composed cold/required replay, child-containing PUF admission, native donor diagnostics, household holdouts and scenario sensitivity remain pending.
