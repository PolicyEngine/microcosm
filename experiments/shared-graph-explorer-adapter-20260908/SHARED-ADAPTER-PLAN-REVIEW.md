# Shared Microcosm adapter plan review

2026-09-08. Source-only design review: the proposed standalone `microcosm.graph.explorer` adapter is a sound presentation boundary, provided it treats its input as supplied declaration metadata. Accepting a schema dictionary deliberately gives up the actual `CompiledGraph` verification performed by `graph_schema`; the adapter must not describe its output as freshly compiled or authenticated. No generic-shell change is required by the reviewed types.

1. **Keep value identity and revision separate.** Namespace operation, field and source IDs. A field ID must include population, entity, column, producer and declared_in. Build the field roster from visible schema rows plus distinct historical input bindings; the latter obtain dtype/ownership/rewrite from their actual nearest Owned declaration, as existing `fieldAtRead` does. Coordinate-only deduplication would erase rewrite incumbents. Keep population/base/compiled-version keys in domain data; they are structural populations, not document revisions or generic containment. Preserve the supplied declaration SHA separately from any converted-document digest. It is suitable as a declared snapshot revision, with no verification claim; do not imply that it uniquely hashes compiled/schema tables, which are separate supplied values.

2. **Export every declared role without inferring formulas.** Include compiled-predecessor edges as their own kind, alongside produced, declared_read, structural_input, source and typed artifact edges. Edge identity must retain role, read subtype, mask and nominal artifact input/output identity so parallel relationships survive. For a carried field, trace the actual base population's corresponding value into the structural carrier; label this ancestry, not unchanged-value equality. An incumbent read before a rewrite remains a current-carrier value whose declaration can come from the base. Never connect the final rewritten output back into its own operation. Artifact edges need exact producer/output/type agreement; a declaration alone supplies no artifact bytes or receipt. Preserve explicit slice, slice-mask, output-mask and rewrite-incumbent roles. Do not label the export as complete runtime schema: IDs, memberships, weights/strata and implicit EXPAND cell reads remain outside the current schema protocol.

3. **Validate references and consistency, not compiler correctness.** Before constructing vertices, bound and detach exact plain JSON-compatible containers; reject unsupported objects, non-string keys, non-finite numbers and excessive depth/items/strings/integers. Check unique operation/source IDs, complete compiled order/version/predecessor references, duplicate visible coordinates, actual Owned references, exact artifact endpoints/types and recognized binding roles. Refuse a missing prerequisite instead of inventing an edge. Preserve all original declaration and compiled metadata, including keys absent from the narrower TypeScript interface, such as a declared mass_partition. Do not silently regenerate predecessors or implement a second compiler to claim equivalence. A coordinated fake schema dict can still satisfy display validation; only a separately configured upstream producer can establish its provenance. If the adapter verifies the declaration digest, use the existing exact canonical byte convention before integer tagging; otherwise explicitly retain it as supplied. A schema/output digest binds all metadata independently.

4. **Bound the full export, not just a selected trace.** The 600-node lineage rendering cap cannot be used to truncate the full adapter document while calling it complete. Derive conservative node/edge budgets from bounded operations, sources, visible rows and input bindings; count role-expanded edges and prospective encoded bytes before allocation. Include copied metadata and integer-tag expansion in that budget. A full document should either complete or refuse its size limit; selected-view truncation belongs in a separately labeled projection with omission counts. These bounds cover adapter construction/output buffers, not the memory already occupied by the caller's schema dict or a future renderer.

5. **Preserve exact metadata and evidence separation.** Transform unsafe Python integers to a documented decimal-literal JSON tag before JavaScript parsing, throughout params and preserved metadata, using exact type checks so booleans remain booleans. Keep finite floats as floats, including integral-looking floats; do not use a float round-trip to decide integer identity. Define how integer tags are distinguished from an originally authored dictionary of the same shape if round-trip fidelity is claimed. Source domain nodes retain name/codec/description; citations remain plain declared text, not guessed URLs. Emit no execution statuses, activities, receipt verdicts or release badges from this input. The shared contract's externally supplied ReceiptAssessment binds exact converted-document bytes and subject revisions; it is not populated from declaration JSON. Metadata should state protocol, country, supplied declaration identity, adapter version and specification-only scope.

Useful small acceptance cases are: carried derived fields across versions; a masked rewrite with both incumbent and final values; same-name fields from separate populations; parallel compiled/read/artifact relationships; missing and contradictory endpoints; complete preservation of an extra declared metadata key; bool versus large positive/negative integer versus float values; and prospective size refusal. These are adapter value tests, not population or compiler execution evidence.
