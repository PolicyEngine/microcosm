## Findings

**P2 — A legitimate named-mask binding can fail the predecessor check.** `packages/microcosm-graph/src/microcosm/graph/explorer.py:300–303` requires every supplied read provider to be a direct compiled predecessor. Current main `decl.py:615–623` only validates a named mask's dtype; `decl.py:649–659` adds explicit slice-column providers but does not add a separately derived mask provider. A graph with CREATE age, a normal operation producing boolean mask, and a consumer declaring `Slice(person, (age,), rows=mask)` therefore has an exported slice-mask binding that this adapter rejects, although the actual compiler accepts the declaration. This is an existing compiler/read-coverage distinction, not evidence that the mask was supplied by the CREATE. Preserve the separately stated compiled and declared-read relationships; do not impose the absent compiler invariant on mask roles. Add a real compile-derived metadata control with a derived mask that is not also an explicit slice column.

**P2 — Declared-read edges are not checked against the actual declaration roles.** `explorer.py:285–309` checks endpoint existence, kind, and predecessor membership, but never checks `operation.inputs`, output masks, or rewrite declarations. Starting from the existing valid fixture, clearing input_bindings passes this loop and loses every declared-read edge. Alternatively, copying the consumer's age read and changing its column to mask, producer to filtered, and declared_in to base satisfies current reference checks even though the consumer's Slice only declares age. The output then presents an invented mask `declared_read` edge with complete scope. Compare supplied role tuples `(node, kind, entity, column, rows)` to the tuples actually declared by slices, named masks, and rewrite outputs, while leaving producer resolution with the source metadata. Refuse missing/extra roles. This is bounded presentation consistency, not a second compiler. Tests should cover both deletion and extra-role injection; current invalid tests only cover unknown provider/kind.

**P2 — Expanded-output byte admission happens after graph construction.** `explorer.py:192–213` accumulates node/edge records, escaped composite IDs and canonical revision bytes using only count limits. Structural expansion at `315–320` can repeat the same base-field inputs across many operations. The first aggregate expanded-output byte check is `_copy_json(result, transport=True)` at `374` (followed by serialization), after those records have already been allocated. Input size and 20,000-node/100,000-edge caps give a finite bound, but they do not enforce the intended 64 MiB output-construction budget. Long IDs and repeated structural edges amplify the gap. Account for conservative encoded bytes before adding each record, including retained metadata, string escaping, numeric tags and revision overhead; retain the final exact encoder check. A small-limit test should establish early admission failure before accumulating all expanded edges, not merely eventual failure of the last serialization. Alternatively document a serialization-only bound and a separately justified, larger construction bound; do not claim the former bounds the latter.
