# Final report: populace #530 processed-PUF audit and QBI port

## Outcome

All three deliverables landed on `qbi-port-530` without network access,
copying microdata into the repository, pushing, or opening a PR:

1. A tracked, aggregate-only audit enumerates all 74 arrays in the exact
   1.8.0 `puf_2024.h5`.
2. The archived Section 199A model is now pure, seeded, version-gated
   Populace logic with vendored assumptions.
3. The true restricted raw assets and release aging were identified; a pure
   raw-aging engine, archived parity profile, runtime handler, migration

The production raw pin is intentionally not declared complete. The current
builder still reads the transitional processed HDF, and a certified raw
revision plus corrected Ledger-backed target-year factors are unavailable in
this sandbox.

## Artifact audit

The audited `puf_2024.h5` is 241,045,964 bytes with SHA-256
`8182579ddfecaf5e5b872e2307b88f03e8e8def993171b648f701a19a847f37b`.
It has 74 root datasets, no root attributes, 484,015 person rows, 207,692
tax-unit rows, and 362,844 marital-unit rows.

The current donor mapping selects 40 physical columns before full-contract
validation:

- 34 preserve direct raw-field tax-unit lineage after regrouping;
- six are retired-code derivations;
- 34 physical arrays are unused.

The requested direct-mapping classifications are:

- educator expense: raw `E03220` passthrough;
- Form 4952 elected income: raw `E58990` passthrough;
- SALT refund: raw `E00700` passthrough;
- physical tuition: raw `E03230` passthrough.

The later `max(E03230, E87530)` tuition rule is not embedded in the release.
The artifact physically contains only one QBI-contract leaf,
`w2_wages_from_qualified_business`, generated by the old deterministic
16%-of-positive-QBI proxy. A later retired loader synthesized and wrote the
15-leaf surface as a load-time cache migration.

QBI v1 supplies the 14 absent QBI leaves, but the exact transitional HDF still
lacks ten non-QBI donor outputs: mortgage-only interest, unreimbursed employee
expenses, farm operations, partnership self-employment earnings, and six
mortgage-structure leaves.

The complete table and ready-to-paste audit summary are in

## Section 199A port

The port includes:

- `qbi_assumptions_v1.yaml`, with explicit PCG64, seeds 41/42/43/64, source
  order, exposure order, and every distribution parameter;
- immutable assumptions and normalized input objects;
- pure NumPy qualification, SSTB, W-2, UBIA, REIT/PTP, and BDC functions;
- explicit rejection of missing/unsupported versions and reordered streams;
- replacement of the artifact's stale W-2 proxy before donor construction;
- the existing post-QRF reconciliation and plausibility gates;
- compact 15-leaf golden streams and a restricted full-artifact replay test.

The production donor boundary explicitly requests
`qbi_simulation_version=1`. The assumptions object is separated from the
engine so a future evidence-anchored v2 can replace occupation/SSTB and
employer-structure assumptions without rewriting orchestration or the output
contract.

## Raw pin and aging

The true inputs are:

- restricted `puf_2015.csv`: 207,696 × 222, observed candidate SHA-256
  `0a7fd643edb1acc55c507db795914b41d232922be78c149b58d111f4672499df`;
- restricted `demographics_2015.csv`: 119,675 × 7, observed candidate
  SHA-256
  `2d275cc405a1d0b254855628eabefe6c6484570ab789b2777a037ea604a82e81`;
- `irs_puf_2015.h5`: only a two-table wrapper, not a governing source.

The observed hashes need licensed-source certification because the archived
prerequisites set neither remote revision nor SHA-256. The demographic file is
not needed for a tax-unit-only donor unless retired personization is
reproduced.

The release labeled `puf_2024.h5` has effective value vintage 2021. Its
intended 2021-to-2024 loop iterated integer year columns as though they were
variable names, so it applied nothing. The audit profile therefore supports
exactly 2015-to-2021 and preserves the accidental double scaling of `E00900`
and `E26270`; it does not pretend to be genuine 2024 aging.

The new raw-aging engine:

- scales only declared raw fields;
- supports straight, weight, and distinct positive/negative factors;
- rejects duplicate ownership, missing/nonfinite values, and version/year
  mismatches;
- preserves declared identifiers and unchanged sources;
- emits aggregate factor provenance with fact IDs and source digest;
- is registered as the manifest `uprate` handler and requires an explicit
  factor bundle.

Restricted integration tests reproduce processed weights, direct fields,
signed Schedule C and partnership/S-corp fields, dividend/rental/estate
components, release tuition, and the legacy W-2 formula from raw inputs. A
broader read-only reconstruction covered 56 processed outputs with maximum
relative residual `1.82e-16`.

The detailed design and blockers are in
`packages/populace-build/src/populace/build/us/PUF_RAW_PIN_AND_AGING.md`.
