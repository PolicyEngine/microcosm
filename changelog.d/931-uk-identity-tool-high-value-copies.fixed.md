The UK identity tool (`tools/verify_uk_identity_stability.py`) now scopes its receipts past the high-value home copies, and E5 checks the regional uprating on the values that stage left (#931).

- **The copies.** The tool's stacking map gains `household_is_high_value_support_copy`, the flag of `high_value_home_support` (stage 26, microcosm#1240). The receipts that scope to an earlier stage now drop the copies and every CGT row made from them: E5's wealth block and E4's FRS-only frame. The copies' mass folds back by family. After the CGT folds, each copy's weight is added onto its root, so the root is back at its weight before the split. No uniform factor could do this, since only the top value stratum is divided. The fold decodes each copy at the copy-id table's `high_value_support` field. It refuses, by count, a copy without a root, a flag that disagrees with the stored index, an index that disagrees with the id, and a family whose decoded size disagrees with `high_value_support_copies`. Dropping the copies while a CGT layer stays in scope is refused.
- **E5's stored values.** `regional_home_values` (stage 27, microcosm#1112) rewrites `main_residence_value` and `property_wealth` after the uprating, so E5's fixed-point check of the uprating was comparing stage 27's values. The scoping now reverses that rewrite for every stage before stage 27. The value comes back from `main_residence_value_rank_basis`, which the stage keeps, and the wealth moves back by the same change. An artifact without the rank basis, such as a release, is read as before. The reversal refuses a roster in which a later stage declares either column, since it would then hide that stage's rewrite.
- **What moves.** Tool verdicts only. On the synthetic H2 oracle frame, E5's stored-column check failed with the tool before this change and passes now. On any spine built since `regional_home_values` joined the roster, the check no longer fails on that stage's rewrite. The `was_wealth` scope drops the 115 high-value copies (of 404 rows) it kept. On that frame every high-value root is an SPI row, which E4 drops anyway, so E4 reads the same frame as before, and the E6, E7 and E9 receipts are identical. On a spine whose high-value roots include FRS households, E4's scope and weights change too. No stage, value, node key or generated file moves, since nothing hashes the tool.
