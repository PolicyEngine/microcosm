The UK identity tool (`tools/verify_uk_identity_stability.py`) now scopes its receipts past the high-value home copies, and E5 checks the regional uprating on the values that stage left (#931).

- **The copies.** The tool's stacking map gains `household_is_high_value_support_copy`, the flag of `high_value_home_support` (stage 26, microcosm#1240). The receipts that scope to an earlier stage now drop the copies and every CGT row made from them: E5's wealth block and E4's FRS-only frame. The copies' mass folds back by family. After the CGT folds, each copy's weight is added onto its root, so the root is back at its weight before the split. No uniform factor could do this, since only the top value stratum is divided. The fold decodes each copy at the copy-id table's `high_value_support` field. It refuses, by count, a copy without a root, a flag that disagrees with the stored index, an index that disagrees with the id, and a family whose decoded size disagrees with `high_value_support_copies`. Dropping the copies while a CGT layer stays in scope is refused.
- **E5's stored values.** `regional_home_values` (stage 27, microcosm#1112) rewrites `main_residence_value` and `property_wealth` after the uprating, so E5's fixed-point check of the uprating was comparing stage 27's values. The scoping now reverses that rewrite for every stage before stage 27. The value comes back from `main_residence_value_rank_basis`, which the stage keeps, and the wealth moves back by the same change. An artifact without the rank basis, such as a release, is read as before. The reversal refuses a roster in which a later stage declares either column, since it would then hide that stage's rewrite. (Later in #931 `regional_home_values` retires and the reversal with it: the WAS chain's area home values keep their draw beside the value they write, and E5 recomputes the main residence from that draw through them and the uprating, which divides by it: `931-spine-localises-home-values`.)
- **E8's band donors.** E8 reran the income band donor stage (stage 17) on the frame its CGT checks read, where only the CGT layers were folded away. The high-value copies stayed in the rerun as households the stage saw, and the stored seats, carriers and band weights read a donor's copies as donors of their own. Once the copy-id table gave each layer its own field, the rerun was refused outright: the donors it appended sorted below the copies' ids. The check now scopes the artifact as E5 does (`_frame_as_stage_saw`). Every row minted after stage 17, the high-value copies and every CGT row, is dropped with its people and benefit units, and its mass folds back onto the row it came from. So the check reads the frame stage 17 wrote, at the weights it left, and each donor once, and reruns the stage on that frame less its donors, at the weights the stage read. A row minted after stage 17 that the scope leaves in place is refused by count.
- **What moves.** Tool verdicts only. On the synthetic H2 oracle frame, E5's stored-column check failed with the tool before this change and passes now. On any spine built since `regional_home_values` joined the roster, the check no longer fails on that stage's rewrite. The `was_wealth` scope drops the 115 high-value copies (of 404 rows) it kept. On that frame every high-value root is an SPI row, which E4 drops anyway, so E4 reads the same frame as before, and the E6, E7 and E9 receipts are identical. On a spine whose high-value roots include FRS households, E4's scope and weights change too. E8's band-donor scope moves E8's receipt and no other: on any spine with high-value copies, the check reads each donor once, and its rerun, which needs the SPI tape, now completes where it raised before. No stage, value, node key or generated file moves, since nothing hashes the tool.
