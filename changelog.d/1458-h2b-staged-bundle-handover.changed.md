UK builds hand their staged dataset bundle, and a failed build's graph evidence, to the build's emitter with `stage_dataset_bundle` instead of committing it with `HfApi`: every file goes by path with its role (an output's `outputs` key as a role name, so `dataset` and `calibration_diagnostics`; the manifest, `staged_manifest.json` and `sha256sums.txt` as `build_manifest`, `staged_manifest` and `checksums`), its SHA-256 and its size, and the emitter's receipt becomes the `staged_dataset` record. The build waits for the emitter's first upload attempt for at most 30 minutes (`STAGED_DATASET_WAIT_SECONDS`) and records a bundle still queued then as `failed` with the emitter's last error code, or `UPLOAD_PENDING`; with those codes (`RETRYING_ERROR_CODES`) the bundle may still arrive, because the emitter keeps it queued and the next emitter on the machine uploads it. The record's error codes gain `CREDENTIAL_MISSING`, `PRESERVED_FILES_MISSING`, `PRESERVED_BYTES_CHANGED`, `UPLOAD_PENDING`, `HANDOVER_REFUSED`, `EMITTER_UNAVAILABLE` and `RECEIPT_UNRECOGNIZED` (a settled answer Microcosm does not recognize, which is final), and the manifest names the emitter's hand-over in `staged_dataset_handover` (its ID, the repository, the run id, the run directory and the outputs' digests as handed over) and keeps what the build's staging run recorded in `staged_dataset_at_build`. After staging, the build rewrites the manifest, `sha256sums.txt` and the national build record only when the receipt lists them in `copied_files`. The remote-staging check before a build is the emitter's `check_write_access`, so a remote stage is refused up front without a running emitter, and the refusal names its cause and remedy (no emitter command, an emitter older than the minimum with the upgrade command, a failed start, an unanswered check, or a repository that is not `owner/name`). A build whose environment sets `HF_HUB_OFFLINE`, as the Modal runner does for every build, hands no bundle over and records it as `local_only`. `tools/stage_uk_rowwise_candidate.py` starts a short-lived emitter with only its Hugging Face module, records the outcome of the build's own hand-over when this machine's emitter still holds it, wherever the directory is now once it landed (so a national build no longer ends `REMOTE_DIFFERS` after its build record changed), hands the directory over as a new job when that hand-over has not landed and can never finish (its files changed, or are gone from the moved directory's old paths; the emitter keeps retrying the abandoned job), never replaces a landed record with a failure but exits 1 when an attempt failed, keeps the manifest's records when a national directory's new hand-over comes back `REMOTE_DIFFERS` where the emitter does not hold the build's hand-over, and waits up to three hours by default (`--wait-seconds`); it updates the manifest and says that the staging run's artifacts and `dataset_staging` event still hold what the build recorded and the Logbook row the phase that gave it. `HuggingFaceDatasetStorage` keeps only `download_file`, for fetching a staged bundle.
