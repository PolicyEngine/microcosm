The UK spine mints every copy row's ids from fixed decimal fields declared in `microcosm.build.uk_runtime.copy_id_table`, not from a power of ten above the largest id each copy layer sees (#931). Once the spine clones households at its start, that largest id would grow with the clone count K, so every layer's offset would move with K and the K=1 spine would stop being the clone-0 slice of the K=15 spine. Copy `k` in a field takes `id + k × radix` on all five id columns, so every copy id is a function of its source id and its copy path alone. The fields, least significant first: `vintage` (10 ordinals at 10^8, reserved for pooled FRS vintages, minted by nothing yet), `geographic_support` (100 at 10^9, for the clone-first spine), `spi_support_channel` (3 at 10^11: the SPI copy at 1, the income band donor at 2), `high_value_support` (6 at 10^12), `cgt_support_split` (10,000 at 10^13), `cgt_incidence_clone` (2 at 10^17) and `cgt_residential_split` (8 at 10^18, the top field). The largest mintable id is about 7.2e18, below int64's limit, which the module checks when it loads.

- **Where.** `frs_spine` refuses raw ids at or above 10^8. The SPI support channel, the income band donors (whose sources are now read from their `{entity}_source_id` columns), the high-value split, the CGT support split, the incidence twin and the residential arms mint through the table, which refuses an ordinal outside its field, a row that already carries one and an int64 overflow. The CGT split refuses a household that would need more than 10,000 copies with a fixed message. The incidence anchor pairs each twin with the id less the twin field's radix, whatever the frame's largest id. The executor recovers each id-offset stage's parents at the stage's declared radix, refuses an incumbent id at or above it, and reads ids as exact int64 on any frame; the row-by-row walk it replaces read a row holding only integer and float columns as float64, inexact above 2^53. The UK modules' refusals on the copy path print counts, never ids: the new ones, and the older checks that listed up to five ids or printed the largest (uniqueness, links, sources, carriers and weights in the clone helpers, the SPI support and spine stages, the row-wise dataset and its tool's dry-run plans, the CGT stages and the spine sampler); the shared graph executor's own EXPAND checks, which every copy stage also passes through, are unchanged, and some of them still name ids. `create_uk_spi_support_tables` no longer takes an `id_multiplier`. The identity tool (`tools/verify_uk_identity_stability.py`) decodes the CGT support copies and the residential arms at their fields' declared radices and records the declared radix as each receipt's `id_multiplier`; it refuses, by count, a spine whose copy ids do not follow the table, as every pre-table spine with copy rows does, and such a spine is receipted with the tool at the commit that built it.
- **What moves.** Base FRS rows keep their ids. Every copy row's five id columns now sit at its parent row's ids plus its layer's offset: SPI copies 10^11, band donors 2×10^11, high-value copy k k×10^12, CGT copy k k×10^13, twins 10^17 and arm j j×10^18. Each used to be a power of ten above the largest id its layer saw. Relative id order is unchanged at K=1, so sorts, ties, ranks and folds are unchanged. Values move on copy rows through every draw keyed on the copy's own id: the SPI income stage's second stage, stages 19 to 24 and 27 to 41, every twin's Advani-Summers prior (so the CGT gains layer is re-realised), stages 48 to 54 and policyengine-uk's Warm Home Discount draw on copy households in spine engine calls. Base rows move second-order through pooled steps: the high-value selection, the regional value ranks, the landlord walk, the residential solve, the anchor, the CGT walks and calibration. Draws keyed on `person_source_id` do not move. National ids pass 2^53 from the incidence twin on, and at the CGT support split for any copy at ordinal 901 or more. The released file's identifiers, ranks of the build ids, do not move at K=1, while its `*_build_id` columns carry the new copy ids, so joining copy rows across versions goes through lineage (source id and copy path), not build ids.
- **Dense line.** The dense expand keeps its multiplier above the spine's largest id. A spine carrying residential arms (multiples of 10^18), as a production national spine does, leaves no int64 room for a second dense clone, so every dense entry point (the graph's `uk.full.expand`, the ladder and crosswalk clone routes and the row-wise tool's plans) refuses wherever the dense offset would overflow int64, in one message naming #931 and the clone-first spine. Dense builds with K > 1 of such a spine wait for #931's clone-first spine; K = 1, and a spine whose ids leave room (one without copy rows, say), expand as before. The dataset-size evaluation decodes dense ids back to spine ids on exact integers, 10^19 included. A caller can pass the multiplier the expansion recorded (`weight_tables(id_multiplier=)`); `tools/evaluate_uk_dataset_size.py` infers it from the spine's household ids or the clone-0 household ids, and a dataset the inferred multiplier does not fit is refused by count. A dense file that keeps its true sources decodes its spine stretch again instead of failing.
- **Declarations.** The `id_remapping` texts of the copy stages in `sources.yaml`, `source_stages.json` and the code dictionaries name the table field; the SPI support and band-donor operations gain the key, which the source schema now requires. The stages that read the table bind it into their hashes. The SPI support and band-donor stages also bind `spi_support`, whose clone helper mints their copies; the high-value split binds `cgt_support`, whose exact-total correction weighs its copies; and the CGT clone and anchor stages, which share `cgt_structure`, bind `rowwise_geography`, whose clone helper mints the twins. Every stage whose module or bound helpers import `microcosm.build.stochastic_assignment`, or import another module's function that draws through it, now binds it, so an edit to the keyed draws re-keys each stage they move. Every spine node re-keys; the coverage manifest's source digests and the H2 fixture are regenerated.
