Transport CREATE (`transport.create@1` and `@2`) accepts an optional `donor_profile` parameter: a canonical JSON document that selects a versioned donor-decoding profile and states each of its choices. The first profile, `populace-us-cps-asec` version 1, stages household tenure, legal marital status and full-time study from the donor's raw survey answers and SPM units, refuses a document written for other donor bytes, and records its counts in CREATE's receipt. No graph selects a profile in this change, and a graph that sets none keeps its CREATE frame and receipt bytes.

The change edits `microcosm/frame/transport.py` and `microcosm/build/transport/population_kernels.py`, so seven kernel refs move once: `transport.create@1`, `transport.create@2`, `transport.currency@1`, `transport.quantile_map@1`, `transport.quantile_map@2`, `transport.support_bounds@1` and `transport.boundary@1`. Their implementation hashes change, so the node records of these kernels and of every node downstream of them re-key, and those nodes run again. A stored CREATE inventory stops matching, because its store key includes CREATE's implementation hash (`transport/cli.py`). Stored support-bounds evidence is refused, not rebuilt: it records its producer's implementation hash, and the battery's header check refuses evidence whose hash differs from this build's (`transport/evidence_contract.py`). `gates.battery@1` does not move, and no committed digest moves.
