The UK spine build takes its geographic clone count (#931). `tools/build_uk_frs_spine.py --n-clones K` builds the clone-first spine at K clones, K a whole number from 1 to 100, the `geographic_support` copy-id field's bound. Without the flag the spine builds one clone, as before. K goes to the `geographic_expand` node, to the transform that makes the clones and to the rules engine. Every engine call after `geographic_expand` runs one simulation per clone, and the engine refuses a frame that carries another count. The engine identity does not take K, so it is the same at every K.

- **Guards.** A release candidate takes one clone until #931 group (c) pins the clone count a release builds at. (Later in #931 it also takes the dense release's 15, on a geography-first roster: `931-dense-k-pin`.) `--release-candidate` with any other K is refused when the arguments are parsed, and again when the full build marks a parsed spine request a release candidate. A `--synthetic-fixture-dir` whose `config.geographic_clones` differs from `--n-clones` is refused while the spine is prepared, before any stage runs.
- **Sidecar and Logbook.** The build sidecar records `geographic_clone_count`, read from the frame's `household_clone_index`; a frame without that column counts as one clone. Its rules engine record keeps the engine's provenance at every K and adds the adapter's batch record only when the final frame carries more than one clone, as before. A spine of more than one clone binds its count into the Logbook identity digest; a one-clone build's digest is unchanged.
- **Memory guard.** `--stage-profile-dir` writes, for each spine graph node and under its id, the node's entry, peak and exit RSS and its wall time to `stage_profile.json`. The profiled kernels key as the kernels they wrap, so node keys do not move and a profiled run reuses an unprofiled run's store. A record keeps the message of a failure its node raised, so the directory must stay private. Before any node runs, the build refuses a directory inside the repository, a path that is not a directory, and a `stage_profile.json` there that is not a stage profile of the current schema, which the profiler would refuse only after the first node had run. `.gitignore` ignores `stage_profile.json` and its lock file.
- **National line.** Every spine from #931 group (b) on carries `household_clone_index`, at one clone too, and the national line drops the clone indices from its export only from group (c) on. So the national problem, the first national node that reads the bound frame, refuses such a spine before it resolves anything, in one fixed sentence (María's ruling of 10 Nov, decision 4). Without it, a national build on a one-clone spine would solve in full and then fail its terminal degenerate-surface gate.
- **Identity tool** (`tools/verify_uk_identity_stability.py`).
  - `--spine-sidecar` takes the spine's build sidecar. The tool refuses a frame whose clone count differs from the sidecar's `geographic_clone_count` or, where the spine ran `cgt_support_split`, from the count that stage counted its copies on; the refusal gives only the clone counts. It refuses in a fixed sentence a sidecar that lacks those records, or whose output digest is not `--input-h5`'s. Every receipt records the counts under `geographic_clones`.
  - E4's rules engine takes the frame's clone count (`PolicyEngineUKEngine(clones=K)`), so its `LHA_category` call runs clone by clone, as the stages' calls did.
  - E4 and E5 no longer compare with the store a column that a later stage declares writing in the packaged source-stage manifest. They name it under `rewritten_later`, with those stages (María's ruling of 10 Nov). A rewrite the receipt's scope takes back does not count: `salary_sacrifice` and `regional_home_values`, where the artifact keeps the column each reversal reads. E5 reports `student_loan_balance`, which `student_loans` re-splits. E4 reports four flags that later take-up and coherence stages rewrite: `would_claim_uc`, `would_claim_pc`, `would_claim_child_benefit` and `child_benefit_opts_out`. It also reports the six childcare columns that `childcare_copy_take_up` declares rewriting, which by its notes it re-draws on copies only. So E4 also names, under `rewritten_later_still_equal`, the rewritten columns the store still holds bitwise.
  - E4 recomputes on what its stages read. `LHA_category` is materialized on the frame `frs_brma` read, as far as the artifact restores it. (Later in #931 the frame `area_brma` read.) Columns first written after that stage are dropped, and the flags `frs_take_up` drew that later stages rewrite are put back from the recompute. `lha_category_scope` names what stays as stored, with the stages that write it, `salary_sacrifice` among them, since its reversal takes back only the records it converted. The household weights are taken back through the band donors' funding and the SPI support channel's declared prior-mass shares, to rounding. `is_apprentice` is held exactly or, where those weights move the walk by rounding, to the walk on them, and `held_to_tolerance` then names it.
  - E8's band donor block gives the layer in the forms of the stage's capped receipt, at every seating:
    - the donors and each band's donors, in rounded distinct source households;
    - the stage's funding rows, with their masses and factor withheld;
    - `funding_within_share`, the stage's funding rule recomputed from the stored weights, which E8 also checks (`band_donor_funding_share`). It holds each rebuilt factor at E8's weight tolerance (relative 1e-9), not the stage gate's few ulps, since the stage's exact-total correction on one incumbent row moves a small stratum's rebuilt factor by more than that.

    It no longer writes the funding factors, band weights, weighted taxpayers or mass scale. Its checks still compare them.
- **SPI income band donors.** The stage's clone-index refusals are fixed sentences naming the column, with no count.
- **What moves.** At one clone, no spine value and no gate verdict moves. The sidecar gains `geographic_clone_count`, and the national line refuses a spine from group (b) on at its first node that reads the frame. Node keys move from `spi_income_band_donors` on, and across the national line. The identity tool's receipts gain the fields above.
