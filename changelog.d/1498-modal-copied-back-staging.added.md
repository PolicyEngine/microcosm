`tools/stage_uk_rowwise_candidate.py --modal-receipt <receipt>` stages a UK run directory copied back from a Modal run with `modal volume get`, for when a UK build is registered with the Modal runner. Before it reads any output, it checks that the receipt is of a stage that finished (`COMPLETED`, not stopped at its budget) and that the directory is inside the run's copied-back state directory (`state/` beside the receipt's `receipts/` directory, or `--modal-state-root`, both resolved). The receipt must list the build manifest and every output it registers; an output the stage never copied to the runs volume (`outputs_not_mirrored`) is named as such. Every output must have the receipt's SHA-256 and size. So must the build manifest unless its `staged_dataset` record is `local_and_remote`, as a hand-over from the workstation leaves it; the command reads that mode from the manifest, so a manifest edited to say `local_and_remote` is not compared either, while its outputs still are. The command refuses the directory otherwise, before it starts an emitter. With `--local-only` it checks the directory and writes the staged manifest and the checksum file, but leaves the build manifest as it is, so later runs with the receipt can still compare it. It then hands the bundle over with the re-stage command's existing code, so the records, retries and landed-bundle handling are those of a directory built on the workstation. The command now reports a build manifest that is not valid JSON or not a JSON object, and an output that does not match its manifest digest, as an error message instead of a traceback.
