`tools/stage_uk_rowwise_candidate.py --modal-receipt <receipt>` stages a UK run directory copied back from a Modal run with `modal volume get`, for when a UK build is registered with the Modal runner. Before it reads any output, it checks that the receipt is of a stage that finished (`COMPLETED`, not stopped at its budget) and that the directory is inside the run's copied-back state directory (`state/` beside the receipt's `receipts/` directory, or `--modal-state-root`, both resolved). The receipt must list the build manifest and every output it registers; an output the stage never copied to the runs volume (`outputs_not_mirrored`) is named as such. Every output must have the receipt's SHA-256 and size. So must the build manifest unless its `staged_dataset` record is `local_and_remote`, as an attempt to hand the directory over from the workstation leaves it whenever it records its outcome in the manifest; the command reads that mode from the manifest, so a manifest edited to say `local_and_remote` is not compared either, while its outputs still are. Every refusal comes before the command starts an emitter. A directory that passes is handed over with the re-stage command's existing code, so the records, retries and landed-bundle handling are those of a directory built on the workstation. With `--local-only` and `--modal-receipt`, the command hands nothing over: it checks the directory and writes the staged manifest and the checksum file, but leaves the build manifest as it is, so a manifest that still holds the build's record is still compared by later runs with the receipt. On a copied-back directory, pass the receipt with `--local-only`: without it, `--local-only` writes a `local_only` record into the build manifest, which can make every later run with the receipt refuse the directory. The command now reports a build manifest that is not valid JSON or not a JSON object, and an output that does not match its manifest digest, as an error message instead of a traceback.
