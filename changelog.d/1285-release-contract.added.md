`docs/release-contract.md` puts the release contract on paper (ARCH-1, cos d1160): the end state, the releases in service on 2026-10-15, and contracts C1 to C5 (release manifest and certification, loader compatibility, staging and run outcome, the Logbook, publish and registry), each as the code enforces it on 2026-11-12 and as its version 1 would, with how far each milestone had got by that date. C5 version 1 takes the build-folder shape in which main already publishes every UK and US build: `releases/<release>/<build>/`, `releases.json` and `microcosm-publish-release-build`. The document says how C1 version 1 keys by declared country instead of release-name strings, records where the recertification lane and C2 version 1 disagree, carries microcosm#378's parity rule, and replaces the branch-only `us-uk-release-path.md`. It changes nothing that publishes.

`tools/generate_release_contract_fixtures.py` writes version 1 of the contract's golden fixtures under `packages/microcosm-data/tests/fixtures/release_contract/v1`, following the staging-fixture pattern. For C1 it freezes one build folder's manifests for the UK national release and for the US national release, each from that country's own writer, and an inventory of what the contract requires of the UK national release. For C5 it freezes one `releases.json` for each country's repository, built with the emitter interface's own changes, and a registry snapshot. `writers.json` names the writer of every file `SHA256SUMS` lists, `SHA256SUMS` pins every byte, and `--check` fails when a regeneration differs. The UK national assembler's manifest construction moves into `uk_national_release_manifests`, a pure function the generator also calls; the assembler writes the same bytes as before.
