US fiscal refresh builds, exact-count builds among them, and their certifications write their staging run files (`runs/<run_id>/` in the US staging repository) with the version 2 writer, as UK builds do: version 3 documents with the run's country (`US`), operation, pipeline, candidate, release, run kind, sampling and delivery summary, ordered events, and result files under `artifacts/<name>.json`. A stage the build reports as running starts an event, a failed check is a failed event that leaves the run running, and any other status (`skipped`, a check's own verdict) is a completed event whose details keep it as `stage_status`. A build whose release checks fail once its record is written (exit 3) closes its run as `blocked`; any other ending is a failure with a classified error code and no error text. The build manifest's `staging` block is the run's version 2 delivery summary, which publication already checks. Each result file the US build attaches is named in `US_STAGING_RESULT_FILES`, with its artifact kind and classification; version 2's content checks (`StagingContentPolicy`) now take a list of artifacts reviewed to hold rows of aggregates, each with its own size limit up to the emitter's 32 MiB, and the US list holds every result file with rows, `calibration_diagnostics` at 32 MiB. An artifact that would take a run's artifacts past what keeps a hand-over within the emitter's 64 MiB request limit is refused alone. A staging error, such as a refused result file or a failed local write, now prints a warning and never stops the build or its hosted telemetry. `--staging-dir` is the local root, with the run's files at `<dir>/runs/<run_id>/` (`<out>/staging` by default, the same place as before). `--exact-k` no longer requires `--no-staging`, and the exact-count launcher no longer passes it; the launcher's own `--no-staging` passes it on for a build that should not stage. A failure reported after the build's run has finished closing leaves the run as it was and checks its final commit no second time. A SIGTERM or Ctrl-C that interrupts a run's closing leaves the run in the state it reached, hands that state over once more and checks its final commit by receipt. During a completion, the build then records the termination and exits 143, as before; once a failing build is closing its run, it ends only that close, as one during the final commit check does, and the build keeps its own outcome and exit status.
