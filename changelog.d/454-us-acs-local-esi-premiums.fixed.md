The US ACS local release lane transfers `employer_sponsored_insurance_premiums` onto its ACS spine (microcosm#454). Before, those rows were null, and the release tool's `fill_reviewed_nulls` refused the staging frame of any donor that carries the column. The staging build now qualifies the donor before the ACS fetch, transfers the column in a lane-only pass fitted on the donor's ASEC observations, which carry measured wages, and runs that pass after the hours and income passes and immediately before the shared transfer; on the test fixture every other value is byte-equal with and without it. A new kernel in `esi_premiums`, `with_us_esi_premium_pool_anchor`, then clears the premium for ACS people without wages and scales the rest so both spines carry the same weighted premium per unit of household mass, which keeps the lane-wide column at the donor release's own. The declared ACS transfer plan does not change. The ESI summary and both ESI gates take a new keyword, `allow_transferred_rows`, so they can grade a frame that mixes CPS rows with transferred rows: with `True`, which only the lane passes, the CPS rows get the MEPS-IC recomputation and the gates compare the transferred rows with them, and a row the CPS record id and raw coverage fields cannot classify fails both gates. The default, `False`, keeps the rule the base build and the fiscal-refresh release tool already applied: every row must carry the raw ASEC coverage fields, and the CPS record id is not read. The lane runs both gates on the staging frame and, in finalize, on the calibrated artifact; the gate report records `esi_premiums_signal` and `esi_premiums_anchor` bound to the artifact bytes, its `input_coverage` entry passes only if both do, and package by default refuses a report without passing verdicts for the bytes it packages. `us/gates.json` also declares the two finalize gates as `us_local_esi_premiums_signal` and `us_local_esi_premiums_anchor`, bound to the lane's own row-kind gates, so the gate battery's shadow compares them like the release's other gates and records `--allow-esi-premium-gaps` as their waiver. `--allow-esi-premium-gaps`, on the staging tool and the release tool, records a refused donor or a red verdict for a diagnostic build instead of failing; with it, package also takes a red verdict bound to the packaged bytes that finalize recorded as waived (`enforced: false`), and no other; the shadow keeps each entry's waiver as finalize had it, and shows it only on the gate report that finalize run wrote (otherwise, or when it cannot read the record, it records the waiver as unknown, with the reason); a Modal plan can pass it to the release tool only. The staging tool refuses a donor with any row that lacks a raw coverage field or a CPS record id, and the ESI gates turn a mixed frame whose CPS rows carry no weighted anchor evidence, or whose household mass, employer premium or MEPS-IC share sums past the largest float, into a red verdict.
