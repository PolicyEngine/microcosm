`tools/patch_us_acs_donor_columns.py` writes a patched copy of a published US national donor H5 for the County Files proof of concept's ACS staging (microcosm#922, plan microcosm#1647). It adds reviewed all-zero columns on the entity the US engine gives them (`strike_benefits`: no donor or ASEC pppub23–26 row has `OI_OFF` 12; `passive_partnership_s_corp_income`: the donor holds partnership and S-corp income as one combined `partnership_income`), refuses a column that is already present with any other value, keeps every other table, column, dtype and root attribute, and writes a receipt with both SHA-256 digests, the row counts, each added column with its reason, and the tool's commit. It first restores the three ASEC work columns (`detailed_industry_recode`, `major_industry_recode`, `worked_last_year`) on `person`, valued as the #720 restoration and the `org_wages` carry value them: it reads each donor income year's pinned ASEC person member (refusing a file whose SHA-256 is not pinned), joins `WEIND` and `WEMIND` on source year and exact `PERIDNUM`, refuses a donor person with no member row or more than one, checks eight Census identity columns on every row, and records the files, their digests and the match counts in the receipt. It reads the members from `--asec-source-cache` (default `~/.cache/microcosm/cps/asec_education`) and downloads a missing pinned archive only with `--asec-fetch`. The published donor is read only, and no default changes. It refuses an existing output copy, receipt or copy release manifest unless `--overwrite` is passed: a re-run writes a copy with another SHA-256 (the HDF5 object headers record write times), so a staging summary built on the first copy would no longer match it. With `--input-release-manifest` it checks the input against the published donor's release manifest and records that build in the receipt. With `--release-manifest`, `--manifest-release` and `--manifest-build` it also writes a build-folder release manifest for the copy (in `policyengine/populace-us-staging` by default), so the ACS staging can take it as `--donor-release-manifest` and record the copy's build as `donor_release`, which the local-area release contract requires before publication.
