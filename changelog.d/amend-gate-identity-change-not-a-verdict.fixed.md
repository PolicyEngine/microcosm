A kernel that reports a changed identity no longer has that report filed as a gate verdict (graph amendment 29). `KernelIdentityChangedError` is new. `gates.battery@1` raises it when its binding registry, or a source file in a binding's closure, has changed since the kernel was built, or can no longer be read or parsed. It checks before it evaluates, before it returns, and when evaluation raises. The executor re-raises that error instead of filing a `fail` under the node key. The run refuses, nothing for that node is stored, and the nodes it had already completed keep their stored results. So a build edited mid-run no longer leaves a stale `fail` that later runs of the unedited registry are served. The change moves the implementation hashes, and therefore the node keys, of `gates.battery@1`, `export.prepare@1` and `transport.package@1` and of their descendants, so stores recompute those nodes once.
