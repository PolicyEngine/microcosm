Hold dense engine blocks, release candidates and size evaluation to the spine's clone count (#931). The dense line takes its geographic clone count K from the spine it binds; now every reader of K holds to it. The dense line still refuses every spine whose roster is not geography-first, so no dense build runs yet; what changes is which spines and runs are refused, and how size evaluation reads a dataset.

- **Engine blocks.** `full_measure`'s engine blocks take the clone count their caller binds (`clones`, through `resolve_uk_full_measures` and `resolve_uk_full_national_problem`) and refuse a frame whose geographic clone count is not K, at every block count, one included: a one-block call on some of the pool's clones (one of them, say) used to pass. The check reads the clone count alone, so a part of the pool that keeps every clone index is not refused there. Blocks other than one or K are refused too. The refusal names the two clone counts and nothing else. The dense measures node carries the spine's K as its `geographic_clones` parameter, which its kernel hands to the engine blocks beside `engine_blocks`, and `append_uk_target_nodes` takes it, refusing engine blocks other than one or K and a K that is not a positive integer. The national rows (`materialize_uk_national_rows`) resolve at one block of one clone. Without `clones` (callers outside the build graph) nothing changes.
- **`--engine-blocks`.** Preparation refuses a count other than one or the spine's K once it has bound the spine, naming K. Validation still compares it with an asserted `--n-clones` only.
- **Release candidates.** On top of the sampled-spine refusal, preparation refuses a `--release-candidate` whose spine fails any of three checks, naming each failure and K:
  - its clone count is not the doctrine's 15;
  - it was not built as a release candidate (its sidecar's `release_posture`, or the one a spine request's flags give);
  - its geography binding is not a release's: the new `country_adapter.uk_spine_geography_binding_failures` wants the atomic law (`assignment` `"atomic"`), the geography key as `identity`, a SHA-256 `definition_sha256`, support pins equal to the conditioned supports `sources.yaml` registers (`uk_atomic_support_register(conditioned=True)`) and no system the register does not list, and, where it is asked for one, that K; sizes and K must be integers, so a recorded `15.0` fails.

  The in-graph spine of a `--spine-request` records no geography block, so its binding carries K alone: a release candidate on one is refused as recording no geography binding until the request route composes a block. (Later in #931 it composes one with the sidecar writer's helper, and the check also holds the block's stream and register: `931-spine-assigns-areas`.) The `uk_atomic_support_register` docstring now says a release builds on the conditioned supports, and that the base ones are what `tools/build_uk_conditioned_area_supports.py` builds them from.
- **The spine's own `--release-candidate`** still takes one clone. It now also takes the dense release's 15, but only where the packaged UK spec's roster is geography-first (`spine_posture.roster_failures`); otherwise the refusal names what the roster lacks. Every other clone count is refused, in the parser and in the preparation the full build hands a spine request, in a sentence that says 15 needs a geography-first roster. Once later commits of #931 declare the area stages and the WAS chain's localiser, the check passes without a code change.
- **The release pre-flight** (`tools/preflight_uk_local_release_candidate.py`) holds the manifest's `geography.assignment` to the same helper, so to the conditioned register rather than the base one, and requires its `geographic_clone_count` to be 15, as `parameters.n_clones` must be. Its failures name the field and what it must be, never the value: `geography.assignment.assignment is not 'atomic'.` replaces the message that printed the law it found.
- **Size evaluation** (`size_evaluation.weight_tables`) reads a dense dataset as its clone-first spine's rows:
  - Every row's ordinal at the copy-id table's `geographic_support` field must equal its `clone_index`. Each row's spine household is then itself, and its design weight is that spine row's own weight, with no division by K.
  - Where a file keeps no `source_household_id`, distinct sources fold the geographic clones back to clone 0's id (`copy_id_table.parent`), copies apart.
  - The old dense layout's multiplier decode (`_source_multiplier`, `_spine_ids` and their `id_multiplier_for_values` import) is removed, as are `weight_tables`' `n_clones` and `id_multiplier` arguments. A dataset in another layout is refused in one fixed sentence, which names no count, id or value and points at the tools of the commit that built it.
  - The result's `source_id_multiplier` and `source_id_multiplier_basis` give way to `source_household_basis` (`source_household_id` or `geographic_support_parent`), the spine-coverage refusal no longer prints a count, and spine weights that list a household twice are refused.
  - The copy-id guards now list `size_evaluation` among the table's readers, not among the users of the retired rule.
- **What moves.** Keys and records only; no dataset value, and no spine node. No spine kernel or gate phase code hashes an edited module, and no spine stage calls edited code, so every spine node keeps its key and H2 is not regenerated.
  - 12 of the 84 UK kernels change hash, none of the spine registry's 58:
    - the dense and gate kernels that hash `full_measure` or `graph_targets` (`uk.full.target_compilation@1`, `uk.full.target_selection@1`, `uk.full.measures@1`, `uk.full.problem@1`, `uk.full-gates.preflight@1`, `uk.full-gates@1` and `uk.full.rotated-holdout@1`);
    - the national kernels that hash `graph_national` (`uk.full.national_targets@1`, `uk.full.national_problem@1`, `uk.full.national-gates@1` and `uk.full.national-readback@1`);
    - `uk.full.bound_spine@1`, which hashes `graph_build`.
  - So every node of the dense graph re-keys, on a composed spine (after its 84 spine nodes, whose keys hold) and on a bound one, and so does every node of the national graph. The measures node's key also takes its new `geographic_clones` parameter.
  - `full_build_cli`, `rowwise_cli`, `spine_build`, `country_adapter`, `size_evaluation` and the pre-flight tool are hashed by no kernel, and the gate phase codes do not move.
  - The NZ transport kernels' hashes, the US kernels and post-transfer graph keys, the spec engine's compiled bundles and the packaged specs are unchanged.
  - No declaration, generated file, `gates.json` or schema changes.

  - The measures' `geographic_clones` parameter, the measures kernel handing it to the engine blocks beside `engine_blocks`, and the target nodes' refusals.
  - `--engine-blocks` held to the spine's K on both routes.
  - A release candidate prepared on a stand-in spine at 15 clones, built as a release candidate, with the stand-in's own binding.
  - A release candidate on a bound spine at another K, in another posture, under another law or off the register, refused naming each failure; the same spines build candidates. The request route's refusal, naming no geography binding.
  - The spine CLI refusing 2, 7 and 16, and refusing 15 on a roster before the area stages while accepting it on a geography-first one.
  - The binding helper field by field, a float K and float sizes included.
