The dense line refuses a spine that does not assign areas, before it pins or reads any other input (#931; María's ruling of 10 Nov, decision 4). Later commits of #931 group (c) move the dense line onto the spine's own areas; refusing first means none of them can build a dense dataset on a half-moved line. `full_build_cli.prepare_full_build` now checks the spine's roster first: after the engine freeze, and before it pins an input, reads the spine, authenticates the checkpoint or composes a graph. It checks again the roster the build then binds. No spine built from this code passes yet. The check passes once the spine declares its area stages and the main-residence localiser, and a bound spine's sidecar records the geography block.

- **The geography-first names** (`microcosm.build.uk_runtime.geography_first_roster`, new). A names-only leaf that imports nothing first-party: `GEOGRAPHY_FIRST_STAGES` (`geographic_expand`, `geographic_identity`, `atomic_area_assign`, `local_authority`, `rfdr`, `area_brma`, `spi_copy_areas` and `private_rent`), `GEOGRAPHY_FIRST_OPERATIONS` (`was_wealth`'s `localise_main_residence_value`) and `SIDECAR_GEOGRAPHY_KEYS`, the keys of the build sidecar's `geography` block (`assignment`, `identity`, `definition_sha256`, `support_pins`, `stream` and `register`). Its stage names are the ones the stages' transforms declare, and a test holds them together.
- **The check** (`microcosm.build.uk_runtime.spine_posture`, new). `roster_failures(stages, operations, geography=None, *, from_sidecar=True)` names, in the leaf's order, every stage, operation and block key a roster lacks. A roster that is not names fails as a whole (`stage roster`, `operation roster`), an operation counts only in a stage the roster ran, and extra names never fail. Only the block's keys are read, never their values. `require_geography_first_spine` refuses a roster that lacks anything, in one sentence that names what it lacks and nothing else: no count, id or value. `stage_roster` reads declared stages' names and operation kinds, and `spec_roster` a spec's.
- **Both routes.**
  - With `--input-h5` the check reads the build sidecar's `stages`, `operations` and `geography`, from `--input-sidecar` where it is named, before the ladder or the spine is pinned. An absent or unreadable sidecar is refused in `load_bound_spine_checkpoint`'s own words. The checkpoint is still authenticated after the check, and the sidecar it authenticates, the one the build binds, is checked again, so one changed since the first read is refused too.
  - With `--spine-request` it reads the stage names and operation kinds of the packaged UK spec, whose whole roster every request runs, before the request is parsed or its spine composed. Its spine runs inside the dense build's own graph, so it has no block to read. The spine the request composes is checked again, on its own stages, before the build reads it.
  - A dry run, with or without `--candidate-clone-counts`, is refused alike. The national line and the row-wise dataset tool (`tools/build_uk_rowwise_dataset.py`) are unchanged.
- **What moves.** No line builds differently: the dense expansion already refused, at any clone count, a spine that carries the geographic clone indices, as every spine built since #931 group (b) does. The check also refuses a spine without them, one built before group (b), which the dense line could still bind until now. The expansion refused only once the graph reached it, so a dense dry run could still plan on a clone-first spine; dry runs and builds now both stop at preparation. A refused build records its attempt as failed, with the refusal as its message. `tools/measure_uk_atomic_assignment.py`'s graph route runs the dense preparation, so it is refused the same way. No node hashes `full_build_cli` or the two new modules, so no node key moves. No declaration, generated file, `gates.json` or schema changes.

  - The packaged roster, and the sidecar the spine build's writer records for it, are refused naming the six area stages and the localiser, and the sidecar also the block.
  - Each missing name fails alone, in the leaf's order; unreadable rosters fail by name; a geography-first stand-in passes, with extra names too; no refusal carries a figure.
  - Through `prepare_full_build` on both routes, recording stand-ins, under which the real request-roster reader runs, show the refusal comes before any input is pinned or read and before any graph is composed, and that a geography-first stand-in goes on to pin its first input. A sidecar block that lacks any one key is refused naming that key; an unreadable sidecar is refused word for word as the bound loader refuses it. A roster that passes the first check but not on the authenticated sidecar or the composed spine is refused before the spine is used. Through `main`, a refused build records a failed attempt without running a graph.
