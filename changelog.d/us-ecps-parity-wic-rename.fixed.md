The eCPS parity release gate grades the pinned reference's retired layer names under the live engine names, using the same rename register as the release input-coverage manifest (`REFERENCE_ECPS_LAYER_RENAMES`). On policyengine-us 2.2.1 the gate compared the reference's `would_claim_wic` against a candidate that carries the input as `takes_up_wic_if_eligible` (renamed in PolicyEngine-US 1.777.0) and refused a populated layer as all-zero. The projection is recorded in the gate details and refuses to merge two layers. Known-gap exemptions resolve through the same register via one shared helper (`project_ecps_parity_known_gap_names`), so an entry spelled `would_claim_wic` exempts, goes stale on, and goes dormant on `takes_up_wic_if_eligible` exactly as the live-name entry does, whatever spelling the reference carries; the gate details key exemptions by live name, record each entry's register spelling, and refuse a register that exempts one live layer under both spellings. The coverage-manifest generator now imports the runtime rename register instead of its own copy and projects register names before its restored-input guard, so a restored input filed as a gap under a historical spelling is refused like the live spelling; the build's coverage-manifest preflight re-checks the register itself for restored inputs under either spelling. The cross-register consistency preflight (#377) now receives the parity known-gap register by name, projected the same way. It previously received the entry objects, so the parity leg never matched a column.
