The US release's five input-stage passes over household batches (ACA source inputs, Medicaid eligibility, December SSI amounts, SNAP eligibility and the other-health-insurance premiums) now refuse a batch engine that computed a population-aggregate variable, a policyengine-us formula that sums or ranks over everyone in its engine, as target compilation already did. The refusal is on when a pass splits its households into more than one batch, or when a caller passes `refuse_population_aggregates=True`; a pass that runs the whole pool in one batch keeps it off. Before building any engine, a pass with more than one batch or the refusal on also refuses a frame whose groups span households, and a pass with the refusal on refuses a positive Medicaid claiming tax unit ID that names no tax unit in the person's own household. Every batch engine is released before the next one is built, also when a batch fails. In policyengine-us 2.2.1 none of these passes reaches a population-aggregate variable, so their outputs are byte-identical to before. The other-health-insurance premiums now release their engines too: the PolicyEngine-US adapter gains `build_microsimulation` and `calculate_variables`, which `materialize` calls, so a caller can check and release the engine it computes on. That pass runs a youngest-generation garbage collection after each batch and a full one when it ends, instead of a full collection after every batch. The local-area build switches the refusal on for its donor and ACS views even when a view fits in one chunk, because neither view is the whole population. The household partition, the selection, the frame checks, the refusal and the garbage-collection helpers move from the release tool into `microcosm.build.us_runtime.household_batches`.
