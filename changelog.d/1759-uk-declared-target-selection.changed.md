The UK full build selects its solve surface with the shared declared target sets, as the US does (microcosm#1759). `uk/spec/target_sets.yaml` declares the UK level rule (a target's level is `geography_level` or `ledger_geography_level`; the two must agree, and the level must be one of country, region, constituency, la and brma) and the full build's selection by level, one clause for each level. `microcosm.calibrate.target_sets` reads a declared `level_rule` (the US file declares its rule in the same form) and its new `select_by_levels` keeps the requested levels in compile order with the same receipt (`microcosm.calibrate.target-selection.v1`). `microcosm.calibrate.target_selection` is removed: the UK selection kernel was its only caller, and `uk_runtime.graph_targets.target_geography` now reads the declared rule. No selection changes: `test_uk_level_selection.py` holds the new code to verbatim copies of the removed selector and resolver on random registries, refusals included. The new UK resource is in the UK solve fingerprint, so the first UK build after this change computes the spine from `frs_brma` on, the target nodes and the national graph again. The two UK calibration lines are declared there too, as the modes of a `calibration_line` product: `uk_runtime.ledger_targets.uk_registry_on_calibration_line` selects through it with one UK predicate that reads each contract target's `calibration_lines`, which stay in `uk/uk_population_targets.json`; `UK_CALIBRATION_LINES` is the declared modes. The shared selector now reads a target's level only when a clause tests levels. `test_uk_calibration_line_selection.py` holds the line filter to a verbatim copy of the replaced function: the same registry (the same object when nothing drops), the same receipt, or the same refusal.
