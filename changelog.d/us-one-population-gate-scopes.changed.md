The US Medicare take-up gate now reconciles `MCARE` on every CPS row of an assembled frame: the physical ASEC rows and their PUF tax-detail clones (stored channels `asec` and `puf_tax_detail`), the rows Route A reconciles. It leaves ACS rows out, so on d2283's one-population frame an ACS row's empty `MCARE` never reaches the reconciliation. The gate still takes every row of Route A's frames and the pre-clone base, which carry no spine source ids, and the stacked pool stores no `puf_tax_detail` channel, so none of their verdicts or statistics change.

The US weeks-unemployed gate now puts every CPS clone of an assembled frame in its unemployment-compensation rule, as Route A does, whether the frame stores the clone as `asec` (the stacked pool) or as `puf_tax_detail` (Route A's clone label, which d2283's one-population frame keeps). Natives of any other channel stay in the rule, and only native `asec` rows reconcile to `LKWEEKS`, so no ACS row reaches that check. ACS rows on d2283's frame carry the channel `acs_2024_1yr`, which has no reviewed rule yet. The gate fails that channel with one line, `acs_2024_1yr weeks_unemployed has no reviewed rule yet (d2283 spike).`, keeps its statistics and reports null bands for it. Route A's frames and the pre-clone base carry no spine source ids, and the stacked pool stores its ACS rows as `acs` and no row as `puf_tax_detail`, so none of their verdicts or statistics change.

The US retirement-contributions gate now reads `RETCB_VAL` on every CPS row of an assembled frame: the physical ASEC rows and their PUF tax-detail clones (stored channels `asec` and `puf_tax_detail`), the rows Route A reads. It reconciles the outputs on each of those rows whose stored channel matches its operator role, a native stored as `asec` or a clone stored as `puf_tax_detail`, so on d2283's one-population frame it reconciles every CPS row, as Route A does.
