The Modal stage runner gives the build it runs a collector token that only writes telemetry (microcosm#1470). With `--run`, `tools/modal_us_stage.py` first runs the launching machine's `microcosm-emitter telemetry-token` for the stage's class timeout plus 3,600 s, which exchanges the operator's Hugging Face login, and refuses to launch on any failing exit code, an unusable answer or a shorter lifetime. The token, its expiry and its origin reach the container in a Modal secret made for that launch, under the runner's own names (`MICROCOSM_MODAL_TELEMETRY_*`), attached with `with_options` together with any Hugging Face secret; the plan, its digest and its attempt budget are unchanged, and no receipt copies the token. `tool_environment` passes them to the build as `MICROCOSM_COLLECTOR_TOKEN`, `MICROCOSM_COLLECTOR_TOKEN_EXPIRES_AT` and `MICROCOSM_COLLECTOR_ORIGIN` only from that secret, removes those names from anywhere else, and sets `MICROCOSM_TELEMETRY_REQUIRED=1`. A plan may set that variable only to `0`, which asks for no token and runs the build without telemetry, and may set none of the token variables. Before staging, the container refuses the attempt (finished, nothing charged) when the token is missing or incomplete, comes from another collector than the image's emitter reports from `microcosm-emitter version`, or expires before the runner's latest stop of the tool plus the emitter's 15 s drain and 30 s margin. The check reports the image emitter's collector origin and fails without one. The receipt's `runner.telemetry` records the token's expiry and origin, never its value; how many events the emitter left undelivered is not recorded yet, because how the runner learns that count without reading the emitter's event queue file waits on a decision. The image emitter's `version` now runs without credentials or the token. The registered tools do not start the emitter yet, so they send no telemetry until they do.
