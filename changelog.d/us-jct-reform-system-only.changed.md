Target compilation's JCT tax-expenditure reform batches now give each batch engine the reform's tax-benefit system alone, without `reform=` as well, as post-export scoring does. Given both, policyengine-us 2.2.1 cloned the reform's system for every batch engine and gave each a `baseline` branch: 11 reforms × 177 batches = 1,947 clones in a release build. Without a `baseline` branch, each reform is refused before its first batch engine if its system moves a labor-supply or capital-gains response parameter off baseline, and a batch engine is refused if it computed a formula that reads the `baseline` branch (`POST_EXPORT_BASELINE_BRANCH_READERS`), at every batch count. On a five-household policyengine-us fixture in three batches, all 11 reforms give byte-identical household income tax to the previous construction. The reform income-tax cache identity is unchanged.
