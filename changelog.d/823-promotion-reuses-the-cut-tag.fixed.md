Promoting a UK release line reuses the immutable cut tag an inspect publication already created: the publisher recognises an existing tag whose `release_manifest.json` is byte-identical to the local release, creates no second immutable revision, and writes only the main commit carrying the line pointer; a tag that describes another release refuses. The documented inspect-then-promote sequence and a retry after a failure between tag creation and the pointer commit both work (review of #966).
