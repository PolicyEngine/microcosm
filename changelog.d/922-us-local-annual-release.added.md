A sixth US release, `microcosm-us-2024-local-annual` (`local_area`, never the default), holds annual projections of an ACS local-area build, the County Files of microcosm#922 (`microcosm.data.contract.US_LOCAL_ANNUAL_RELEASE_ID`; `US_ANNUAL_BASE_RELEASES` maps each annual release to the release it projects). A build's ID is its base local build's ID followed by `-annual-<YYYYMMDDTHHMMSSZ>-<hex8>`. Its folder carries the base build's files unchanged, its base-year H5 under the base's file name (`microcosm_us_2024_acs_local.h5`, or `populace_us_2024_acs_local.h5` for a moved build, `US_LOCAL_ANNUAL_BASE_DATASET_FILES`), one `microcosm_us_<year>_acs_local.h5` per projected year, the candidate manifest, the acceptance report and the per-year receipts, with `default_datasets` empty and `metadata.annual_projection_base` naming the base build of `microcosm-us-2024-local`. The local-area contract checks it: the projected years need not be consecutive, the H5s are read in their fixed-format layout through h5py (stored year, row counts, column order, entity and membership IDs equal to the base's, finite, strictly positive household weights on every row), and the base build's stored-input and SPM measurement gates are held to its base H5 rather than skipped because the build declares several microdata artifacts. Only builds of the two annual releases may declare `metadata.dataset_years`. `microcosm-publish-release-build` hands a local-annual build over only once its base build's published manifest, read from `releases/microcosm-us-2024-local/<base build>/`, declares the same base-year H5 and every carried file, and once every claim the build inherits from the base build's release and build manifests (`annual_projections.inherited_release_claims`, `inherited_build_claims`) equals the published one, so a base folder edited after publication cannot pass its edit on. `tools/assemble_us_annual_release_dir.py` takes a local base build folder too, with `--base-artifact-root` for an H5 outside the folder (where the ACS package stage writes it), and writes the build into `releases/microcosm-us-2024-local-annual/`; the national path is unchanged. Editing `contract.py` moves the producer source identity that SPM and receipt enrichments and recertifications record (`contract.py` is in their producer inventories), so publish any such build made before this change first, or rebuild it.
