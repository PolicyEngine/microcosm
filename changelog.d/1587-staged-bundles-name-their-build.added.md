UK builds now name their build for the collector when they hand their staged dataset bundle to the emitter, and so does the re-stage command (`tools/stage_uk_rowwise_candidate.py`), copied-back Modal runs included. The hand-over carries the interface's `CollectorProvenance`: country `UK`, the build's attempt ID (which a release build keeps as its folder name, whatever run ID the staging used), licensed data, and the manifest's `release_id` when it is the national or dense release (`microcosm-uk-2024-25-national` or `-dense`, otherwise none). The re-stage command reads a dense build's attempt ID from its local gate report, and stages a directory with no staged record under the build it records. Where neither the manifest nor the gate report records the build, it refuses a directory whose Logbook rows name more than one build unless `--build-id` names it; `--build-id` may not contradict a recorded build ID. The emitter submits the bundle's calibration diagnostics to the collector from it once the bundle's commit lands, but only while its collector submissions are on, and no emitter release so far (up to 0.14.0) can switch them on: until one does, the bundle goes to Hugging Face alone. Submissions at release need an emitter release whose release publication carries the same provenance.
