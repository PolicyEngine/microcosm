Source-enrichment certification can declare a publisher model compatibility range instead of the default exact pin: `--compatible-model-specifier 'policyengine-us>=2.0.1,<2.1'` with `--compatibility-claim-declared-by`. The range must name the built-with package, be a specifier that constrains the version, contain the version certification tested, and be bounded above and below: the guard refuses any range still admitting the next major version, a far-future `99999.0.0`, or `0`, so `>=2.0.1`, `>=2.0.1,<3.0.1`, `>=2.0.1,!=3.0.0` and a lower-unbounded `<2.1` are refused while `>=2.0.1,<2.1`, `~=2.0.1` and `>=2.0.1,<3` pass. It is recorded in both the certified report and the release manifest with `basis: publisher_claim` and the declarer, and replayed at publish preflight. Re-certifying a declared bundle without the options reverts it to the exact pin, which warns and records `compatibility.narrowed_claims`; certification, validation and `--preflight-only` print that record beside their verdict, and publication repeats it on stderr, so a later publisher sees it. Core keeps its exact pin and a forged `core` claim is refused. Undeclared certification is unchanged.
