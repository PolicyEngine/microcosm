The PolicyEngine-US adapter's `materialize` now hands `Microsimulation` a dataset that holds the read year alone. Given a single-year dataset, policyengine-us 2.2.1 adds an uprated copy of every later year up to its last CPI-U year (2035), stores all twelve years' inputs, and copies all of them again into each branch it opens (federal itemization and some state taxes). `materialize` reads only the dataset's own year, so the adapter now stops the extension there (`extend_single_year_dataset(..., end_year=period)`). Values do not change: no policyengine-us formula reads a later year's data, and a test compares six variables, `household_net_income` among them, with the engine's default window. On the public populace-us 2024 file (57,240 households), process memory after the engine is built falls from 3.66 to 1.78 GiB; on 15,000 of its households, peak memory while computing `income_tax` falls from 10.47 to 8.74 GiB. Calculation time does not change. The adapter's source feeds the implementation hashes of the US post-transfer seed and materialize kernels, and a node key includes its parents' keys, so the seed and every node after it re-key once.
