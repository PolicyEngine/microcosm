The CI test plan scopes a file below `tools/` to a country only when that country is a whole word of its file name and the other country's letters appear nowhere in the name, so a pull request that changes only a tool named like `status.py` runs both countries' engine jobs. The US engine runner refuses to start unless its tasks run each file the plan lists for `engine-us` exactly once, and `tools/ci_test_plan.py verify` refuses an `engine-us` group that the runner never runs. A test runs the runner as CI does and reads its exit code. `verify` no longer reads the workflow's job names line by line; `verify-workflow`, which parses the workflow with PyYAML, checks the job set alone.
