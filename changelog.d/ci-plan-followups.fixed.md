Below `tools/`, the rules for documentation, test groups and the country runtime packages still run first. The CI test plan now scopes a file there that none of them claims to a country only when its file name holds that country as a whole word and the other country's letters appear nowhere in its lower-cased path. A pull request that changes only a tool such as `status.py`, or a UK tool in a directory such as `us_bundle_generation/`, now runs both countries' engine jobs. The US engine runner refuses to start unless its tasks run each file the plan lists for `engine-us` exactly once, and `tools/ci_test_plan.py verify` refuses an `engine-us` group that the runner never runs. One test runs the runner's module in its own process and reads its exit code. Another runs a copy of `tools/run_engine_us_tests.sh` with a stand-in `uv` and reads the copy's exit status. `verify` no longer reads the workflow's job names line by line. Only `verify-workflow`, which parses the workflow with PyYAML, now checks the job set.
