US spine assembly (`assemble_spines`, used by the stacked ASEC+ACS pool and the retiring two-spine pool) now carries an integer column that one spine lacks as `float64` with `NaN` on that spine's rows. It used to pad such a column with `None`, leaving an object column of integers and `None` that pandas 3 refuses to write to table-format HDF ("mixed-integer"), so a stacked release with ACS rows would have failed at the national release writer on spine-only raw codes: CPS-only household `H_TENURE` (and `HPUBLIC`/`HLORENT` once they land), CPS-only person codes, and ACS-only `TYPEHUGQ` on CPS rows. For NumPy integers this is the union a plain `pd.concat` makes on the ACS local line; pandas nullable integers, signed and unsigned, are cast to `float64` too, since PyTables has no type for them. A value outside +/-2**53, which `float64` cannot hold exactly, is refused rather than rounded, and later writes into a padded column must be numeric. Pools and stage checkpoints written before this change still hold the object columns. The stacked pool's stage-checkpoint materializer version moves from 7 to 8, so its older checkpoints no longer resume; the two-spine line's checkpoint version stays at 4, so rebuild its pools and checkpoints from assembly rather than resuming. Raw codes padded this way are now `float64` on the stacked and ACS local lines and stay `int64` on Route A, so their readers must accept both. Columns every spine carries keep their dtype, and the ASEC-only Route A line never calls assembly, so its raw codes stay integer. Boolean source-only columns stay object booleans plus `None`, the form the multispine source-operator merge expects; the merge turns them into booleans once a CPS producer fills them, and those write in table format (an unfilled one still cannot).
