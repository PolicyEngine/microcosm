`microcosm.build.worker_pool` runs independent units of household-batched work, such as policyengine-us passes over household batches, in spawned worker processes and returns their results in unit order, so callers join them in the order one process would use and get byte-identical outputs. Each worker runs the caller's initializer once, so start-up data such as a frame crosses once per worker; a worker can be replaced after a set number of units; a thread in the parent stops a worker whose memory footprint (resident plus compressed or swapped-out pages) goes over a per-worker cap; a unit whose worker dies, goes over the cap or raises `MemoryError` runs again in a fresh worker, up to a set number of attempts; and optional environment variables are set in each worker as it starts, before it imports anything. The caller sets the worker count and the cap. `test_support/microcosm_build/worker_pool_identity.py` adds a test helper that runs a pooled computation at several worker counts and requires byte-identical results.
