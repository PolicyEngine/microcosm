One queued telemetry run whose delivery keeps failing no longer stops the others in the host's shared spool (`~/.cache/microcosm/telemetry/events.sqlite3`). Every emitter service delivers every pending run, oldest update first. Before, an unexpected error from one run ended the pass on every tick and backed off delivery for all runs, so a stored registration that could not be decoded, or a collector response the client could not parse, stopped every later run from being delivered by any service on the host. Now each run keeps its own retry delay, which doubles from 1 s to 60 s on each failure and clears when the collector accepts a batch, and the pass moves on to the next run. A run that fails on every attempt settles to one attempt a minute per service. The token exchange is shared by every run, so a failed exchange delays further exchanges but charges no run. Each unexpected error type is still one warning line without a traceback, now naming whether one run or the token exchange failed. Spool lock contention still ends the pass for every run and is retried on the next tick.
