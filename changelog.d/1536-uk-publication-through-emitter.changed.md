After the UK repository's switch to `releases.json`, the UK national, dense and local-area releases publish and change their current build only through the emitter (microcosm#1536). The UK national and dense assemblers write build-folder manifests (the build is the calibration attempt ID; `build_id`, `attempt_id` and `cut_tag` are gone, and both assemblers' `--cut-tag` option with them) and print the `microcosm-publish-release-build` publication and promotion commands. The release contract checks those releases in the build-folder layout only and refuses the tagged one. `microcosm-publish-release` and `tools/publish_release.sh` refuse them and lose `--promote-line`, which made a release current through its `latest-<line>.json` pointer file, so they publish only releases that keep tags and `latest.json`, which are every US release until its stable releases are agreed. When the emitter refuses a change with `POINTER_FILES_PRESENT`, or the command's own listing finds a `latest*.json` file in a repository with `releases.json`, the advice is to remove the file that appeared and run the command again, not to publish through `tools/publish_release.sh`; in a repository without `releases.json`, the listing refusal says the switch has not run and to keep the files. `microcosm-publish-release-build` refuses a release that does not publish into build folders, as `microcosm.data.release.build_folder_identity` does, with one message: US releases publish through `tools/publish_release.sh`, and the June 2023 and `populace-uk-<year>-<tier>-k<N>` UK releases take no new builds once the UK repository records its builds in `releases.json`. The tagged publisher's refusal of a repository with `releases.json` says that only releases that publish into build folders publish there, through `microcosm-publish-release-build`, and that any other release takes no new builds there. The `("uk", 2023)` registry entry names release `populace-uk-2023`, into which the UK switch moves the June 2023 build that `latest.json` named, so `microcosm.data.load("uk", 2023)` reads it from `releases.json` after the switch and follows `latest.json` until then. `populace-uk-<year>-<tier>-k<N>` releases have no publication path in the UK repository after its switch.
