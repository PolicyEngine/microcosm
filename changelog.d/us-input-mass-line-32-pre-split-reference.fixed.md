The US input-mass gate now counts `partnership_income` plus `s_corp_income` when its reference has a zero `s_corp_income` total, and the release preflight and dry run read the line the same way. A reference built before #1261 holds partnership and S corporation income together in `partnership_income`, so a build that kept that income still failed the gate once the split left too little of it in that column. A reference with a nonzero `s_corp_income` total gets each column compared alone, a candidate with no `partnership_income` mass stays refused, and the gate's details name both columns whenever it counts them together.
