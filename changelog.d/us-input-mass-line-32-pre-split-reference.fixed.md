The US input-mass gate now counts `partnership_income` plus `s_corp_income` when no reference record holds `s_corp_income`, and the release preflight and dry run read the line the same way. A reference from before #1261 holds partnership and S corporation income together in `partnership_income`, so a build that kept that income still failed the gate once the split left too little of it in that column. Any reference record that holds `s_corp_income` marks the split, even when those amounts cancel, and the gate then compares each column alone. The candidate's column counts alone unless a record with nonzero weight holds `partnership_income`, so S corporation income can't stand in for a lost column. The gate's and the preflight's details name both columns whenever they count them together.
