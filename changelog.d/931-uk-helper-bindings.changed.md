Every UK spine stage now hashes each module its transform computes through, and the dense population nodes each module theirs do (#931). `source_hash` hashes only the files it is given, so a stage that called a function in a module its hash did not name replayed a stale cached output when that module changed.

- **The rule.** `test_uk_graph` derives what each stage's hash must name. It starts at the transform `graph_kernels` builds for the stage, follows every definition the code names (annotations included, through re-exports and module attributes) into the module that defines it, within `microcosm.build`, to a fixed point, and checks that the stage's hash covers every module it meets. Five kinds of definition need no binding and are not followed: a check that returns nothing and writes nothing, a function returning one column name, a record class of undefaulted fields, a constant made only of strings, and the stage's own declaration (`country_spec`, `source_manifest` and the spec engine, whose content the node key already hashes as the stage contract). A numeric constant needs its module bound. The workspace's other packages stay outside the rule: `microcosm.graph` and `microcosm.frame` run every node, and `microcosm.fit`'s fitters are bound by hand. A second test applies the rule to the seven dense population kernels that share `_PopulationKernel`'s hash, where the spine gate admission check is listed as refusal-only, and a control test pins each way of naming a helper that the rule follows and each kind it skips.
- **What is bound.** `national_frame` joins the modules every spine stage hashes. The stage helper table gains 219 bindings of 49 modules in 48 stages, among them `property_localisation`, `cgt_structure`, `spi_support`'s exact-total helpers, `cgt_imputation`, `cgt_asset_type` and `advani_summers` in the CGT and high-value stages, and `employer_pension_contributions` in `frs_hmrc_spine_leaves`. Two groups recur: the vendored-fact reader with the chronicle feed and its schema epochs (20 stages), and `frs_spine`'s pinned tab reader with `trace` (14 stages). Because the new helpers import them, `stochastic_assignment` is bound into 8 more stages and the SPI support channel's exemption goes, the copy-id table is bound into `frs_hmrc_spine_leaves` and `hmrc_spi_income_spine`, 15 stages join the copy-id test's name-only list, and `frs_spine`, `spi_support_channel`, `spi_income_band_donors` and `uc_deduction_attributes` join the counting stages. The dense nodes' shared hash adds `rowwise_geography`, `frame_sampling`, `national_frame`, `local_authority_input` and `gates`.
- **What moves.** Node keys only: no value, declaration or generated file moves. Every spine kernel hashes `graph_kernels.py`, so every spine node re-keys, and with them every node downstream. Every kernel in `graph_population.py`, and the calibration and size kernels that hash it, re-key too. `uk_spine.json` and the H2 fixture hold stage contract hashes, not code hashes, so neither regenerates.
