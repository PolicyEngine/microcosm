Every UK spine stage now hashes each first-party module that its transform computes through, and the seven dense population kernels that share `_PopulationKernel`'s hash do so for `microcosm.build` (#931). `source_hash` hashes only the files it is given, so a stage that called a function in a module its hash did not name replayed a stale cached output when that module changed.

- **The rule.** `test_uk_graph` derives what each stage's hash must name. It starts at the transform `graph_kernels` builds for the stage and follows every definition the code names into the module that defines it, to a fixed point. Annotations count, and so do re-exports and module attributes. It then checks that the stage's hash covers every module it meets. Every definition is a value except for these:
  - four listed refusal-only checks, each with its reason, which a test checks write nothing and return nothing but None or their sole argument;
  - the stage's own declaration (`country_spec`, `source_manifest` and the spec engine), whose content the node key already hashes as the stage contract;
  - the listed core modules every node runs through (see Scope);
  - a single string, a function returning one column name, and a record class whose field types are of these kinds. Their module must be hashed by the stage or by a node upstream of it, whose key the stage's key chains on. Otherwise they are listed with a reason; two such names are listed.

  A collection of strings is a value, like a number, because it selects rows, columns or codes. A second test applies the rule to the seven dense population kernels, still over `microcosm.build` alone, with two listed names. Two more cover the transforms the production spine build installs itself; a transform installed inside the source adapter or the rung sampler must come from its stage's module, since neither hands the node what the wrapped transform declares. Control tests pin each way of naming a helper that the rule follows, each kind it skips, the core-module stop, and each way a refusal-only check could write.
- **Scope.** The rule follows every first-party package: `microcosm-build`, `-calibrate`, `-data`, `-diagnostics`, `-fit`, `-frame` and `-graph`, all under the `microcosm.` namespace. What the stages compute through outside `microcosm.build` is now bound as it is inside it, 71 bindings in 47 stages:
  - `microcosm.fit.qrf` and `fit.model` in 11 stages: the nine that fit through the regime-gated QRF, and `spi_employment_shell` and `aps_occupation`, whose classifier resolves its fit weights through `fit.model` and whose held-out scores and folds use the QRF's;
  - `microcosm.frame.materialize`, whose `engine_tables` copies a frame's tables, in the three stages of `spi_spine` and the band donors;
  - `microcosm.frame.rules` in `uc_take_up` and `pension_credit_take_up`, which type their engine by the adapter's `ProjectingRulesEngine`, a protocol that extends its `RulesEngine`;
  - the engine adapter in every spine stage, beside `national_frame`, which stamps each frame it builds with the adapter's ISA income contract and savings income projection; 38 stages that call no engine gain it;
  - `microcosm.graph.randomness` and its canonical encoder `microcosm.graph.canonical` in `regional_home_values`, which draws its keyed uniforms through them;
  - `microcosm.calibrate.geography_constants`, the UK region tier, in `hmrc_cgt_gains_spine`, `isa_subscriptions` and `spi_housing_shell`.

  Listed instead, each with a reason a test checks:
  - the core modules every node runs through, where the rule stops, since binding one would re-key every node on any edit to it. They are the Frame's three modules (`microcosm.frame.bundle`, `schema` and `weights`), which a stage's transform meets all three or none of; the graph executor's (`microcosm.graph.executor` and `population`); and the modules that compute node keys (`keys`, `decl` and `kernel`), which no stage's transform meets. No spine key hashes them. An edit to the Frame that changes values is left to its own tests and to H1, whose fixtures run it through `run_graph` against stored bytes. One to the executor's modules that changes a value on H2's fixture fails H2, which compares the graph's spine with the legacy stage plan's. One that changes what `node_key` or `source_hash` returns changes every key. A test checks that the walk from `run_graph` meets each of them. `microcosm.graph.canonical` also encodes every key, but `regional_home_values` draws through it, so it is bound there instead;
  - `microcosm.frame.rules`' `assert_rules_engine_country`, the fourth refusal-only check, which every stage that takes an engine calls first;
  - `SOURCE_HOUSEHOLD_ID_COLUMN` from `microcosm.frame.concepts`, CopyLineage's default source column, the second listed name. The support channel writes the column by its literal name. Every stage that reads the constant declares the column by that name, which its key hashes, and counts before the copies only beside a copy column, or declares neither, so a renamed constant leaves the lineage readers to refuse or count as before.

  Still outside the rule: calls through an object whose class the code never names. The engine the engine stages call is one: the hand-bound engine modules cover the adapter, the engine-block machinery and the UK declaration, but not the adapter's own imports (`policyengine_uk_concepts`, `concept_mapping`, `concepts`, `materialize` and `rules`).
- **What is bound.** `national_frame` joins the modules every spine stage hashes. The stage helper table gains 231 bindings of 54 modules in 49 stages. Among them:
  - in the CGT and high-value stages: `property_localisation`, `cgt_structure`, `spi_support`'s exact-total helpers, `cgt_imputation`, `cgt_asset_type` and `advani_summers`;
  - `employer_pension_contributions` in `frs_hmrc_spine_leaves` and `hmrc_spi_income_spine`;

  Two groups recur: the vendored-fact reader with the chronicle feed and its schema epochs (20 stages), and `frs_spine`'s pinned tab reader with `trace` (14 stages). The older import tests then ask for more, because the new helpers import these modules:

  - the copy-id table is bound into `frs_hmrc_spine_leaves` and `hmrc_spi_income_spine`, and 15 stages join the copy-id test's name-only list;
  - `frs_spine`, `spi_support_channel`, `spi_income_band_donors`, `uc_deduction_attributes` and `etb_services` join the counting stages.

  The dense nodes' shared hash adds `rowwise_geography`, `frame_sampling`, `national_frame`, `local_authority_input`, `gates` and `spi_support`, whose replacement strata the sample reads.
- **The sampled spine root.** The spine build wraps the root's transform in a rung sampler, which samples the root below f100. That sampler lived in `spine_build`, which no node hashes, and sampled through `frame_sampling`. It now lives in `national_sampling` as `UKSampledSpineRootTransform`, with `sample_uk_spine_root`. Through `graph_implementation_dependencies`, which the root node hashes, it declares `national_sampling` at every rung, since it resets the root's indexes at f100 too, and `frame_sampling` only below f100, where it samples. Its behaviour is unchanged.
- **Other dense kernels.** The rule is not yet applied to the UK's other graph kernels. Run over them, it finds unhashed modules in the identity node (`household_lineage`, `source_lineage`), the property value and band nodes (`tenure_constants`, `source_lineage`), the private rent node (`source_lineage`, `receipt_counts`, `national_frame`) and the BRMA and RFDR nodes (`receipt_counts`). The calibration and size kernels miss `national_frame`, and the size search and refit also miss the doctrine, local target and target weight modules. The rule finds more in the gate, target, national and export kernels. Binding them is left open.
- **What moves.** Node keys only: no value, declaration or generated file moves. Every spine kernel hashes `graph_kernels.py`, so every spine node re-keys, and with them every node downstream. The root node also hashes the rung sampler's module at every rung, and the shared core below f100. Every kernel in `graph_population.py`, and the calibration and size kernels that hash it, re-key too. `uk_spine.json` and the H2 fixture hold stage contract hashes, not code hashes, so neither regenerates.
