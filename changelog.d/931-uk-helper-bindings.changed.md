Every UK spine stage now hashes each module in `microcosm.build` that its transform computes through, and so do the seven dense population kernels that share `_PopulationKernel`'s hash (#931). `source_hash` hashes only the files it is given, so a stage that called a function in a module its hash did not name replayed a stale cached output when that module changed.

- **The rule.** `test_uk_graph` derives what each stage's hash must name. It starts at the transform `graph_kernels` builds for the stage and follows every definition the code names into the module that defines it, to a fixed point. Annotations count, and so do re-exports and module attributes. It then checks that the stage's hash covers every module it meets. Every definition is a value except for these:
  - three listed refusal-only checks, each with its reason, which a test checks write nothing and return nothing but None or their sole argument;
  - the stage's own declaration (`country_spec`, `source_manifest` and the spec engine), whose content the node key already hashes as the stage contract;
  - a single string, a function returning one column name, and a record class whose field types are of these kinds. Their module must be hashed by the stage or by a node upstream of it, whose key the stage's key chains on. Otherwise they are listed with a reason; one such name is listed.

  A collection of strings is a value, like a number, because it selects rows, columns or codes. A second test applies the rule to the seven dense population kernels, with two listed names. Two more cover the transforms the production spine build installs itself. Control tests pin each way of naming a helper that the rule follows, each kind it skips, and each way a refusal-only check could write.
- **Scope.** The rule follows `microcosm.build` only. `microcosm.graph` and `microcosm.frame` run every node, so binding them by rule would re-key every node on any edit to them. Only some value-computing modules outside `microcosm.build` are bound, by hand: `microcosm.fit`'s categorical, donor and held-out fitters in `spi_employment_shell` and `aps_occupation`, and the engine adapter in the stages that call the engine. These are still unbound:
  - `microcosm.fit.qrf` and `fit.model`, which 11 stages fit through, those two among them;
  - `microcosm.frame.rules` and `frame.materialize`;
  - the engine adapter's helpers, in stages that call no engine;
  - `microcosm.graph.randomness`, which `regional_home_values` draws through;
  - `microcosm.calibrate.geography_constants`.
- **What is bound.** `national_frame` joins the modules every spine stage hashes. The stage helper table gains 231 bindings of 54 modules in 49 stages. Among them:
  - in the CGT and high-value stages: `property_localisation`, `cgt_structure`, `spi_support`'s exact-total helpers, `cgt_imputation`, `cgt_asset_type` and `advani_summers`;
  - `employer_pension_contributions` in `frs_hmrc_spine_leaves` and `hmrc_spi_income_spine`;
  - the tables the narrower rule finds: `tenure_constants` in `was_wealth`, `was_lisa`, `high_value_home_support` and `regional_home_values`; `council_tax_constants` in `frs_spine`; `rowwise_geography` in `lcfs_consumption`; `etb_vat` in `etb_services`; `cgt_imputation` in `cgt_incidence_clone`; `frs_annual_income` and `hmrc_source_contract` in `hmrc_spi_income_spine`;
  - `household_income` in `was_wealth` and `was_lisa`, for its predictor names.

  Two groups recur: the vendored-fact reader with the chronicle feed and its schema epochs (20 stages), and `frs_spine`'s pinned tab reader with `trace` (14 stages). The older import tests then ask for more, because the new helpers import these modules:
  - `stochastic_assignment` is bound into 8 more stages, and the SPI support channel's exemption goes;
  - the copy-id table is bound into `frs_hmrc_spine_leaves` and `hmrc_spi_income_spine`, and 15 stages join the copy-id test's name-only list;
  - `frs_spine`, `spi_support_channel`, `spi_income_band_donors`, `uc_deduction_attributes` and `etb_services` join the counting stages.

  The dense nodes' shared hash adds `rowwise_geography`, `frame_sampling`, `national_frame`, `local_authority_input`, `gates` and `spi_support`, whose replacement strata the sample reads.
- **The sampled spine root.** The spine build wraps the root's transform in a rung sampler, which samples the root below f100. That sampler lived in `spine_build`, which no node hashes, and sampled through `frame_sampling`. It now lives in `national_sampling` as `UKSampledSpineRootTransform`, with `sample_uk_spine_root`. It declares both modules through `graph_implementation_dependencies`, which the root node hashes. Its behaviour is unchanged.
- **Other dense kernels.** The rule is not yet applied to the UK's other graph kernels. Run over them, it finds unhashed modules in the identity node (`household_lineage`, `source_lineage`), the property value and band nodes (`tenure_constants`, `source_lineage`), the private rent node (`source_lineage`, `receipt_counts`, `national_frame`) and the BRMA and RFDR nodes (`receipt_counts`). The calibration and size kernels miss `national_frame`, and the size search and refit also miss the doctrine, local target and target weight modules. The rule finds more in the gate, target, national and export kernels. Binding them is left open.
- **What moves.** Node keys only: no value, declaration or generated file moves. Every spine kernel hashes `graph_kernels.py`, so every spine node re-keys, and with them every node downstream. The root node also hashes the rung sampler at every rung. Every kernel in `graph_population.py`, and the calibration and size kernels that hash it, re-key too. `uk_spine.json` and the H2 fixture hold stage contract hashes, not code hashes, so neither regenerates.
