Add `tools/draft_uk_dense_signoff.py`, which drafts the gate-only sign-off between the two dense UK builds (microcosm#1301). From build 1's run directory it reads the full gate report, the signed local gate report, the target and area-support tables and the Logbook row, checks them against one another and against the checkout's `gates.json`, and drafts `release_lines: ["local"]` entries for every failing national target-fit row, local target-fit cell and area below the support floor. It also drafts the removal of every entry build 2 would fail and the test pins those registers move, as a `git apply` patch with a PR body of counts, gate ids and policy dates. A national target-fit entry that applies on every line is never removed or replaced, since the national line may still stand on it: when build 2 would fail it on the local line it is rescoped to `release_lines: ["national"]`, otherwise unchanged. An expired one also goes to review for the national line to renew or retire, and the draft is unsignable until then if keeping it breaks the national graph test's review invariant; a row build 1 still breaches under such an entry needs a hand sign-off, since a register key holds one entry. Any other release-blocking failure makes the build unsignable, and so does an area exclusion the local reference generator's own deferrals keep, when build 2 would fail it. The receipt and the PR body give the assembly deadline: the earliest expiry among the measure exclusions build 1's solve ran under (from its candidate manifest, or from the target compilation's surface when its gates stopped it before the export), the local line's degenerate-register entries and the gate-only entries the local line stands on after the sign-off. Build 2's gate-clock range ends there, and a gate clock past the solve-scoped expiries is refused, since renewing one changes the solve. Reasons are templated from the key, the gate's bound or the floors the area missed, the build-1 attempt id and the full gate report's sha256. `--approved-by` must be a GitHub login, the reviewer's `--class-note`, `--area-name` and `--adjudication` text may carry digits only in issue references and ISO dates, and no `%`, and the drafted entries then pass the release contract's disclosure walk, which on text refuses only an area's support worded with its measured value; none of these checks reads a figure written in words. Per-row errors, per-area support figures and the local registers' stale-risk and near-bound counts go only to a private review file (the local counts also to the tool's standard output); the PR body and the receipt carry the national register's counts alone. `--out` must lie outside every git work tree, `.gitignore` covers `PRIVATE_review.csv` and `signoff-draft/`, and the support table's maximum weight is never read. `--verify` checks that build 2 stood on exactly the committed entries, that no release-blocking gate failed and that its signed local report passes the dense contract and its disclosure walk; it fails once the assembly deadline has passed, warns from two days before it, and reports whether build 2 reused build 1's solve. The three fixed-clock target-fit tests in `test_uk_terminal_gates.py` now read the register as the national line does, so local-line sign-offs approved after their clock leave them unchanged.
