Add `tools/draft_uk_dense_signoff.py`, which drafts the gate-only sign-off between the two dense UK builds (microcosm#1301). From build 1's run directory it reads the full gate report, the signed local gate report, the target and area-support tables and the Logbook row, checks them against one another and against the checkout's `gates.json`, and drafts `release_lines: ["local"]` entries for every failing national target-fit row, local target-fit cell and area below the support floor. It also drafts the removal of every entry build 2 would fail and the test pins those registers move, as a `git apply` patch with a counts-only PR body. Any other release-blocking failure makes the build unsignable, and so does an area exclusion the local reference generator's own deferrals keep, when build 2 would fail it. Reasons cite the build-1 attempt id and the full gate report's sha256, carry no figures and pass the release contract's disclosure walk; per-row errors and per-area support figures go only to a private review file outside the repository, and the support table's maximum weight is never read. `--verify` checks that build 2 stood on exactly the committed entries, that no release-blocking gate failed and that its signed local report passes the dense contract and its disclosure walk, and reports whether it reused build 1's solve. The three fixed-clock target-fit tests in `test_uk_terminal_gates.py` now read the register as the national line does, so local-line sign-offs approved after their clock leave them unchanged.
