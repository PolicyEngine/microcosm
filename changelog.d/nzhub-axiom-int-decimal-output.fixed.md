Accept an integer array for a declared-decimal output of a graph-typed Axiom adapter. The engine's per-period dense surface returns int64 for a rule declared decimal when the rule's value stays integer-typed inside the engine, for example an `if` tree whose branches read parameters written as whole numbers, and `_graph_output` refused every such array. New Zealand's 13 Accommodation Supplement rules nodes failed this way on `accommodation_supplement_maximum_weekly_rate`. A signed or unsigned integer array for a decimal now becomes float64 when every value lies from `-2**53` to `2**53`, where float64 holds each integer exactly. The cast still refuses bool and any value outside that range, and the view scatter path applies the same rule. The adapter module's source changes, so the nodes of every kernel in the transport registry that hashes it re-key, with their descendants: `simulate.rules@1`, `simulate.rules_by_ref@1`, `simulate.counterfactual@1` and `simulate.solve_zero@1` when bound to an `AxiomEngine`, and `export.prepare@1`, `export.readback@1` and `transport.input_closure@1`.
