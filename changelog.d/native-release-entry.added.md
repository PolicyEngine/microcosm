Add `build_native_survey_release`, the in-process native US release entry. It authenticates a live issued enrichment owner before anything else, refuses every option it does not consume, compares the consumer with an expected identity (including re-hashed installed files, authenticated file and namespace origins of loaded consumer modules, and effective SPM settings), projects the declared cells and runs a pure input gate. Only then does it materialize targets with the admitted constructors, run the shared dense/L0 solve, attach weights to the projected inputs, evaluate the fit gates and write one verified logical H5. `native-releases` and the release directory are created and opened relative to held directory descriptors, and the manifest is published through them. `<out>` and any missing parents are created and opened by path and then checked for their canonical location, and the final reopen detects ancestor swaps but does not prevent them; diagnostics and H5 writes use ordinary paths, so the output tree requires exclusive ownership. The manifest is written once into the directory whose inode was retained after creation. Failed directory setup retains paths for inspection, and temporary-file cleanup is best-effort. Its manifest is never release-eligible and lists outstanding qualifications. Wrong-parent H5 export tests refuse before the writer.
