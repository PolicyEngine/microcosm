The Route A driver (`tools/route_a/route_a.sh`) gains a `LOCATION_RULE` setting for the base's household location. `legacy`, the default, keeps the published run's command: a congressional district drawn from SOI return counts, then a block within it. `block_v1` (microcosm#1047) draws one 2020 census block per household within its CPS ASEC source geography: the base drops `--ledger-facts`, `--assign-congressional-districts` and `--congressional-district-seed`, and passes `--location-rule block_v1 --location-seed 0`. Under `block_v1`, `check_commit` also requires the base tool at the build commit to declare those two flags. The driver refuses any other value. Tests check that the `block_v1` command differs from the legacy one only in those flags, and that the base tool's own parser accepts it. `block_v1` is for a base that the driver builds itself. The Modal base registration keeps the legacy location flags, so the Route A README and the Modal runbook say not to hand a Modal base to a `block_v1` run.
