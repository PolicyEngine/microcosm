The declared target sets are now a typed resource of the spec engine (microcosm#1728 and microcosm#1759, from the review of microcosm#1755). The spec engine has a new resource kind, `target_sets`, with the schema `target_sets.schema.json`, the sixteenth schema of its catalog. `us/target_sets.json` and `uk/target_sets.json` become `us/spec/target_sets.yaml` and `uk/spec/target_sets.yaml`. The schema marks each `description` and `rationale` as documentation and every other field as normative, so the spec engine keeps the prose apart from the content a selection reads, and the bundle's `spec_sha256` now covers that content: a changed clause changes the spec hash, and a reworded rationale does not. The products and the modes are lists with an `id`, so their declared order is content; the order of the fields of an object is not. `microcosm.calibrate.target_sets.load_target_set_declarations` takes the object the spec engine parsed, and the file reader it had is removed; the country modules read through the new `country_spec.load_country_target_sets`, which loads the one resource as the bundle loader does. The US file is written by hand (`AUTHORED_DOMAIN_KINDS` of `tools/generate_us_bundle_from_constants.py`), with a reviewed claim in the F0 field ledger; the US pins move to 42,557 configuration fields and a new `spec_sha256`. No target, order or receipt changes: the pinned US surfaces and the UK equivalence tests hold.
