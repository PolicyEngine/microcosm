`tools/modal_uk_cut.py`'s image installs the separately installed `microcosm-emitter` (microcosm#1757), so a UK build run on Modal no longer stops at `run_uk_cut.py`'s preflight, which starts the emitter to check write access (#1460). As in the US Modal image, the install step asks for `microcosm-emitter>=` the release `packages/microcosm-build/src/microcosm/build/minimum_emitter_version.json` names in the launching checkout, installs it into `/usr/local/bin` outside the environment the container syncs, and runs its `version` so a command that cannot run fails the image build; `MICROCOSM_EMITTER_COMMAND` points the build at it. Before it downloads anything, the image now also drops the compromised eMudhra (emSign) certificate authorities as the US image does (`emudhra-ca-trust`): it upgrades `ca-certificates`, replaces the base's pip 25.3 with the hash-pinned pip 26.2.2, and installs uv 0.13.4 instead of 0.11.7; it also sets `UV_PYTHON_DOWNLOADS=never`. The launcher refuses a minimum file it cannot read, its plan names the emitter requirement, and the plan refuses a commit whose `minimum_emitter_version.json` names a higher release than the launching checkout's, which the build's preflight would otherwise refuse in the paid container. The emitter's event queue files stay in the container's cache directory, as in the US runner, so hand-overs still queued when the container exits are lost with it. The launcher has still never run on Modal.
