A build that must send telemetry can say so with `MICROCOSM_TELEMETRY_REQUIRED=1` (microcosm#1464). Starting its emitter then raises `TelemetryRequiredError` (`microcosm.build.telemetry_emitter`), so the build exits nonzero before doing any work, when the emitter cannot be prepared, the `microcosm-emitter` command is missing or older than `MINIMUM_EMITTER_VERSION`, it does not accept protocol version 1, it exits or times out before it is ready, or it starts without its telemetry module. The error names a fixed reason and the remedy, never a setting's or credential's value, and the adapter prints no warning that the build continues. Emitter 0.11.0 and later exit before they are ready when the collector-token variables they inherit (`MICROCOSM_COLLECTOR_TOKEN`, `MICROCOSM_COLLECTOR_TOKEN_EXPIRES_AT`, `MICROCOSM_COLLECTOR_ORIGIN`) are not all set, cannot be read, or name another collector, so such a build stops then too; whether the collector later accepts the credential is not visible to the build. Unset or `0`, builds continue without the emitter as before, and any other value raises `ValueError`. The short-lived Orrery-only emitters are unaffected. Nothing in Microcosm sets the variable yet.
