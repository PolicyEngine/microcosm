US post-export scoring can run in the shared worker pool (`_PooledPostExportScorer`): the merged baseline pass is split into one range of household batches per worker, each reformed simulation's recorded passes are one unit, and each post-export stage then runs in the certifying process over the results, refusing any request its engine-free dry run did not record. Every output file and both manifests' consumer records are byte-identical to the serial scorer's; the manifests' `post_export_scoring` block records how scoring ran under `execution`, as run metadata. `POST_EXPORT_SCORING_METHOD` is raised once, to `household_batched_written_h5_v2`, for the merged baseline sweeps and pooled scoring (decision 1.1 · 1), so a build recorded with the earlier label is certified with the code it was built with. A changed batch file stops pooled scoring's merged baseline pass instead of falling back to per-stage passes, the held-out reports stop certification when the pool fails, and `tools/probe_us_post_export.py` registers every stage's baseline plan (one shared baseline pass, as certification runs), can score in the pool and writes each worker pass's time and memory to `passes.jsonl`; its household row map reads one batch file at a time.
