US certification scores post-export stages in the shared worker pool by default (`_PooledPostExportScorer`), with tracker decision 1.4 · 6's settings: `MICROCOSM_POST_EXPORT_WORKERS` unset or `auto` starts at most min(usable cores − 1, ⌊(0.75 × memory − 3 GiB) ÷ 5 GiB⌋) workers and refuses, before the build is placed, a machine with no room for one; a positive number starts that many, and `serial` scores in the certifying process as before; each worker is replaced after 2 units and capped at max(5 GiB, (0.75 × memory − 3 GiB) ÷ workers). In the pool, the merged baseline pass is split into one range of household batches per worker, each reformed simulation's recorded passes are one unit, and each post-export stage then runs in the certifying process over the results, refusing any request, or any reform, its engine-free dry run did not record; the smoke check's and reform validation's builders mark each reform with the description it was built from. A merged baseline unit the pool cannot finish falls back to each stage's own pass, as a serial `MemoryError` does; any other unit that fails on every attempt fails the stage that asks for it, and the pool goes on with the rest in fresh workers; a worker refuses a release tool whose bytes differ from the certifying process's. Every output file and both manifests' consumer records are byte-identical to the serial scorer's; the manifests' `post_export_scoring` block records how scoring ran under `execution`, as run metadata. `POST_EXPORT_SCORING_METHOD` is raised once, to `household_batched_written_h5_v2`, for the merged baseline sweeps and pooled scoring (decision 1.1 · 1), so a build recorded with the earlier label is certified with the code it was built with. A changed batch file stops pooled scoring's merged baseline pass instead of falling back to per-stage passes, the held-out reports stop certification when the pool fails, and `tools/probe_us_post_export.py` registers every stage's baseline plan and the held-out reports' (certification's shared baseline pass), can score in the pool and writes each worker pass's time and memory to `passes.jsonl`; its household row map reads one batch file at a time.
