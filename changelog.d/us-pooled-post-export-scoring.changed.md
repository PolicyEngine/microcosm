US certification scores post-export stages in the shared worker pool by default (`_PooledPostExportScorer`), with tracker decision 1.4 · 6's settings: `MICROCOSM_POST_EXPORT_WORKERS` unset or `auto` starts at most min(usable cores − 1, ⌊(0.75 × memory − 3 GiB) ÷ 5 GiB⌋) workers and refuses, before the build is placed, a machine with no room for one; a positive number starts that many, and `serial` scores in the certifying process as before; each worker is replaced after 2 units and capped at max(5 GiB, (0.75 × memory − 3 GiB) ÷ workers). Every baseline pass runs in the certifying process with the serial scorer's code, when the first stage opens and before any worker starts: the merged pass, and, if it raises, every stage's own pass, each stage then served its values or its error (Anthony's decision of 27 November, after the 5% export probe showed one 2,000-household batch's baseline pass going over the 5.25 GiB worker cap). The pool then runs one unit per reformed simulation, holding its recorded passes, and each post-export stage runs in the certifying process over the results, refusing any request, or any reform, its engine-free dry run did not record; the smoke check's and reform validation's builders mark each reform with the description it was built from. A unit that fails on every attempt fails the stage that asks for it, and the pool goes on with the rest in fresh workers; a worker refuses a release tool whose bytes differ from the certifying process's. Every output file and both manifests' consumer records are byte-identical to the serial scorer's; the manifests' `post_export_scoring` block records how scoring ran under `execution`, as run metadata. `POST_EXPORT_SCORING_METHOD` is raised once, to `household_batched_written_h5_v2`, for the merged baseline sweeps and pooled scoring (decision 1.1 · 1), so a build recorded with the earlier label is certified with the code it was built with. A changed batch file stops pooled scoring's baseline passes instead of falling back to per-stage passes, the held-out reports stop certification when the pool fails, and `tools/probe_us_post_export.py` registers every stage's baseline plan and the held-out reports' (certification's shared baseline pass), taking the held-out reports from the release tool's `_post_export_holdout_consumers`, can score in the pool and writes each pass's time and memory to `passes.jsonl`, naming the process that ran it; its household row map reads one batch file at a time.
