A one-time tool, `python -m microcosm.build.build_folder_switch`, moves a dataset repository from tags and `latest*.json` pointer files to build folders and `releases.json` (microcosm#1533). Its `copy` step adds each tagged build's folder, `releases/<release>/<build>/`, in one commit per build: it rewrites the build's two manifests in the build-folder layout, recording the tag, its commit and the original manifest's SHA-256 under `migrated_from`, rewrites its checksum ledger to match, and copies every other file the manifest declares from the tagged commit with Hugging Face's server-side copy after checking its SHA-256. A field that a tagged release manifest has both in its `build` object and at its top level, such as the June 2023 UK release's `metadata`, becomes one object when the two do not disagree. Each tag is resolved to the commit it names, since the Hub lists an annotated tag with its tag object's ID. Its `switch` step then, in one commit, writes `releases.json` and deletes every pointer file: each build keeps its tagged commit's date as `published_at`, each pointer file's build becomes its release's `current`, and `default` is the release of `latest-national.json`'s build, or else of `latest.json`'s. It refuses unless each build's folder holds exactly its copied files with the SHA-256 values its tag recorded, every pointer file's build moves or `--retire-pointer` deletes that file, and the emitter interface's checks on the record, the folders and the commit pass. Both steps only read and report without `--write`, refuse to run with `HF_HUB_OFFLINE` set, and name the head they checked as each commit's parent.
