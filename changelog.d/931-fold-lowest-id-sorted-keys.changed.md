The UK fits now train each variant of a survey record on its lowest-id clone instead of its first row, through a shared fold that takes the order from its caller and reports what the clone receipts will need; `integer_record_keys` finds repeated ids by sorting (#931; the sort as María ruled on 10 Nov). No output moves: every spine is one clone today, so every fit keeps its rows and weights value for value, and every id check on integer ids gives the verdict it gave.

- **`fold_replicas`** (`microcosm.build.source_lineage`) returns a `ReplicaFold` with one value per record in each field:
  - `kept`: the rows the fit trains on;
  - `weights`: on each kept row, its variant's selected weights summed exactly (`math.fsum`); every other weight unchanged;
  - `representative`: the row each selected record's variant trains on, -1 off the selection;
  - `varied`: whether a selected record's key holds more than one variant;
  - `key_group`: a code of each selected record's replica key, -1 off the selection.

  A variant's representative is its selected record with the least `order`, ties going to the earlier row. `order` is one numpy integer per record, and a malformed one, a timedelta included, is refused with counts only. Without `order` the representative is the variant's first selected record in row order, as before. A selected record with a null key, which `replica_keys` never gives, is now refused rather than folded with other records.
- **Early returns decided on the key.** When no two selected records share a key, the selection and weights come back value for value and nothing varies. When keys repeat but no two selected records share a variant, the selection and weights still come back value for value, and the records of every key with more than one variant vary. Deciding on the key and the inputs together would report no variety exactly when every clone differs.
- **`collapse_replicas`** is a wrapper that returns `fold_replicas`'s kept rows and weights. It takes the same keywords as `fold_replicas`, `order` included. Without `order` a variant keeps its first selected row, as before, so every caller and fixture keeps its values.
- **The UK entry.** `household_lineage.collapse_geographic_clones` keeps its signature and return, and orders the fold by the entity's id column. The new `fold_geographic_clones` returns the whole `ReplicaFold`. A key's clones differ in id only by their clone's offset, so each variant trains on its lowest clone among the selected rows: clone 0 whenever clone 0 is selected and agrees with it, whatever the row order. Before, it trained on whichever of its clones came first.
- **`integer_record_keys`** (`microcosm.build.stochastic_assignment`) compares neighbours in a sorted copy of the ids instead of building `np.unique`'s array. On integer ids its verdicts, errors and return are unchanged. Timedelta ids, which numpy types as integers and the check used to accept, are now refused as ids that are not integers.
- **What moves.** No output, at one clone or on any spine. On frames whose clones are out of clone order, which only tests build today, a variant now trains on its lowest-id record. Node keys move:
  - every UK spine node, since the spine's root binds `stochastic_assignment`, `source_lineage` and `household_lineage` and keys chain; with them the spine gate phases (the transferred phase's own code also hashes `stochastic_assignment`) and, in the in-graph build, every node after the spine;
  - on a bound spine, whose root hashes none of the three, the full build's `uk.full.identity`, `uk.full.property.value` and `uk.full.private_rent`, which hash `source_lineage` and `household_lineage`, and every node keyed on them;
  - the national line's gates, whose registry modules include `stochastic_assignment`.

  The spine checkpoint's gate digests do not move. The derived binding tables are unchanged, since the new names live in modules already bound wherever they are reached. No generated file or `gates.json` changes: `uk_spine.json` and the H2 fixture hold stage contract hashes, not code hashes. No transport kernel and no US, NZ or BE node hashes an edited module, so their node keys stay; only the US PUF-support builder's whole-tree resume fingerprint moves, as it does on any edit to packaged source.
- **Tests.** The fold is checked against a record-by-record statement of its contract on random frames; under every row order of a three-clone frame; per variant; on a frame without replicas; and on a two-clone frame whose clones all differ, which folds nothing and varies everywhere. Without `order` it keeps the earlier tests' rows and weights. The UK entry keeps clone 0 when every table lists its clones in reverse, and the id check gives `np.unique`'s verdict on random integer arrays of several dtypes and refuses timedeltas. The test that holds every folding stage to a live lineage now finds a stage through either UK entry.
