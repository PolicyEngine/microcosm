The US base stage checks the policyengine-us lock file (`engine_abi.lock.json`) once in the `--stage all` process instead of in every step process and QRF worker. The parent hands each step process a record of its check (lock file SHA-256, installed policyengine-us version and take-up and sources domain digest, in `MICROCOSM_ENGINE_ABI_LOCK_CHECK_RECORD`), and each step process hands the QRF workers it starts the record of its own check. A child with its parent's record compares those three values instead of building two tax-benefit systems, and refuses to run when any differs. Processes without a record from their parent still run the full check. `microcosm.calibrate.solve` now imports torch inside the functions that use it, so importing `microcosm.calibrate` no longer imports torch. Together these cut a step process start from about 38 s and 1.5 GB peak resident memory to about 6 s and 0.3 GB, and a QRF worker start from about 37 s and 1.75 GB to about 8 s and 0.3 GB, on a 10-core Mac. The QRF worker identity digest changes once: its import trace no longer opens `gate_shadow.py`, `multispine_pool.py` or `us_late_overlap_ownership.py`, and imports fewer standard-library and third-party modules. The seed-protocol and seed-map digests and the US `spec_sha256` pins move because `solve.py` and `puf_qrf_chain.py` are attested kernel sources; no draw or data output changes.
