Three release-blocking gates that failed on the first K=25 local candidate for reasons of policy, not fit, now have reviewed answers (microcosm#1124; María's rulings of 2026-10-13).

- **Line-scoped exclusions.** A reviewed exclusion may name `release_lines` (`national`, `local`), the lines whose evidence earned it. A gate context declares its line (`release_line`): the full build declares `local`, and the national gate kernel and the release-cut certifier declare `national`. On any other line, and wherever a context declares no line, a scoped entry stands aside: it neither suppresses a failure nor reads as stale, and the gate details name it. Unscoped entries behave as before everywhere, and unscoped receipts keep their policy payload. The four schema-2 exclusion gates (degenerate surface, target fit, input-mass parity, QRF tail) honour it.
- **`uk_qrf_tail_concentration`.** The `charitable_investment_gifts` exclusion is scoped to the national line, where it was earned. On the K-clone local pool the gate counts clone rows, so the column sits below the threshold and the entry read as stale.
- **`uk_degenerate_release_surface`.** `household.atomic_area_basis` is constant at `assigned` by construction on the local line; it gets a local-line exclusion and stays in the export as assignment provenance (microcosm#932).
- **One engine block per clone.** The local release pre-flight accepts an engine resolved per clone when the build recorded the pool representation exact (identical copies scaled to the pool), as `release_verdict` and the runbook already did. The record now states what exact covers (`exact_scope`): the weight-share scaling, not engine draws that depend on a record's position, which can differ between per-clone and single-block runs. The incumbent-surface evaluation still requires one block, re-measures the released file on it and fails release on any row more than 25% from its target, so the shipped file's fit is gated on the engine a consumer runs.
- The dense runbook passes the national line's licensed `--input-mass-reference`.
