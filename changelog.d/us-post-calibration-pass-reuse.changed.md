The US fiscal-refresh release tool no longer reruns policyengine-us over every household for the post-calibration December SSI candidate amounts and Medicaid eligibility. Each pre-calibration pass keeps its per-person values and a digest of each household's rows: IDs, membership, row order, and every column the engine can read for `uncapped_ssi` or `is_medicaid_eligible`. That is the engine's static dependency graph, plus the variables named in strings in a listed formula's source (branch simulations, `get_holder` reads and `all_of_variables` lists) and the state flags that programs are `defined_for`. After calibration, households whose digest is unchanged take their earlier values, matched by person ID. The tool runs policyengine-us on the households whose inputs changed, one batch at a time, and on one batch of unchanged households spread over the frame as a check; if that check disagrees, it runs every household again. The counts are printed and sent with the build's telemetry. Neither variable reads weights or a population-wide sum, so calibrated weights and L0's dropped households change no remaining value. No column written between the two SSI passes is an SSI input. Between the Medicaid passes, SNAP take-up and the other-health-insurance premium attribution change some households' inputs, and those households are rerun. The new country-neutral helper is `microcosm.build.household_pass_reuse`; `microcosm.build.us_runtime.household_pass_inputs` lists a policyengine-us pass's input columns.
