`tools/check_us_acs_county_agi_support.py` lists, before the ACS local release (R2) runs, the counties whose county IRS SOI AGI row R2 would build empty: counties with households but none that can carry a nonzero AGI (microcosm#922; microcosm#1630 review, finding 1). The state AGI row stores no zero, so such a county makes `attach_surface` refuse the run after the materialize engine pass. The check reads the staging H5's household table and only the AGI income columns, which it takes from policyengine-us's `irs_gross_income` inputs without importing the engine (Social Security and deductions are left out, so it errs towards listing a county). With `--puma-ladder` it applies R2's own minimum-support moves first. It exits 2 when a county is at risk.
