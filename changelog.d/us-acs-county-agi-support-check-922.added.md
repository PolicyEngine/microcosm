`tools/check_us_acs_county_agi_support.py` lists, before the ACS local release (R2) runs, the counties whose county IRS SOI AGI row R2 would build empty: counties with households but none with a nonzero AGI (microcosm#922; microcosm#1630 review, finding 1). The state AGI row stores no zero, so such a county makes `attach_surface` refuse the run after the materialize engine pass. The check computes the value R2 stores: it loads the staging frame and its summary as R2 does, holds back the formula-owned columns, fills the reviewed nulls with R2's own functions, and runs policyengine-us for the household sum of `adjusted_gross_income` in household chunks. That sum is the production SOI materializer's AGI measure (an engine-tier test compares them), so income held by a dependent, or by a tax unit without an adult, counts as the engine counts it: not at all. A null take-up flag that R2's own stages fill is held back, since the AGI does not read it; a null in a never-default column that the AGI reads is refused, as R2 refuses it. With `--puma-ladder` it applies R2's own minimum-support moves first. It exits 2 when a county is at risk.
