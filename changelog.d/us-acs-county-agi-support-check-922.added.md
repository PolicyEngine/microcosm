`tools/check_us_acs_county_agi_support.py` lists, before the ACS local release (R2) runs, the counties whose county IRS SOI AGI row R2 would build empty: counties with households but none with a nonzero AGI (microcosm#922; microcosm#1630 review, finding 1). The state AGI row stores no zero, so such a county makes `attach_surface` refuse the run after the materialize engine pass. The check computes the value R2 stores: it loads the staging frame and its summary as R2 does, holds back the formula-owned columns, fills the reviewed nulls with R2's own functions, and runs policyengine-us for the household sum of `adjusted_gross_income` in household chunks. That sum is the production SOI materializer's AGI measure (an engine-tier test compares them), so income held by a dependent, or by a tax unit without an adult, counts as the engine counts it: not at all. A null in a never-default column that one of R2's own stages fills (the set the reviewed-fill pre-check uses) is held back only while its nulls are on ACS rows and the AGI does not read it; every other never-default null is refused, as R2's fill step refuses it: a null on a donor row, in a column no R2 stage fills, or in one the AGI reads. An engine-tier test checks that no stage-filled column is an AGI input. With `--puma-ladder` it applies R2's own minimum-support moves first, and lists the counties that R2's `check_support` refuses with or without `--county-drop-empty-soi-rows`: a county outside the ladder, and a ladder county without a household-universe record after the moves (as R2 does, it moves no household when a county is outside the ladder). It exits 2 when a county is at risk, and 3 when R2 would refuse the run (3 takes precedence).
