Test repositories no longer start git's background maintenance. `git commit` starts `git maintenance run --auto`, which detaches holding `.git/objects/maintenance.lock` and removes it after the commit has returned. The Axiom checkout-reference tests hash `.git`, so on a busy runner the digest could list the lock and fail to read it, failing the engine-free job (`FileNotFoundError` in `test_a_clean_checkout_at_the_declared_commit_is_accepted`). Every test that commits to a throwaway repository now passes `test_support.git_repositories.NO_BACKGROUND_MAINTENANCE`. `rulespec_tree_digest` still refuses a tree that loses a file while it is hashed, now with a `ValueError` that names the file and the remedy instead of an unhandled `FileNotFoundError`.
