`microcosm.build.build_folder_switch` can now move builds that have no tag, as BE's are stored: an untagged folder `releases/<folder>/` on `main` that holds a build's files directly (microcosm#1739). `--include-untagged <folder>=<release>` moves it as build `<folder>` of `<release>`, without reading `publishes_to_build_folder`. The `copy` step copies every file the folder holds from the commit that last changed it and rewrites the two manifests as for a tagged build. The rewritten release manifest's `artifacts` lists exactly the files the folder holds, and its old map, which may declare files the folder doesn't hold, is kept unchanged as `unpublished_artifacts`. Its `migrated_from` names the old folder, that commit and the old manifest's SHA-256. The build's `published_at` is that commit's date, and the `switch` step refuses a folder changed since it was copied. A `latest.json` with no `revision` that names such a folder by its `release_id` makes its build current. The copy step refuses a folder that is also a tag, a release named like a folder `--include-untagged` moves, a folder holding a checksum ledger, a subfolder or nothing but its manifests, two files whose names give one artifact name, a folder from which a file was deleted after the commit that last changed the files it holds, and a manifest with no `build` object, whose `build.build_id` isn't the folder's name or that names a tag.
