The implementation hashes of the UK stage kernels and of the population and calibration kernels that use the default hash of their module now include `microcosm.frame.table_copies`, which `_minimal_frame` and the UK `context_frame` copy each kernel's inputs with (#1746). The create, location draw, geography mapping and pool checkpoint kernels share those hash functions and move too, though they do not copy through it. `source_hash` reads only the modules it is given, so before this an edit to `copy_table` left those kernels' node keys unchanged, and a graph store built before the edit could serve their nodes. The hashes move once more with this change: the next UK spine or full build reruns those nodes and every node after them, because a node key is derived from the keys of the nodes that produced its inputs; in a spine build that is every node. No data output changes. The national problem kernel also copies through `context_frame`, but its hash lists neither `graph_population` nor `table_copies`, a gap this change leaves as it was.
