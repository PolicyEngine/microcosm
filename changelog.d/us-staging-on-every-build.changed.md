US fiscal-refresh staging telemetry is now safe to leave on for every build. Exact-count builds stage under their own `runs/<run_id>/` prefix and never write `latest_staging.json` or `runs.json`, so `--exact-k` no longer requires `--no-staging` and the exact-k ladder launcher stops passing it. The release uploads from a background thread, so a slow or unreachable Hub never stalls the build; the terminal upload is awaited for at most 120 s. `--staging-upload-interval-seconds` defaults to 300 s (was 30 s), as for UK builds, because each cycle is up to six single-file Hub commits. SIGTERM now raises `BuildTerminatedError`, so a supervisor or budget stop marks the staging run failed instead of leaving it `running`.
