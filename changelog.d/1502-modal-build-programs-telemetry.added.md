The registered US Modal build programs start the emitter (microcosm#1502), so their stages on Modal send telemetry with the collector token the runner passes. `tools/build_us_acs_local_release.py`, `tools/build_us_puf_support_base.py` and the ACS staging builder behind `tools/build_us_acs_multispine_base.py` open one telemetry run each through the new `microcosm.build.program_telemetry`, right after parsing their arguments, under the pipelines `us_acs_local_release`, `us_puf_support_base` and `us_acs_multispine_staging` (country `US`). They record a stage change before each stage (the release's stages, the base's outer stages, the staging builder's main phases) and then completion, or failure with the error; a validation refusal is recorded as a failure. With `MICROCOSM_TELEMETRY_REQUIRED=1`, which the runner sets, a program whose emitter cannot be used stops before any work; unset or `0`, it runs without one. Leaving telemetry not required exists only for people outside PolicyEngine who run Microcosm without access to the collector; PolicyEngine's own builds keep it required. The runner gives each stage `MICROCOSM_TELEMETRY_RUN_ID=<plan run_id>.<stage>`, which a plan may not set, so each stage is its own telemetry run with the plan's run as its candidate ID and every attempt of a stage reports under the same run; started by hand, a program makes its own attempt ID (`<pipeline>-<UTC time>-<8 hex digits>`), as the US fiscal refresh does, and an ID the collector would refuse stops it with `ValueError`. In the PUF support base only the `--stage all` parent starts the emitter: it records each child interpreter's stage and outcome, and tells the children through `MICROCOSM_TELEMETRY_PARENT_PID`, which a plan may not set either, to start none. The no-checkpoint compatibility path starts the emitter too and changes no output byte; a named `--stage` run by hand starts its own. A plan pinned to an earlier commit runs tool code that starts no emitter, so its stage still sends nothing.
