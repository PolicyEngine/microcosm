`MICROCOSM_THREADS` is the one thread setting of the US release, base, ACS multispine staging and ACS local-release commands. When it is set to a positive whole number, each command copies it, before numpy loads, into every unset or blank OpenMP, BLAS, numexpr and joblib thread variable (`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `BLIS_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, `NUMEXPR_NUM_THREADS` and `LOKY_MAX_CPU_COUNT`, and `NUMEXPR_MAX_THREADS` above 64). Variables already set keep their values. A value that is not a positive whole number stops the command, and a Modal plan that sets one is refused when it is loaded. Commands that import the release tool, such as the exact-k ladder, certification and scoring tools, read the setting at that import. Without it, the base, ACS staging and ACS local-release commands set nothing and each library chooses its own count as before, and the release tool keeps its default of `min(os.cpu_count(), 16)`, which still leaves a blank variable as it is.

On Linux the OpenBLAS thread count can change output bytes, so the base command now records `MICROCOSM_THREADS` and each loaded BLAS library's thread count (`blas_threads_in_use`, from threadpoolctl) in `thread_environment`, and a resume with different values is refused, including one on a host where OpenBLAS would use a different count.
