The US base and local-area build commands now set their OpenMP, BLAS and numexpr thread variables before numpy loads, each to the count its library already uses: `OMP_NUM_THREADS` if it names a count, otherwise `os.process_cpu_count()`, with no upper limit. numexpr keeps its own rule. Values already set are kept, and importing the tools changes nothing.

On Linux the OpenBLAS thread count changes output bytes, so a build's output already depends on the host's count. This change keeps each count, so it keeps a host's output, but the base command now records real counts in `thread_environment` and refuses a resume on a host with a different count. On hosts with more logical CPUs than physical cores, scikit-learn's sign classifier now uses all logical CPUs. OpenMP and BLAS still do not follow a CPU quota outside Modal.
