The US base and ACS multispine staging commands now set their OpenMP, BLAS and numexpr thread variables before numpy loads. Each BLAS and numexpr variable gets the count its library already uses: `OMP_NUM_THREADS` if it is a plain count, otherwise `os.process_cpu_count()`, with no upper limit, and numexpr keeps its own rule. Values already set are kept, and importing the tools changes nothing.

On Linux the OpenBLAS thread count changes output bytes, so a build's output already depends on the host's count. This change keeps that count, so it keeps a host's output, and the base command now records real counts in `thread_environment` and refuses a resume with different ones. OpenMP and BLAS still do not follow a CPU quota. Because `OMP_NUM_THREADS` is now set, scikit-learn's sign classifier and torch use that count instead of their own defaults, which for scikit-learn means it no longer follows a CPU quota or `LOKY_MAX_CPU_COUNT`.
