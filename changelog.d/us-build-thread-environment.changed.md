`MICROCOSM_THREADS` is the one thread setting of the US release, base and ACS multispine staging commands. When it is set to a positive whole number, each command copies it, before numpy loads, into every unset OpenMP, BLAS, numexpr and joblib thread variable (`OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS`, `BLIS_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS`, `NUMEXPR_NUM_THREADS` and `LOKY_MAX_CPU_COUNT`). Variables already set keep their values, and a value that is not a positive whole number stops the command. Without it, the base and ACS staging commands set nothing and each library chooses its own count as before, and the release tool keeps its default of `min(os.cpu_count(), 16)`.

On Linux the OpenBLAS thread count changes output bytes, so the base command now records `MICROCOSM_THREADS` and each loaded BLAS library's thread count (`blas_threads_in_use`, from threadpoolctl) in `thread_environment`, and a resume with different values is refused, including one on a host where OpenBLAS would use a different count.
