The graph kernels that compile targets now include `microcosm.calibrate.geography_constants` in their implementation hashes, so an edit to a geography label recompiles the targets instead of reusing a stored surface that carries the old label (microcosm#1492). `ledger_targets` labels a target's geography from `UK_GEOGRAPHY_ID_TO_LABEL` when the Chronicle facts give no name, and `uk_runtime/target_weights` reads `UK_WIDE_GEOGRAPHY_IDS` for the UK loss weights, both through `from … import`, which `source_hash` does not follow. The module joins the transport `_COMPILE_MODULES` (hashed by `targets.compile@1`, `takeup.compare@1`, `takeup.gap@1`, `transport.create@1`/`@2` and `transport.quantile_map@1`/`@2`), the UK target compile modules (hashed by the full graph's target, selection, measures and problem kernels and the national graph's target and problem kernels), and the UK problem kernel's loss-weight hash. The UK list also gains `microcosm.calibrate.registry`, `target` and `hierarchy`, which the transport list already hashed: the UK import check read only `microcosm.build` imports and now reads every `microcosm.*` import, and a new transport check does the same for `_COMPILE_MODULES`, so a module a compile module imports must be hashed or excluded with a reason. Node keys move once: the target compilation of every transport country and everything after it, and the UK target, selection, measures, problem and national target and problem nodes and everything after them, including the UK solve. Because `transport/target_kernels.py` itself changes, `calibration.prepare@1` and `gates.battery@1` nodes that do not read a compiled surface also get new keys once.
