US releases now carry their stored-input verdict (microcosm#1026) as release evidence, and the publisher requires it (microcosm#1034). Before, the fiscal-refresh tool recorded the verdict only in run telemetry, and the publisher's local-area gate check read only the gates a summary happened to list, so a release packaged by a tool without the check validated like one packaged with it. The fiscal-refresh tool, which the exact-k ladder lane also runs, now writes `stored_inputs.json` before its batched pre-export raise: the gate's failure lines, whether it passed, the engine it graded against, the register digest, and the registered and refused columns. It binds the file as a `diagnostics` artifact with `gate_evidence` status `bound`, and records the same verdict as a `stored_inputs` block in both manifests, tied to the H5 they pin. `validate_release_dir` and `validate_evidence_release_dir` refuse a US national calibration release that lacks that evidence, or whose verdict names an engine other than its built-with policyengine-us, disagrees across its files, refused a column at the certified tier, or (at the evidence tier) leaves a refusal line out of `known_failures`. A US non-default local-area release must now list the ACS package stage's `stored_inputs` gate, naming its built-with engine and the microdata sha256 it ships; UK local-area releases are unaffected. The publisher's checks read JSON only. No release on the Hub carries this evidence and none is exempt. Nothing re-validates a published release automatically; the two paths that run the contract on one again, a publish retry of its local directory and an annual-projection cut on a national base, are re-certifications, every published US national base already fails the unchanged calibration-diagnostics schema rule, and local-area releases cannot be annual bases, so publishing one again means rebuilding or re-packaging it, which runs the check. The fiscal-refresh gate now records why it could not evaluate with the exception's type, so an empty exception message cannot leave a verdict the contract refuses. A source-enrichment bundle certified with a publisher compatibility range now records, beside the claim, what it was measured against: `compatibility.claim_measurement` names the claim's specifier and the one policyengine-us version the native-loader probe and its stored-input contract graded. Validation and the publisher recompute the record from the replayed probe and refuse any other record, a record without a claim, or one on a pending candidate; the certify, validation and preflight JSON and the publisher's stderr print it. Other versions the range admits, later or below the tested one, remain unmeasured, and the SPM-role runbook now says so and how to grade a candidate against another released version before declaring a range.
