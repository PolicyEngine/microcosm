The US PUF-support base now keeps each person's prior-year wage and salary income as `cps_employment_income_last_year`. policyengine-us computes `employment_income_last_year` with its own formula from 2024 on, and the release writer refuses to store a formula-owned column, so the prior-year income stage used to drop the wage it had derived once it finished on the support-cloned frame. The stage now copies that wage into `cps_employment_income_last_year` before the drop: ASEC rows keep the wage the stage derived, and PUF-support rows keep the joint QRF's imputation. On ASEC rows (`person_support_channel == "asec"`) where `previous_year_income_available` is true, the column holds `WSAL_VAL` from the same person's record in the previous ASEC year, unadjusted. Analyses that need an observed prior-year wage read only those rows, since PUF-support rows copy the availability flag from their ASEC source but hold an imputed wage. policyengine-us 2.2.1 and 2.90.4 define no variable of that name, so no rule reads it. `US_AUXILIARY_STORED_COLUMNS` in `microcosm.data.stored_inputs` registers it with its reason, and `US_STORED_NON_VARIABLE_COLUMNS` takes in that mapping, so the stored-input contract admits the column. The source reconciliation gate now requires the wage under one of its two names and compares each name present with the derivation on every ASEC row. When the column is present, the signal gate refuses a negative or nonfinite value and, as it does for the other prior-year columns, fails when the column holds fewer than two distinct values. Stacked multispine pools merge only declared operator outputs, so they don't carry the column. ACS pooling (`build_optional_acs_multispine`) drops it from the base before it adds ACS rows, since no ACS transfer target fills it, and lists it under `dropped_base_person_columns` in its provenance.
