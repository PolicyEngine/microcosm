The US head-to-head scorer (`tools/score_us_release_head_to_head.py`) runs its `--workers` slices on the shared worker pool instead of `ProcessPoolExecutor`, so the repository has one worker-pool implementation. `--worker-max-slices` now works on every supported Python: the scorer no longer refuses it on interpreters where `ProcessPoolExecutor` could hang replacing a worker. A slice whose worker dies (for example, killed by the operating system for its memory) runs once more in a fresh worker before the run stops with the slice's label; the scorer's own 20 GiB memory check, and any other error raised while scoring a slice, still stop the run at once. Each failed attempt is printed on stderr. Scorecards are unchanged.
