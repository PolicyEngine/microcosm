The US head-to-head scorer (`tools/score_us_release_head_to_head.py`) runs its `--workers` slices on the shared worker pool instead of `ProcessPoolExecutor`, so the repository has one worker-pool implementation. `--worker-max-slices` now works on every supported Python: the scorer no longer refuses it on interpreters where `ProcessPoolExecutor` could hang replacing a worker. A slice whose worker dies or runs out of memory runs once more in a fresh worker before the run stops with the slice's label. Scorecards are unchanged.
