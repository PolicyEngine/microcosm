The US release tool now binds its terminal gate verdicts into the release manifests, so the evidence a certified-surface exception rests on ships with the release. `input_coverage.json`, `input_mass_parity.json`, `qrf_tail_concentration.json` and `reform_coverage_smoke.json` become `diagnostics` artifacts whenever the run wrote them, so the publisher uploads them without `--extra-file`. Stale copies left by an earlier attempt under the same release id are cleared before the gates run. Both manifests (`build_manifest.json` top level and `release_manifest.json` `build`) now record:

- `gate_evidence`: for each of the four gates, `bound` (its verdict is an artifact), `skipped` (only `--skip-reform-coverage-smoke` can skip one) or `not_evaluated` (an evidence-tier run whose evaluation crashed under earlier failures wrote no verdict), so a missing verdict is never ambiguous.
- `qrf_tail_register`: path, sha256 and entries of the per-run QRF tail register as the gate evaluated it, its stale/unused mismatch, and whether the gate was enforced. A null path and sha256 means no per-column register was passed; `enforced: false` means `--allow-qrf-tail-concentration` waived the whole gate.
- `export_input_mass_reference`: path and sha256 of the `--export-input-mass-reference-h5` bytes the export-mass gate loaded. Before this change only the file's basename was recorded.
- `calibration_runtime`: the torch version, `torch.get_num_threads()` and `OMP_NUM_THREADS` when the solve starts. `calibration_diagnostics.json`'s `build` block records the same values, so a run that fails its pre-export gates, and writes no manifest, keeps them too.
- `fiscal_target_exclusion_receipt`: where `us_source_coverage.json` carries the fiscal-target exclusion receipt (file sha256, key, whether it is present, and the receipt's own sha256).
