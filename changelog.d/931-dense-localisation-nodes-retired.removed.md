Retire the dense line's own property, BRMA, private-rent and fuel-relief nodes, with their flags, configuration fields and release-candidate refusals (#931). The dense line takes home values, BRMAs, private rents and Rural Fuel Duty Relief flags from the spine, whose own stages set them in later commits of #931 group (c), and keeps the spine's council-tax bands. It already refuses, before it pins or reads any other input, a spine whose roster lacks those stages (`spine_posture`), so no dense build runs until they land.

- **Nodes and kernels.** `uk.full.property.value@1`, `uk.full.property.band@1`, `uk.full.geography.brma@1`, `uk.full.geography.rfdr@1` and `uk.full.private_rent@1` leave `microcosm.build.uk_runtime.graph_population`, with the helpers that composed them, the property quantile artifact type (`microcosm.uk.property-quantile-draw`) and the pool checkpoint's typed edge to it. `append_uk_population_nodes` no longer takes `property_localisation_mode`, `brma_localisation_mode`, `private_rent_localisation_mode`, `rfdr_localisation_mode` or `full_scale`, and `uk_pool_validation_inputs` no longer takes a property mode. On the atomic assignment the dense graph's geography is now the identity, the shared support imports, assignment and derivation, the local-authority resolve, the shared gate and the UK distribution gate; the next change of #931 retires those too, when the dense line takes its areas from the spine.
- **Configuration.** `UKFullBuildConfig` loses `property_localisation`, `brma_localisation`, `private_rent_localisation` and `rfdr_localisation`, and with them its refusal of BRMA target rows without area BRMAs. The dense line no longer leaves its BRMA-grain rows out on either assignment: they bind on the spine's `brma` column, which a spine the dense line accepts reads off its areas. So `append_uk_target_nodes` loses its `brma_rows` switch and the target selection's payload its `brma_rows_left_out` field, which nothing could set once the configuration field went.
- **Flags.** `microcosm-build-uk` (`tools/build_uk_full.py`) no longer takes `--property-localisation`, `--price-paid-quantiles`, `--voa-band-mix`, `--scotgov-band-mix`, `--brma-localisation`, `--brma-area-layer`, `--private-rent-localisation`, `--brma-rent-quantiles`, `--rfdr-localisation` or `--rfdr-area-layer`, nor the six resource pins `--price-paid-quantiles-sha256`, `--voa-band-mix-sha256`, `--scotgov-band-mix-sha256`, `--brma-area-layer-sha256`, `--brma-rent-quantiles-sha256` and `--rfdr-area-layer-sha256`. A script that still passes one is refused as an unrecognized argument. The release-candidate refusals of the four `none` modes go with them: the spine-roster check holds every dense build, release candidates included, to a spine with the stages that set those columns. The build request's bindings lose their four localisation blocks, and the size-checkpoint identity loses the four blocks that bound those resources' pins.
- **Kept.** Every function the nodes called stays, with its tests: `owner_uniforms`, `localise_values`, `localise_bands` and `spine_household_keys` in `property_localisation`, `area_brmas` in `brma_area_layer`, `area_flags` in `rfdr_area_layer` and `localise_rents` in `private_rent_localisation`. The spine's geography and private-rent transforms (`spine_geography`, `spine_private_rent`), which no stage declares yet, call `area_brmas`, `area_flags` and `localise_rents`, and the `regional_home_values` stage calls `owner_uniforms`. The committed resources the nodes read and the terminal `uk_local_brma_enum_domain` gate stay too, though no dataset build reads the VOA or Scottish band mix now. The unread mode tuples `BRMA_LOCALISATION_MODES`, `RFDR_LOCALISATION_MODES` and `PRIVATE_RENT_LOCALISATION_MODES` go; `PROPERTY_LOCALISATION_MODES` stays for now, since spine stages hash `property_localisation`. `private_rent_localisation`'s docstring now names the spine's private-rent stage as the caller that supplies the row keys and tie-break uniforms. `tools/uk_private_rent_pool.py` and `tools/uk_private_rent_receipt.py` now say they read only dense runs built before this change.
- **What moves.** Keys only, no value: the dense line already refuses every spine, the national line every clone-first one, no spine module changes, and a national build on a spine without clone indices computes what it did before. Of the 96 kernels the UK registries register (101 before), 30 change hash, all `uk.full`: the nine `graph_population` defines (sample, normalisation, expand, identity, locations, mapping, local authority, pool and the distribution gate); the fifteen that hash it (the dense measures and problem, the dense solve, the calibration install and the five size kernels, the rotated holdout, both export preparations, and the national problem, gates and read-back); the bound spine's checkpoint kernel (`uk.full.bound_spine@1`), which hashes `graph_build`; and the five that hash `graph_targets` but not `graph_population` (the target compilation and selection, the national targets, and the full battery's preflight and calibrated gate kernels). Each kernel that hashes `size_checkpoint` also hashes `graph_population`, and no kernel hashes `full_build_cli`, `rowwise_cli`, `orrery_contract`, `brma_area_layer`, `rfdr_area_layer` or `private_rent_localisation`. Of the gate phase codes only the full battery's terminal code moves, since it lists `graph_population`, so the calibrated gates' `terminal_code` parameter changes too. On a spine the dense build composes, every spine stage and both spine gates keep their keys and every dense node re-keys; on a bound spine the checkpoint re-keys, and every dense and national node after it. A dense run's input pins no longer carry the seven resources, so its input-pins digest, candidate identity digest and size-checkpoint identity change. No declaration, generated file, `gates.json` or schema changes.
- **Tests.** The node and configuration tests go: `test_uk_brma_area_graph.py` and `test_uk_rfdr_area_graph.py` are removed, as are the graph sections of `test_uk_private_rent_localisation.py`, `test_uk_property_localisation.py` and `test_uk_regional_home_values.py` and the CLI's localisation flag tests. Their function tests stay. New tests check that each retired flag is refused as an unrecognized argument, and that the atomic dense graph composes none of the five nodes, neither declares nor reads their resources, and the Orrery roster names none of them. The toy resource writers that only the nodes read leave `test_support/microcosm_build/uk_atomic_support_fixtures.py`.
