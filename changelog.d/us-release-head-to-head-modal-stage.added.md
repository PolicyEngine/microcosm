The US head-to-head scorer is a Modal stage: `us-release-head-to-head` (one `score` stage; digest-pinned incumbent, candidate and ledger-feed inputs; `workers`, `maximum_microsim_batch_size` and `worker_max_slices` as the only plan options), with a `head-to-head` resource class (16 CPUs and 288 GiB, both limited at the request, and a timeout derived from `HEAD_TO_HEAD_COST_CAP_USD`: at d844's $40 cap and the non-preemptible list price, 15,705 seconds). `docs/us-modal-stage-route-a-h2h-plan.json` is the 16-worker d844 run (the d1386 Route A build against `populace-us-2024-spm-20260915`), non-preemptible, without worker recycling, with a 14,505-second tool budget, pinned to `main` at 2cfe3043d, which carries #1171. Whether it fits $40 depends on Modal's speed for this scorer, which nothing has measured. Check mode reports the image venv's Python and runs a tool's option preflights (`ToolSpec.option_preflights`), so a plan that sets `worker_max_slices` runs the scorer's recycling guard in the image and fails the check on Python below 3.14.7. `tools/us_head_to_head_projection.py` reads the stage's streamed log, rebuilds both worker pools under CPython's on-demand worker starts, replays the rest of the run from the measured paces, and answers `WAIT`, `GO` or `NO-GO` against the tool's time budget or a stall; memory is reported, not judged. `tools/us_head_to_head_watch.sh` streams the app's log into one file per stream, polls the projection every ten minutes and stops the app on `NO-GO`, confirming the stop. `docs/evidence/us-h2h-speed` holds the local slice times, a three-worker pool run of the pinned scorer and simulated 16-worker runs. The runbook documents the sizing evidence and its gaps, costs outside the compute ceiling, the lack of a final receipt after a whole-container OOM, and operator-supplied input paths. Check mode imports sibling-dependent tools with their script directory on the module search path and registers the probed module before executing it.
