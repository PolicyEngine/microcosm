A build on a busy host no longer loses its hosted telemetry when another build holds the shared local spool (`~/.cache/microcosm/telemetry/events.sqlite3`) at the moment its emitter service starts. Before, the service's registration gave up after SQLite's 5 s busy wait, the service exited and a SQLAlchemy traceback landed on the build's stderr. Now the build tells the service when it will stop waiting (`--ready-deadline`), and the service retries lock errors with jittered backoff until shortly before then; if the spool is still locked it prints one warning line and exits with status 75. Opening a spool that is already at the current schema takes no write lock: retention pruning moved from spool open and every append to the delivery worker. Schema migrations now run in one `BEGIN IMMEDIATE` transaction, so concurrent first opens of a new spool no longer fail with "table already exists" (about half of eight simultaneous opens did before) and an interrupted migration leaves no partial schema. The delivery worker skips a failed step for one tick instead of dying, so heartbeats, delivery and the check that records a killed build keep running, and errors other than lock contention print one line per error type rather than a thread traceback.
