`microcosm-publish-release-build --promote` and `microcosm-withdraw-release-build` name the change's own release and build for the collector (UK builds as licensed, US builds as not), so the emitter submits the `releases.json` the change wrote to the collector, naming the build that is current after it, and the collector's latest calibration tree follows the default release's current build, older or newer (microcosm#1607). Once the change has landed, the command waits up to ten minutes for the collector to accept it and prints its status as `collector_submission`; a release left with no current build sends nothing (`NO_CURRENT_BUILD`).
