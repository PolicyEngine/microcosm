`microcosm-publish-release-build --promote` and `microcosm-withdraw-release-build` name the change's own release and build for the collector (UK builds as licensed, US builds as not), so once the change has landed the emitter submits `releases.json` to the collector, naming the build that is current after it, and the collector points the country's latest calibration tree at its default release's current build, older or newer (microcosm#1607). The command then waits up to ten minutes for the collector to accept it and prints its status as `collector_submission`; a change that has not landed sends nothing and the command says nothing of the collector, and a release left with no current build sends nothing (`NO_CURRENT_BUILD`).
