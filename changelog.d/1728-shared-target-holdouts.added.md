Target hold-outs are shared code for any country (microcosm#1728): `microcosm.build.target_holdouts` draws held-out targets by hashed blocks from declared passes (scope, eligibility, unit key, salt, fractions, receipt), builds the training target set, and scores the held rows against a pro-rata baseline. The ACS local release declares its district and county passes in the new `us/local_target_construction.json`, read by `microcosm.build.us_runtime.local_target_construction`; the tool functions call the shared code under their old names. No target, role or receipt changes: `test_us_target_holdouts.py` holds the shared code to verbatim copies of the replaced tool code, and the pinned bytes of `test_us_acs_local_surface_bytes.py` are unchanged. The new resource row moves the US F0 spec-engine pins (42,410 configuration fields). One label changes: `calibration_diagnostics.json` names each matrix-row measure `microcosm.build.target_holdouts.target_matrix_row[N]` instead of `us_acs_local_cd_surface.target_matrix_row[N]`, because the function that makes it moved to the shared module. So the diagnostics' `target_surface.sha256` (and the same field in `build_manifest.json`) changes for the same targets and weights; `names_sha256` and `values_sha256` do not. Accepted on 26 Nov 2026 and pinned in `test_us_target_holdouts.py`.
