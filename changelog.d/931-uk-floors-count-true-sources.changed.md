Every UK floor now counts true source households, the survey household each copy and clone keeps in `source_household_id`, through one reader (#931). The reader is the new country-neutral `microcosm.build.source_lineage.record_sources`: a country declares its copy lineage once (the entity copies are made of, its source column and each copying step's marker and ordinal columns), and every record of any entity reads its source through household membership. `receipt_counts.record_source_households` is the UK's entry on `household_lineage.UK_COPY_LINEAGE`, and `receipt_counts.SOURCE_HOUSEHOLD_COLUMN` is the shared `source_household_id`, no longer `household_source_id`, the support channel's immediate parent. The reader refuses a frame without the source column, and a null source; a stage that can run before the first copying step says so (`before_copies`), and on a frame without the source column or copy lineage its households are their own sources; on the clone-first spine that step is `geographic_expand`, which writes the column, so a stage after it that says so reads it. The take-up signal receipts, the apprentice receipt and the annual income receipts (`frs_take_up`, `frs_person_draws`, `frs_household_draws` and `frs_annual_income_spells`), the SPI pay floor and pension coherence (which read `household_source_id` without the null refusal), company cars, the SPI benefit coherence, UC take-up's pools, the legacy closure, salary sacrifice's receipt and bonus donor floor, Carer's Allowance, the trading allowance, the support floor, the single-year age report, the dataset-size evaluation, the sampled rung's region floor for private rents, and the council-tax, BRMA-distribution, weighted-integrity, benefit-cap and UC-relationship tools count through it. The two columns agree on every household row of today's spine and pool, so no spine output moves. The single-year age report and the dataset-size evaluation now count a zero-weight row as carrying nothing and a household's copies once, so their support counts can fall; the weighted-integrity tool's carriers are now distinct sources, not rows. The five finite stages that declared `household_source_id` declare `source_household_id`, UC take-up's pooling text and the Carer's Allowance and support-floor notes name it, and a static test refuses any distinct count of `household_id`, `person_household_id` or `household_source_id` in the UK runtime and tools outside two named structural checks. The receipts' counting modules (`receipt_counts`, `household_lineage`, `source_lineage`) are bound into the implementation hash of every stage whose module or helpers import one of them; eight stages that counted through `receipt_counts` did not bind it, so an edit to it alone left their cache keys in place. Main's carer-link share (microcosm#1095 A3), which the SPI channel's refresh in `hmrc_spi_income_spine` reads after `geographic_expand`, counts its base the same way: `frs_disability.carer_link_share` takes `support_keys`, and the refresh passes each FRS-channel person's true source, so the share's floor and support band count a survey household's clones once.
