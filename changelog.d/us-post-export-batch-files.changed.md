US post-export scoring keeps each household batch of the written H5 in its own file instead of in memory. The scorer still loads the H5 once, bound to its SHA-256, and checks that the batches partition it. It then pickles each batch to a file, records the SHA-256 of the bytes written, frees the frames, and reads each batch back from its file whenever a pass scores it, freeing it before the next. A file that changed or cannot be read is refused, and the refusal stops certification in every stage, the held-out reports included. The process that scores therefore holds no frame of the H5 between batches: about 0.39 GiB less on the published 57,240-household national file (measured) and about 2.1 GiB less on a 352,932-household national export (estimate), for the whole of certification. Certification's scorer keeps the files in a directory of its own inside `post_export_batches/` in the build's `--out`, which takes about as much disk as the export H5, and removes them when it closes. Placing a build for certification removes files that a killed attempt left. Scored values are unchanged.
