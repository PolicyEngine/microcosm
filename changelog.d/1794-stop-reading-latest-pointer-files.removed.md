Stop reading and writing `latest*.json` pointer files (#1794): every release repository lists its builds in `releases.json`, and each repository's switch deleted its pointer files. The loader refuses a repository without `releases.json`, online and offline, instead of following `latest.json` or a UK release's `latest-<name>.json`; `load()` loses its `unverified_root` option, since no repository holds a root dataset file; `DatasetSpec` loses `pointer_path` and must name its `release`. `microcosm.data` and `microcosm.data.release` no longer have `latest_release`, `latest_line_release`, `latest_evidence_release`, `LatestPointer`, the pointer payload builders, `line_pointer_path` or the pointer constants, and `microcosm.data.contract` no longer has `line_for_release_id` or `dataset_role_for_line`. `microcosm-publish-release-build` still refuses a repository that has a pointer file, now with one message for any repository: remove the file. AM's and NZ's release contracts name build folders and `releases.json` instead of `latest.json`. A caller of a removed reader now fails at import, for example PolicyEngine/bottom-50-tax-analysis's call of `latest_release`, which already failed because no repository has `latest.json`.
