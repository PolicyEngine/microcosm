`tools/sample_us_export_households.py` and `tools/probe_us_post_export.py` record what they ran. They used to record the worktree's HEAD when they wrote the receipt or report, and in the first real run both named a commit made minutes after they started. Each tool now records `tool_source` in two parts. As it loads, it records the repository state (HEAD; whether `tools/` or `packages/` differ from it; a sha256 of those differences, untracked files included) and its own sha256. When it writes, it reads that state again and sets `moved_since_load` if it changed, so an edit within an already dirty tree also counts. The comparison covers those two moments only: an edit made and undone in between is not seen, and installed libraries are recorded by version. The probe also records the sha256 of the release tool and sampler it ran. For a tool it loads itself, this is the hash of the bytes it executed; for one passed in, the file is hashed at write, and the record says which. Git is read with `--no-optional-locks`, so these reads never take the index lock. The sampler's `tools_dirty` becomes `dirty` and covers `packages/` too; the probe report names the source of its process peak RSS (`ru_maxrss`); both schema versions are now 2. `docs/evidence/us-export-subsample-design/route-a-p005/` records that run, a p = 0.05 probe of the published Route A export against its full-size outputs, with a rerun of its smoke by the merged probe.
