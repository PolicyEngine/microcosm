`tools/sample_us_export_households.py` and `tools/probe_us_post_export.py` record what they ran. They used to record the worktree's HEAD when they wrote the receipt or report, and in the first real run both named a commit made minutes after they started. Now each records `tool_source` as it loads: HEAD; whether the working tree under `tools/` or `packages/` differs from HEAD's tree in any file's bytes or mode; a sha256 of those differences, untracked files included; its own sha256, of its bytes read before its heavy imports; and a digest of every installed distribution's name and version. When it writes, it reads that state again and sets `moved_since_load` if it changed. The working tree is compared with HEAD by content, not with the index, so staging, or rewriting a file with the same bytes, is not a change. Only git plumbing runs, which never writes the index, so a concurrent `git add` in the same worktree never finds the index locked. The probe also records the sha256 of the release tool and sampler it ran: the bytes it executed for a tool it loads itself (its tracebacks quote the same bytes), or the file at write time for one passed in, saying which. The comparison covers the two moments only: an edit made and undone in between is not seen. The sampler's `tools_dirty` becomes `dirty`; the probe report names the source of its process peak RSS (`ru_maxrss`); both schema versions are now 2. `docs/evidence/us-export-subsample-design/route-a-p005/` records that run, a p = 0.05 probe of the published Route A export against its full-size outputs, and a rerun of its smoke by the merged probe, which reproduces all 41 smoke rows exactly.
