Reform-coverage smoke probes that change a list-valued parameter now declare the items they remove or add (`list_edits`) instead of pinning the whole list; all ten such probes, the NIIT pass-through probe among them, use the new form. Each edit resolves against the installed PolicyEngine-US baseline when its reform is built, and it fails loudly, in the release preflight and again at build and apply time, if a removed item is gone, an added item is already present, the baseline changes inside the edit's period, or the period starts on or before the list's first breakpoint at the engine's first reform pass (where PolicyEngine-US would backdate the edited list outside its period). At apply time the reform checks each stretch of its period on its own: every stretch must hold the baseline or the reform's own resolution. The post-export plan's dry run builds no probe reform and needs no engine. The coverage manifest moves to schema_version 2, which refuses a pinned list or a null `list_edits` and rejects schema_version 1 with a regeneration hint; the smoke evidence records each resolved list.
