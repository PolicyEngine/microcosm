Reform-coverage smoke probes that change a list-valued parameter now declare the items they remove or add (`list_edits`) instead of pinning the whole list, and each edit resolves against the installed PolicyEngine-US baseline when its reform is built — failing loudly, in the release preflight and again at build and apply time, if a removed item is gone, an added item is already present, or the baseline changes inside the edit's period. The coverage manifest moves to schema_version 2, which refuses a pinned list and rejects schema_version 1 with a regeneration hint; the smoke evidence records each resolved list.
