microcosm-fit's QRF forests build their leaf array in place. quantile-forest stores, for every tree, the training rows each leaf holds in one zero-padded int64 array (trees x nodes x outputs x width); version 1.4.2 builds one array per tree and then copies the list into the final array, which writes every padding byte and makes the whole padded array resident while both copies exist. `_fit_forest` now builds `_InPlaceLeafQRF`, a subclass that allocates the final array once and fills each tree's slice directly. The array is byte-identical to the library's, so every prediction and draw is unchanged; tests compare the two classes byte for byte on continuous, capped near-discrete, multi-output and weighted fits, and compare grid predictions and draws.

- quantile-forest is pinned to exactly 1.4.2, since the subclass replaces a private method. `_InPlaceLeafQRF` refuses any other installed release, in `fit` before growing a tree and again where its copied code runs.
- `tools/measure_qrf_leaf_memory.py` fits one synthetic forest shaped like the CPS-ORG wage fit or a capped near-discrete fit through `_fit_forest`, once with each class and each in a fresh process, and reports each fit's peak memory (the peak physical footprint on macOS, the peak resident set on Linux).
- Pickling or deep-copying a fitted forest still writes the full padded array, as before. New pickles name `microcosm.fit.qrf._InPlaceLeafQRF`, so microcosm-fit from before this change cannot load them; pickles made before it still load and draw the same values. scikit-learn's validation messages for a forest (a missing value in a predictor, an invalid `max_samples_leaf`) name `_InPlaceLeafQRF` instead of `RandomForestQuantileRegressor`; the exception types are unchanged.
