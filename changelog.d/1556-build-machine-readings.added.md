Builds and the Modal image now require microcosm-emitter 0.14.0 or later instead of 0.13.0 (microcosm#1556). 0.14.0 adds the build machine's readings: each heartbeat carries the machine's memory, CPU and disk use and the build's processes, a heartbeat after the machine wakes carries the sleep, the run's first event describes the machine, and each stage's end says how long it was awake and asleep. microcosm-build's `microcosm-emitter-interface` pin rises from `>=0.7.0,<1` to `>=0.14.0,<1` (the lock moves from 0.7.0 to 0.14.0, and `APPROVED_UV_LOCK_SHA256` is re-pinned for the new lock), and `LocalTelemetryEmitter.progress` takes the interface's `outer` counter. The US fiscal refresh's post-export scoring reports each reform pass as that outer counter, `reform_pass` *n* of the consumer's planned count, on every scoring-batch progress event of the pass, so "batch 74 of 177" also says "pass 57 of 101": the engine-free dry run that records each consumer's baseline plan also counts its reform passes, one per distinct key asked of each reformed simulation, and the scoring plan holds the counts for `_main`; a baseline pass, a consumer opened without a count, and any pass beyond the count send no outer counter, and the plan's record in the calibration diagnostics keeps its shape. The US Modal stage runner passes the stage container's resource class to the tool as `MICROCOSM_MODAL_RESOURCES` (`class`, `cpu`, `cpu_limit`, `memory_mib`, as JSON), in the stage run and in the check's probe, and the build reports it in its runtime identity as `modal_resources` (null outside a Modal stage or for a value that is not that object). A plan may not set the variable, and the container's own value is removed and listed in `runner.tool_env_removed`. The installed-emitter job's pin rises to 0.14.0, and its tests expect the two stage-end events 0.14.0 records when a run ends with stages open.
