Calibration diagnostics carry each dimension value's source order, so the calibration dashboard can list Federal Student Aid's nine debt-size bands from "Less than 5K" to "200K+" instead of alphabetically (Max Ghenis on microcosm#1357, PolicyEngine/calibration-diagnostics#276).

- **The field.** `HierarchyDimension` gains an optional `value_rank`: the position, from 0, of the value's row among its source table's rows. `_inherited_dimensions` takes it from Chronicle's `layout.groupby_ordinal` for the group-by dimension when every selected fact gives the same non-negative integer. Other dimensions, facts that disagree and Microcosm-derived facts give none, and a Medicaid enrollment substitution drops the template state's rank.
- **Diagnostics.** A schema 8 row's dimension carries `value_rank`. In schema 9, each catalog value carries `rank`, the one rank its rows give it. Ranks order values within one source table, and tables disagree: the IRS SOI tables place some AGI bands at different rows (`50k_to_75k` at 5, 9 and 10), and the USDA SNAP state tables number the states within each region, so seven states share row 0. So a dimension gets no ranks when any of its values is ranked two ways, or when one category gives two of its values the same rank. Ranks therefore order values within one category, with unranked values last; values from different categories can share a rank. Expansion gives each row its value's catalog rank. Rows still refer to values as `{id, value_id}`. The committed JSON Schemas for schemas 8 and 9 are regenerated.
- **Every country.** The compile is shared, so UK targets gain ranks too. The next UK build moves UK registry versions, local-surface records (which store each hierarchy's `to_dict()`) and diagnostics. No committed UK pin moves.
- **Compatibility.** A dimension without a rank serializes exactly as before (`HierarchyDimension.to_dict`, used by `TargetSpec.to_dict`, the UK local surface and the diagnostics rows), so registries written before this change keep their version and load. A registry whose targets gain ranks gets a new version: the pinned US `national_state` surface moves from `3aa2a0830e7d` to `c698e70d33ce`. Registry files are now format 4, and formats 2 and 3 stay readable, so a reader from before this change refuses a new file by its revision instead of failing on the unexpected `value_rank`. The diagnostics schemas stay 8 and 9, with `value_rank` and `rank` as optional additions: a reader that validates with an earlier `microcosm-diagnostics`, whose models forbid unknown fields, or with an earlier copy of the JSON Schemas refuses a file that carries either field, and a reader that ignores unknown fields reads it unchanged. The edited sources also move the US bundle's `spec_sha256` (through `medicaid_take_up`, an attested kernel module) and the `calibrate.adam@1` parity key; no draw, solve or target value changes.
