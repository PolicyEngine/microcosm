Calibration diagnostics carry each dimension value's source order, so the calibration dashboard can list Federal Student Aid's nine debt-size bands from "Less than 5K" to "200K+" instead of alphabetically (Max Ghenis on microcosm#1357, PolicyEngine/calibration-diagnostics#276).

- **The field.** `HierarchyDimension` gains an optional `value_rank`: the value's position, from 0, in the order its source lists the dimension's values. `_inherited_dimensions` takes it from Chronicle's `layout.groupby_ordinal` for the group-by dimension when every selected fact gives the same non-negative integer. Other dimensions, facts that disagree and Microcosm-derived facts give none, and a Medicaid enrollment substitution drops the template state's rank.
- **Diagnostics.** A schema 8 row's dimension carries `value_rank`. In schema 9, each catalog value carries `rank`, the one rank its rows give it. Ranks order values within one source table, and tables disagree: the IRS SOI tables place some AGI bands at different rows (`50k_to_75k` at 5, 9 and 10), and the USDA SNAP tables list states by region. So a dimension gets no ranks when any of its values is ranked two ways, or when one category gives two of its values the same rank. Expansion gives each row its value's catalog rank. Rows still refer to values as `{id, value_id}`, so a reader that ignores `rank` reads the file unchanged; the committed JSON Schemas for schemas 8 and 9 are regenerated.
- **Compatibility.** A dimension without a rank serializes exactly as before (`HierarchyDimension.to_dict`, used by `TargetSpec.to_dict`, the UK local surface and the diagnostics rows), so registries written before this change keep their version and load. A registry whose targets gain ranks gets a new version: the pinned US `national_state` surface moves from `3aa2a0830e7d`.
