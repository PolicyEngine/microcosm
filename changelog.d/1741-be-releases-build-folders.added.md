BE's two releases, `microcosm-be-2025-national` and `microcosm-be-2026-national` (one for each population year), publish each build into its own folder, `releases/<release>/<build>/`, through `microcosm-publish-release-build` and the emitter, as the UK releases do (microcosm#1741). `microcosm.data.contract.BE_RELEASES` names them, and `publishes_to_build_folder` admits them; the tagged publisher refuses them by name, and already refuses any repository that has `releases.json`.

- **The collector.** Publication, promotion and withdrawal name a BE build for the collector with the country code `BE` (`BE_COLLECTOR_COUNTRY_CODE`) and `licensed_data` true, as a UK build is named with `UK`. BE's inputs carry no restricting licence, so for BE the flag is a privacy setting: the collector keeps BE builds' Orrery graph files private while BE's repository stays private; a build's calibration tree may be public either way. Until now every release outside `US_RELEASES` was reported as a UK build.
- **The files.** A BE build carries the six files BE's release contract lists: the three base files plus `source_coverage.json`, `demographics.json` and `reform_validation.json` (`BE_REQUIRED_RELEASE_FILES`), keyed on the release name as each UK release's files are, and declares the three added files as artifacts, as a US build declares its source coverage, so that each is published. As for a UK release, no BE release is tied to a role in `releases.json`: a build's `dataset_role` gives it.
- **BE's release contract** (`packages/microcosm-build/src/microcosm/build/be/release_contract.json`) names the build folders and `releases.json` instead of `latest.json`, and says that builds publish into the private repository through the emitter while making any of them public is Max's decision. The golden country-spec file pins its new digest.
