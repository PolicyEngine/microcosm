The UK compile-parity gates receive the compile's own report of unresolved references (microcosm#1123 follow-up). The signed-differences receipts classify a fixture row whose reference no longer resolves as `ledger_absent`, because the tool that writes them holds that report. The release-cut certifier and the full graph kept each period's compiled registry and dropped the report, so the gate read the same row as `fixture_only` and failed it as a changed kind. After the re-pin to Chronicle 942a1fa the production-2023 receipt signed three such rows, so its gate would have blocked the next release cut. That gate is retired in the same change, so the fix now protects the two gates at the 2025 calibration period. Neither of their receipts has a `ledger_absent` row today; the fix is preventive there.

`ledger_compile_parity_gate` takes `unsupported`, and the report travels beside each compiled registry as `uk_ledger_compile_unsupported` and `uk_ledger_compile_local_unsupported`, one entry for every compiled period. Both are required evidence of the gate: a producer that drops the report gets `evidence_absent`, not a verdict. The names of the period's unresolved references are part of the gate's attested evidence, so two runs that differ only in the report do not share an evidence digest. A row signed `fixture_only` whose reference stops resolving fails as a changed kind too.
