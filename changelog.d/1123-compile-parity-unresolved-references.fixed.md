The UK compile-parity gates receive the compile's own report of unresolved references (microcosm#1123 follow-up). The signed-differences receipts classify a fixture row whose reference no longer resolves as `ledger_absent`, because the tool that writes them holds that report. The release-cut certifier and the full graph kept each period's compiled registry and dropped the report, so the gate read the same row as `fixture_only` and failed it as a changed kind. Since the re-pin to Chronicle 942a1fa the production-2023 receipt signs three such rows (the three `ons.land` values, whose selector pins the preliminary end-2025 edition), so `uk_ledger_compile_parity_production_2023` would have blocked the next release cut.

`ledger_compile_parity_gate` takes `unsupported`, and the report travels beside each compiled registry as `uk_ledger_compile_unsupported` and `uk_ledger_compile_local_unsupported`, one entry for every compiled period. Both are required evidence of the gate: a producer that drops the report gets `evidence_absent`, not a verdict. A row signed `fixture_only` whose reference stops resolving fails as a changed kind too.
