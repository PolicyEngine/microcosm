`mass_parametrization="softmax"` now projects the log-weights exactly onto the capped simplex after every Adam step: one common shift, then a clamp to each cap. Active-set rounds find the shift in float64, and a sort finishes it in log space if they run long or the uncapped weights underflow float64. It replaces a renormalize/clamp loop of at most 32 rounds, which ran out on most epochs of the ACS local release because of float32 rounding (the overshoot it left was float32-sized, measured in `experiments/us-acs-local-l2-basis-20260928/results/exact_cap.md`). Softmax solves record `options["iterate_selection_receipt"]["softmax_in_loop_max_cap_ratio"]`, the largest in-loop weight over its cap, in place of the exhaustion count, and the ACS local-area tool carries it in its calibration summary and build manifest, where every build now names that key in place of `softmax_cap_rounds_exhausted_epochs` (null under the default projection). The tool's package stage refuses a softmax calibration summary written before this change, which holds the old count and no ratio: calibrate that checkpoint again. The default `"projection"` parametrization is unchanged.
