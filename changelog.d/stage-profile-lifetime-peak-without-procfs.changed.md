The build stage profiler (`microcosm.build.stage_profile.profile_stage`, which writes `stage_profile.json` for each US base step and QRF variable) no longer starts a `ps` process every 0.25 s where `/proc` is unreadable, as on macOS. There it reads the process's lifetime peak resident memory (`getrusage(RUSAGE_SELF).ru_maxrss`) when the stage starts and when it ends, and still runs `ps` once each for the entry and exit readings. Each record gains `peak_rss_source`: `sampled_current_rss` where `/proc` is read every 0.25 s as before (Linux, including Modal); `process_peak_rss_reached_during_stage` when the lifetime peak rose during the stage, so it is the stage's own peak; `process_peak_rss_reached_before_stage` when it did not, so the stage's own peak is at most the recorded value; and `entry_and_exit_rss` when `getrusage` gave no usable value. `stage_profile.json` stays at schema version 1, so a resumed run merges new records into a file an earlier run wrote; records from before this change lack `peak_rss_source`. No data output changes.
