A checkpointed US base run (`tools/build_us_puf_support_base.py --stage all`) now hashes the PUF H5, the PUF CSV and the builder's source files once, in the parent process. Before, each of its 24 step processes hashed them again for its own resume check. The parent computes the run config and compares it with the one locked in the checkpoint directory. It then passes each step process the SHA-256 of each PUF file, keyed by the file's resolved path, and the source digest, together with the repository root and tool file it covers, in the environment variable `MICROCOSM_US_BASE_PARENT_DIGESTS`. A step process uses a digest only for the same path, and only when its own parent set the variable. It hashes every other file itself, so a named `--stage` run by hand hashes everything as before, and a malformed variable stops the step. `microcosm.build.code_identity.builder_code_identity` takes the digest as `source_sha256` and then reads no source file. The recorded run config is unchanged, so existing checkpoint directories still resume. A resume after a PUF file or the builder's code changed is still refused before any step process starts. A step process no longer notices a PUF file or source file that changes while the run is under way. Written outputs are unchanged.
