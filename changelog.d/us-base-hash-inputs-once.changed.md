In a checkpointed US base run (`tools/build_us_puf_support_base.py --stage all`), the step processes' resume check no longer hashes the PUF H5, the PUF CSV or the builder's source files. Before, each step process (24 under the default location rule, 23 under `block_v1`) hashed them again to compare its run config with the one locked in the checkpoint directory. Now the parent computes the run config once and compares it with the locked one. It then passes each step process the SHA-256 of each PUF file, keyed by the file's resolved path, and the source digest, with the repository root and tool file it covers, in the environment variable `MICROCOSM_US_BASE_PARENT_DIGESTS`. A step process uses a digest only for the same path, and only when its own parent set the variable. It hashes every other file itself, so a named `--stage` run by hand without the variable hashes everything as before. A malformed variable stops the step. `microcosm.build.code_identity.builder_code_identity` takes the digest as `source_sha256` and then reads no source file. The recorded run config is unchanged, so existing checkpoint directories still resume. A resume after a PUF file or the builder's code changed is still refused before any step process starts. A step process no longer notices a PUF file or source file that changes while the run is under way, a `git pull` in the same checkout included. The `clone_feature_extraction` step, which reads both PUF files, still hashes them for its own metadata. Written outputs are unchanged.
