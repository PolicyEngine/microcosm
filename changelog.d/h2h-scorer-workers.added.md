`tools/score_us_release_head_to_head.py` takes `--workers N` to score household slices in spawned processes. Each chunk is reduced in slice-index order with the sequential copy-then-add sequence, so estimates are bit-identical to `--workers 1` (the default, which keeps the sequential path); every per-slice contract and the 20 GiB per-process RSS cap still apply, and the run records `run_metadata.workers`.
