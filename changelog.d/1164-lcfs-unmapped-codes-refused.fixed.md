The UK `lcfs_consumption` stage refuses an LCFS region (`gorx`), tenure (`a122`) or accommodation (`a121`) code it does not map, instead of dropping the donor (microcosm#1164). The donor table ended in a `.dropna()` that silently lost any household whose code fell outside the stage's maps, and the derive step's `logged_dropna_row_count` was never implemented, so a survey year that recoded one of these variables would have shrunk the donor without a trace. The derive step now declares `unmapped_codes: refuse`; the error names each unknown code, or a blank, without counting rows, and any other missing donor value stops the stage too. Every LCFS 2023-24 code maps, so the donor is unchanged.
