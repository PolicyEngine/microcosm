Declare Chronicle's `chronicle.consumer_fact.v5` row contract, the one Chronicle `main` writes since PolicyEngine/chronicle#377 (`44eebe037`), and refuse a Chronicle feed whose pin or rows name a row contract Microcosm does not declare (microcosm#1509).

- **The declaration.** `microcosm.build.chronicle_epoch` declares v5 in the chronicle epoch beside `ledger.consumer_fact.v1` and `chronicle.consumer_fact.v2` to v4, matching Chronicle's own `CONSUMER_FACT_ROW_CONTRACTS`. Before this change nothing outside the tests read that list, so a v5 feed would already have loaded.
- **Pins.** The UK and US pin loaders, `chronicle_feed_identity` (used by reference factors, money normalization and the transport composer) and `validate_chronicle_feed_pin` refuse a pin whose `consumer_fact_schema_versions` names an undeclared row contract. The message names it and says to declare it in `chronicle_epoch` first; an id outside Chronicle's namespaces, such as `arch.consumer_fact.v1`, is named as not a Chronicle row contract, which `chronicle_epoch` cannot declare.
- **Rows.** `validate_chronicle_feed_pin` compares the rows' `schema_version` values with the pin before it checks them, so the transport kernels and the NZ and Belgian generators, which use it, cover the rows. The UK and US builds hold their feeds to committed pins by digest, so they now also check the rows they read (`validate_pinned_row_contracts`): rows on an undeclared row contract are refused, and rows of the committed feed must carry exactly the pin's list, which a re-pin types by hand. That covers the UK full and national builds, the UK vendoring tool and release certifier, and the US fiscal-refresh release tool. The UK reference generators, the compile-parity tool and the DESNZ constituency builder, which read a subset of the feed or only some of its rows, require each row's contract to be one the pin lists. A feed admitted by `--allow-unpinned-feed` is held to the declared row contracts only.
- **Loads without a pin.** A feed loaded by path for diagnostics and experiments, or a bare feed with no manifest that no reviewed pin covers, still carries its per-row ids unchecked; the July 2026 US fiscal-refresh feed, whose rows carry `arch.consumer_fact.v1`, loads that way.
- **The new field.** v5 adds an optional `package_dimension_value_labels`: a source package's own wording of a dimension value where it differs from the label the row exports. The loader keeps it on the parsed rows, as it keeps every published field, and Microcosm never takes a label from it: each value keeps the one label Chronicle gives it in `dimension_value_labels` and `layout.groupby_value_label`.
- **Its shape.** When a target with a calibration hierarchy (a provider and category seed) is compiled, each selected fact's field must be an object of dimension id to an object of value id to non-empty text, the shape the v5 schema requires. Any other shape raises `LedgerHierarchyMetadataError`, the error a missing Chronicle label raises, and callers treat it the same way: the UK compilers report the reference as unsupported, which stops the build year and is recorded for validation periods. This check walks every entry of the field, where the check of `dimension_value_labels` reads only the selected entries.
- **No feed pin moves.** The UK, US, NZ and Belgian feeds stay on their current Chronicle commits until their own re-pins.
