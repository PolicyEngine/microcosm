Declare Chronicle's `chronicle.consumer_fact.v5` row contract, the one Chronicle `main` writes since PolicyEngine/chronicle#377 (`44eebe037`), and refuse a Chronicle feed pinned on a row contract Microcosm does not declare (microcosm#1509).

- **The declaration.** `microcosm.build.chronicle_epoch` declares v5 in the chronicle epoch beside `ledger.consumer_fact.v1` and `chronicle.consumer_fact.v2` to v4, matching Chronicle's own `CONSUMER_FACT_ROW_CONTRACTS`. Before this change nothing outside the tests read that list, so a v5 feed would already have loaded.
- **The refusal.** A pin whose `consumer_fact_schema_versions` names an undeclared row contract is refused, with a message that names it and says to declare it in `chronicle_epoch` first. The checks are the UK and US pin loaders, `chronicle_feed_identity` (used by reference factors, money normalization and the transport composer), and `validate_chronicle_feed_pin` once a pin, its artifact's rows and its manifest agree. The transport kernels reach the last two. Every committed pin (UK, NZ and Belgium on v4, the US on v3) and every resource restating one names declared contracts. A feed loaded without a full pin, such as the US fiscal-refresh feed with its `arch.consumer_fact.v1` rows, still carries its per-row ids unchecked.
- **The new field.** v5 adds an optional `package_dimension_value_labels`: a source package's own wording of a dimension value where it differs from the label the row exports. The loader keeps it on the parsed rows, as it keeps every published field, and Microcosm never takes a label from it: each value keeps the one label Chronicle gives it in `dimension_value_labels` and `layout.groupby_value_label`.
- **Its shape.** When a target with a calibration hierarchy (a provider and category seed) is compiled, each selected fact's field must be an object of dimension id to an object of value id to non-empty text, the shape the v5 schema requires. Any other shape raises `LedgerHierarchyMetadataError`, the error a missing Chronicle label raises, and callers treat it the same way: the UK compilers report the reference as unsupported, which stops the build year and is recorded for validation periods. This check walks every entry of the field, where the check of `dimension_value_labels` reads only the selected entries.
- **No feed pin moves.** The UK, US, NZ and Belgian feeds stay on their current Chronicle commits until their own re-pins.
