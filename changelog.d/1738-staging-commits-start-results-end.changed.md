Staging run files (`runs/<run_id>/` in the Hugging Face staging repositories) are handed to the build's emitter at three points only: when the run starts, when a result file is added and when the run ends. Every one of those hand-overs is forced, so the emitter commits it at its next cycle, and the run's folder exists from its start even if the build dies before anything else reaches it. Stage events and calibration progress in between are still written locally and reach the repository with the next of those hand-overs; the build's hosted telemetry is the live record of a running build. The US writer (staging version 1) no longer stops for good after three hand-overs the emitter does not accept: as the UK writer already did, it pauses until the run's final state, which it hands over on completion and on failure. A SIGTERM in the US fiscal refresh build (`tools/build_us_fiscal_refresh_release.py`) now closes its staging run as failed, records a termination with the emitter and exits 143, as UK builds already do.
