Staging run files (`runs/<run_id>/` in the Hugging Face staging repositories) are handed to the build's emitter at three points only: when the run starts, when a result file is added and when the run ends. Every hand-over is forced and carries the run's folder as it stands, so the folder exists from the run's start and the emitter commits each hand-over at its next cycle. Stage events and calibration progress in between are still written locally and reach the repository with the next hand-over; the build's hosted telemetry is the live record of a running build. `--staging-upload-interval-seconds`, the writers' `upload_interval_seconds` (and version 2's `monotonic`), `force_upload` on `stage`, `attach_artifact` and `add_artifact`, and the US build record's `staging_settings.upload_interval_seconds` are removed; US certification ignores that field in older records.

Once a remote run has completed, failed or been refused by its release checks, the build has the emitter check its final commit before it reports the run's outcome: the emitter reads the run back, waiting up to 120 seconds for pending files before its comparison; after a SIGTERM or Ctrl-C the build reads the emitter's receipts instead, waiting up to 30 seconds (plus up to 5 seconds a query), and a missing credential or an emitter that stops answering ends the check at once. The build reports the result to its hosted telemetry as one progress event outside any stage, whose details name the check `staging_final_commit`, so the stage a failure is recorded in does not change. A failed check, or one an interrupt ends, warns and changes neither the build's outcome nor the run's delivery summary; with `--staging-read-back` (UK builds) the check is that stricter read-back, which still fails the build. US result files now go with every hand-over of the run's documents, so the final one also carries any the emitter missed while hand-overs paused; a result file too large for the emitter (over 32 MiB, or past 64 MiB for the hand-over) stays local with a warning instead of getting the documents refused. US certification handles SIGTERM as the build does. The US writer (staging version 1) now pauses after three refused hand-overs instead of stopping for good, and hands its final state over on completion and failure, as the UK writer already did. A SIGTERM in the US fiscal refresh build (`tools/build_us_fiscal_refresh_release.py`) closes its staging run as failed, records a termination with the emitter and exits 143, as UK builds already do.
