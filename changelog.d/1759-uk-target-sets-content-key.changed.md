The UK solve fingerprint now reads `uk/spec/target_sets.yaml` by its normative content, not by its bytes (microcosm#1759, from the review of microcosm#1755). The country spec records, for each typed resource of a package, the sha256 of the normative projection that the spec engine gives it (`ResolvedCountrySpec.content_hashes`), and `fingerprint_excluding` takes that hash for the resources named in `by_content`. The UK solve names its declared target sets there (`uk_runtime.solve_scope.UK_CONTENT_KEYED_RESOURCES`). A reworded description or rationale, or a new layout of the file, re-keys no solve node, so it cannot force the second build of a local release to solve again; a changed clause, level or exclusion re-keys every node that keys on the solve fingerprint. The calibrated gates and the release manifests keep the byte hash. The solve fingerprint has a new value, so the first UK build after this change computes the solve-scoped nodes again, with the same outputs. `test_uk_solve_scope.py` edits the packaged file both ways and compares every solve kernel's key.
