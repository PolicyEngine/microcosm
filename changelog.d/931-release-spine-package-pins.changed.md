A release candidate on a bound spine, and the national certifier, hold the spine to the package they run from (#931). Before the move, a dense release candidate refused any localisation resource other than the committed package file (the knots, the band mixes, the BRMA and RFDR layers, the rent resources). The spine reads those now, and its build sidecar records each one's pin, but nothing held the recorded pins to the package: a spine built at one commit bound as a release candidate at a later commit that changed only a resource, with values from the old files. The binding's `definition_sha256` was held to its format only.

- **Package pins** (`spine_build.uk_spine_package_pin_failures`, with `uk_spine_package_pins`, which reads the package through the sidecar writer's own helpers). The sidecar's `resource_pins` and `stage_artifact_pins` must be, entry for entry, the package's for the stages it records, and each of those stages one the package declares. A failure names the field, the stage, the resource or the artifact, and never a digest, a size or a locator.
- **The area definition** (`country_adapter.uk_spine_definition_failures`). The definition the spine's area draw builds on the conditioned supports at its declared seed is composed again, with the helper the sidecar writer calls, and the block's `definition_sha256` must be its digest. A zero or invented digest fails, and so does one of a definition that another commit's code composed. The digest is a function of the supports' bytes, so the check takes them; `uk_spine_geography_binding_failures` still holds the digest to its format only, as the dense release pre-flight reads it.
- **The supports' flags** (`spine_build.SPINE_SUPPORT_FLAGS`): `--spine-support-ew`, `--spine-support-scotland` and `--spine-support-ni`, the files the spine took as `--atomic-support-*`. They bind nothing, so they are not those retired dense flags. Each file is held to `sources.yaml`'s conditioned register (`spine_build.registered_atomic_support_payloads`, which the spine build now reads its own supports through, under its own flags).
- **The dense build.** `--release-candidate` with `--input-h5` now requires the three flags, read before any input is pinned, and `_require_release_candidate_spine` adds both checks to its refusal on a bound spine. A spine request composes its block and its pins from the package and its own supports, so it takes neither. Any other dense build refuses the flags, and so does the national role.
- **The national certifier** (`tools/certify_uk_release_cut.py`) takes the same three flags, holds them to the register and refuses, before any gate runs and after the geography binding check, a sidecar that fails either check (`_verify_spine_package`). `tools/run_uk_cut.py` passes it the supports the spine read, from `inputs/atomic_area_supports/`.
- **What moves.** Refusals only, under `--release-candidate` and in the certifier: no network request, no change to staging or publishing. `full_build_cli`, `rowwise_cli`, `spine_build`, `country_adapter` and the two tools are hashed by no kernel, so no node key moves. No declaration, generated file or `gates.json` changes. The dense and national assembly runbooks and `docs/uk-cut-anyone.md` name the new flags.
- **Tests** (invented data and the toy supports): on the dense preparation's stand-in spine and on the certifier's stand-in inputs, a zero digest and a resource pin or a stage artifact pin overwritten as another commit's are refused, naming the field and the resource or artifact; so is a missing resource pin in the certifier. Missing supports, a support off the register and support flags on a build that reads none are refused by flag before the spine is read, and the national role refuses them by name. The recompute passes the toys' own block and refuses a zero digest and the digest at another seed.
