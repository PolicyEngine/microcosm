The dense release runbook and the full-build graph doc say how to retry a failed or interrupted build 1 (microcosm#1301, answering the third review of microcosm#1307): into a new `--out`, with the same `--review-date` and `--graph-store` so that the retry reuses the nodes the failed attempt finished, and with `--logbook-prev-row-digest` naming the failed attempt's row when it spooled one. Nothing refuses an occupied `--out` for build 1, and a retry into the failed attempt's directory spools a second Logbook row there, which the sign-off drafter and `--verify` refuse and assembly can misread; clearing the failed attempt's row instead would drop its Logbook record. The graph doc also now says that the dense release contract warns on a shipped JSON document carrying a per-area support figure, rather than refusing it.
