A spec country's transport build can now be assembled into a release build that `microcosm-publish-release-build` publishes, with the three files BE's release contract adds to the base three (microcosm#1800). Until now nothing wrote `source_coverage.json`, `demographics.json` or `reform_validation.json` for BE, so no new BE build could pass the contract #1744 put in force.

- **The release files.** `microcosm.build.spec_release_files` builds each from the country's spec and the build's calibration diagnostics, reading no population. `source_coverage.json` has the US file's fields under the contract name `be_source_coverage`: each target category with an executable calibration reference is a hard target, each whose references are all parked is a source gap, and each held-out category is validation-only; the check fails when the build left out an executable reference or calibrated a held-out one. `demographics.json` has the US file's fields (each age band without `min_age` and `max_age`, which the spec does not give) for the spec's demography references (BE: Statbel population by NUTS1 region, sex and age band), with each cell's calibrated population and benchmark and their sums by age band; BE calibrates these cells, so the file reports in-sample fit (`in_sample` true). `reform_validation.json` lists no reforms until scored BE reforms exist (microcosm#264), and records `out_of_sample_simulated` true, as the US writer does when no out-of-sample reform exists, so publication does not refuse it.
- **The release step.** `tools/assemble_spec_release_dir.py --build-dir <transport --out> --country be` (`microcosm.build.spec_release_assembly`) reads what the transport build wrote, as the UK national assembler reads its candidate's outputs. It refuses a build that still owes outputs; records no clean Microcosm commit, no runtime or no spec digests; ran on a spec whose resources differ from the one the step loads; has an H5 or diagnostics file that changed after the build wrote it, or an H5 that does not read back against its descriptor (which needs the pandas and NumPy versions the build used); has a gate that did not pass or a release tier other than certified; has a year with no release that publishes into build folders; or fails its source coverage check. It also refuses to replace an earlier assembly. It writes `releases/<release>/` with each file the release contract requires, puts the H5 (`populace_be_<year>.h5`) and a weights file from its household table (`populace_be_<year>_calibration.npz`) beside the build, validates the directory with the release contract, and prints the publish and promote commands. It uploads nothing. The build is named `microcosm-be-<year>-chronicle-<Chronicle pin>-<finish time>`.
- **Transport builds record what they ran on.** `build-status.json` now records the Microcosm commit of the checkout that tracks the transport command's code and whether a tracked file differed from it (`microcosm.graph.reconstruction.code_revision`), the Python and package versions (`transport_build_provenance`), and the digest of each spec resource the graph was composed from.

Out of scope: a BE transport graph (BE's spec declares none yet, so no BE build runs through the release step until it does), scored BE reforms, and a BE registry entry or staging.
