UK release builds publish into their own folders through the emitter. The UK national, dense and local-area releases (`microcosm.data.contract.publishes_to_build_folder`) hand each build to the separately installed `microcosm-emitter` with the interface's `publish_release` call, and its release writer puts the build in `releases/<release>/<build>/` and records it in the repository's `releases.json` in one commit; Microcosm no longer commits, tags or writes `latest*.json` pointer files for them. The new `microcosm-publish-release-build` command (`microcosm.build.release_publication`, in `microcosm-build`) checks the build with the release contract, hands every file over with its role and SHA-256, publishes with or without `--make-current`, makes a published build current with `--promote`, and succeeds only when the emitter's receipt is `published` and, when current was asked for, names the build as `current`. The build is the calibration attempt ID: both manifests name `release` and `build` as strings, the release manifest records `built_at`, `built_with_model_package` and `built_with_core_package` at its top level and a `role` on each artifact (`dataset`, `calibration_weights`, `calibration_diagnostics`, otherwise the artifact's key), and no artifact pins a `revision`. The fields `build_id`, `attempt_id` and `cut_tag` are gone from UK manifests, and the assemblers' `--cut-tag` option with them. Each release's role in `releases.json` is `national` or `local_area`, from its `dataset_role`. The UK national assembler prints a publication command and a separate promotion command; the dense assembler's command makes each new dense build current. The release contract checks this layout for UK releases and refuses the tagged one. `microcosm.data.load` reads a UK release's current build from `releases.json` (or the listed build `build=` names, a withdrawn one with a warning), then its manifest and dataset from the build's folder; `unverified_root=True` is refused for such a release, and the loader no longer follows `latest-<line>.json` pointers. `microcosm-publish-release` and `tools/publish_release.sh` keep publishing US releases with tags and `latest.json`, refuse UK releases, and lose `--promote-line`. UK publications send no Slack alert. The stable releases proposed for US builds, `populace-us-2024-national` (`national`, the default) and `populace-us-2024-acs-local` (`local_area`), are recorded in `microcosm.data.contract.PROPOSED_US_RELEASES` but not used until they are agreed with the US data builder.
