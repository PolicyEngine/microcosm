The graph executor no longer deep-copies the tables a kernel reads (microcosm#1679). Each kernel gets new pandas objects whose buffers are read-only views of the memory they are projected from: the stored population's own memory for a node that reads every row, and the one copy `.loc` makes of the selected rows for a node with a row mask. Kernels see the same columns, order, dtypes, index, values and `attrs`, so no node key or output changes. A table with a strided column, a column type with no known view, and a pandas subclass are copied as before. The saving is in UK graph builds; the US release and base tools do not run the graph executor.

Measured with `tracemalloc` on an invented 1,000,000-row person table, 23 NumPy and nullable columns (131.6 MiB):

- a node reading every row: the context held 154.5 MiB before and 7.7 MiB after (the weights copy), and the projection peaked at 170.8 MiB before and 24.9 MiB after;
- a node reading half the rows: the context held 77.3 MiB before and 73.5 MiB after, and the projection peaked at 136.4 MiB before and 89.7 MiB after.

A pandas write into a context table lands in the kernel's own copy, as before, and the executor's before/after comparison of the context refuses it if it changed a value. An item write into an array a column hands out, into its `.base`, or after `setflags(write=True)` raises. `np.<ufunc>.at` ignores the read-only flag and writes into the population's memory; the comparison rejects the node before its result is applied or stored, and the run stops. The comparison now also hashes the raw bytes of NumPy bool columns. An item write into `np.asarray(table.index)` no longer reaches the population's index. Graph amendment 31 in `docs/graph-acceptance.md` records the design and its costs.
