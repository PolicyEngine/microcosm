The US Modal stage runner records how many telemetry events each run's emitter left undelivered (microcosm#1522). After the tool exits and its output ends, which is after the emitter the build started has stopped, `tools/modal_us_stage.py` runs the image emitter's read-only `microcosm-emitter status` (microcosm-emitter 0.13.0) without `--event-queue-file`, in the tool's environment without credentials or the collector token, with a 60 s timeout, and never reads the emitter's event queue file itself. The receipt's `runner.telemetry.undelivered_events`, `null` until now, becomes `{"runs": [...], "problem": null}` with `status`'s runs as printed (`run_id`, `producer_id`, `upload_state`, `reason`, `undelivered_events`); `{"runs": [], "problem": null}` when no event queue file exists (exit 8); and `{"runs": null, "problem": "<one line>"}` for any other exit code, a timeout, a command that cannot run or output that is not its list of runs. A failure is recorded only and never changes the stage's status or outcome. The runner's reserve after the tool keeps those 60 s, so the check's write probe leaves the mirror 1,560 s of a 30-minute reserve instead of 1,620 s, and its verdict reports the stop's and `status`'s allowances beside the receipt's. Builds and the Modal image now require microcosm-emitter 0.13.0 or later instead of 0.11.9, written once in `packages/microcosm-build/src/microcosm/build/minimum_emitter_version.json`: `microcosm.build.telemetry_emitter.MINIMUM_EMITTER_VERSION` reads it as package data and the runner's image install step reads it by its path in the launching checkout, replacing the repeated value and the test that kept the two equal. The image adds that checkout's file beside the plan module's copy, `/root/minimum_emitter_version.json`, which the copy reads first, so the check in the container reports the install step the image was built with. The installed-emitter job's pin rises to 0.13.0, and a new installed-emitter test runs a stage through the runner with the real emitter.
