The US fiscal-refresh target-frame checkpoint identity now carries `staged_frame_sha256`, a streaming digest of the staged frame handed to the materializer: every entity table's column names, dtypes and value bytes, the weight vectors with their kinds, and the person strata. Before this, the identity hashed the on-disk base dataset, the run settings (seed, PolicyEngine-US version, target registry, congressional-district crosswalk, selection-mass protections), a few named stage-input digests (the weeks-unemployed source, the SSI take-up assignment and prior-weight basis, the selection support) and a hand-bumped materializer version, so a change to any other stage that forgot the bump would silently reuse stale target columns. The materializer version moves from 11 to 12, so every existing checkpoint misses once. The reform-vector cache keys are unchanged; they bind the identity digest, so they tighten with it. The checkpoint also records the build commit that wrote it, in its HDF attributes and in `calibration_diagnostics.build.target_compilation.target_frame_checkpoint.source_build_commit`. That commit is provenance only, never identity: a later commit that stages the same frame still hits, and the hit names the commit that wrote the frame it reuses.
