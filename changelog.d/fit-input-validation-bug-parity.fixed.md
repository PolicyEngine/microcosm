microcosm-fit now refuses invalid input that it used to accept silently or crash on. The microimpute bug-parity audit reproduced each case against microcosm-fit. The checks are meant to leave the output for valid input unchanged, and a differential run of a fixed workload through the old and new code matched in every value. Two exceptions are listed below: unsorted classes in `categorical_scores`, and argument types outside the annotations that the old code converted. Only the attested kernel hashes move, because the fit kernels' source bytes changed.

- `RegimeGatedQRF` and `CategoricalClassifier` refuse a boolean or non-integer seed at construction, and `RegimeGatedQRF` also refuses a negative seed and a boolean or non-integer `n_estimators` there. Before, `RegimeGatedQRF` turned `seed=True` and `seed=1.9` into seed 1, so two different seeds shared one random stream, and `CategoricalClassifier` did the same with `seed=True`. Only Python and NumPy integers pass, so values the old code turned into an equal integer, such as `seed=1.0`, `seed="3"` and `n_estimators=4.0`, are refused too.
- `RegimeGatedQRF`, `detect_regime` and a loaded chain checkpoint (`QRFChainState`) require `zero_atol` to be a finite, non-negative real number (a `numbers.Real` other than a bool). The check converts nothing, so an integer tolerance still compares exactly with integer targets. Before, a NaN or positive infinite tolerance made a positive target fit as degenerate zero and draw only zeros. A `Decimal` or a 0-d array, which the old code turned into a float, is now refused.
- A DataFrame fit refuses a predictor, target, weight or groups label that names more than one column. Before, the fit read a duplicated predictor or target label as a two-column frame without saying so: a duplicated predictor fit silently, and in the audit's repro an all-zero duplicated target fit as degenerate zero. A duplicated weight or groups label crashed with an unrelated error.
- `categorical_scores` requires each row of `proba` to be a real probability distribution over `classes`, the classes to be distinct, the weights to be real, finite and non-negative with a positive total, and each stratum to be a 1-D array with one label per row. Labels still match classes by NumPy equality (`True` matches `1`). Before, probabilities of `[[2, 0], [0, 2]]` scored a log loss of -0.69, negative weights scored, NaN or all-zero weights scored NaN, and complex values lost their imaginary parts, NaN ones included, with only a NumPy warning.
- `categorical_scores` reads the classes in sorted order whatever order they come in, so permuting the classes together with the probability columns changes no score (bit for bit when `proba` is C-ordered). Sorted classes, which every production caller passes, score exactly as before. Unsorted classes now score as the same columns sorted would. Before, unsorted classes failed with "Every label must be one of classes" unless the sorted search happened to find every label, and then they scored in the order given. The calibration fit fixes the first class's offset, so those inputs now score differently:
  - the log loss is unchanged, and the share gaps move only in the last bits;
  - for slopes between 0.1 and 5 the calibration slope agrees to about 1e-12;
  - where only one class is observed, or the slope sits near 0 or far above 1, the slope can move materially and the calibration outcome can change.
- A weighted fit refuses, by name, a target whose positive or negative donor rows all carry zero weight. Before, the weighted bootstrap failed with "Probabilities contain NaN".
- A fit refuses an empty training table. Before, an unweighted fit treated the target as degenerate zero and predicted zeros, and a weighted one failed with "Weights sum to zero".
- A gated model answers an empty recipient batch with an empty result in `predict`, `conditional_uniforms` and the chain step, positional or keyed, as `predict_from_uniforms` already did, and `predict` consumes no draws for it. Before, the sign gate's classifier refused the zero rows.
- `donor_distance_features` refuses a missing or non-finite rank or presence-rank value and a missing categorical value. Its new `unseen_categories` argument sets what happens to a recipient category that no donor holds: `"refuse"`, the default, raises, and `"ignore"` keeps the old all-zero indicators. Before, a missing recipient rank value took rank 1, tying the largest donor, a missing presence-rank value counted as absent, and an unseen category became an all-zero dummy without a word.
