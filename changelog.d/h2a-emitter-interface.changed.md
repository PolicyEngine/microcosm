Builds start the separately installed `microcosm-emitter` command through `microcosm-emitter-interface` (`>=0.7.0,<1`), which replaces the exact `microcosm-emitter==0.2.1` dependency, so an emitter release needs no Microcosm change: install the emitter once per machine with `uv tool install microcosm-emitter`, and the Modal image installs the newest release when it is built. The emitter runs as the build's child process and inherits its environment, so it uses the build's Hugging Face credential. Telemetry events, Orrery graph files and now the version 1 and version 2 staging run files go through it: the writers hand their files over instead of uploading each with `HfApi`, the emitter commits a repository's pending files in one commit per upload interval and merges the version 1 runs index, read-back is the emitter's comparison of the Hub's copy with the bytes it committed, and the delivery counts are the emitter's as of each document's hand-over. Without the command a build continues with no hosted telemetry and no remote staging. The Hugging Face module keeps its hand-overs in `events.handovers.sqlite3` beside the existing spool database, which stays at the revision 0.2.1 used. Staged dataset bundles and releases still upload directly. `uv.lock` drops `microcosm-emitter`, `alembic`, `mako` and `sqlalchemy`, and `APPROVED_UV_LOCK_SHA256` is re-pinned.
